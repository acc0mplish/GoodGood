# 네이티브 호스트와 인터페이스

저장소 루트의 권한, 테스트 격리, 로그와 커밋 규칙을 따릅니다. 프런트엔드는 GPUI와 애플리케이션 데이터만 사용하고, 창과 운영 체제 통합은 platform 및 호스트 모듈에 둡니다.

- 인터페이스 문구는 locales, 테마와 애플리케이션 메타데이터는 resources를 사용합니다. 하드웨어 정보는 반드시 실제 스냅숏에서 가져오고 없는 데이터는 알 수 없음으로 둡니다.
- 텍스트 상자의 입력 요소는 `widgets::input`으로 만들고 `Input::new`를 직접 쓰지 않습니다. 구성 요소 라이브러리에 딸린 오른쪽 클릭 메뉴는 자체 문구 디렉터리(`gpui-component`의 `locales/ui.yml`, 영어, 한국어와 이탈리아어만 수록)를 쓰므로 `widgets::input`이 `common.edit` 문구로 바꿉니다. 자체 문구가 들어간 다른 구성 요소(대화 상자의 기본 단추, 선택 상자의 자리 표시자 등)를 쓸 때는 locales의 문구를 명시적으로 넘깁니다. 이 메뉴는 시스템 네이티브 팝업 메뉴라 표시하기 전에 `SetForegroundWindow`를 호출하므로 별도 데스크톱에서만 띄우고, `MN_GETHMENU`로 메뉴 항목을 읽어 확인합니다.
- 아이콘은 구성 요소 라이브러리에 포함된 Lucide만 쓰고 직접 그린 SVG를 추가하지 않습니다. `frontend/assets.rs`의 `product_icons!` 표에 이름과 대응 아이콘을 등록하고 `theme::icon` / `theme::glyph`로 그립니다. 이 표가 어떤 아이콘을 포함할지도 정하므로 등록하지 않은 이름은 원으로 표시됩니다. 고르기 전에 `gpui-kit-assets`의 `assets/icons`에 파일이 있는지 확인합니다. 그 디렉터리의 `github`는 채워진 로고이고 예전 Lucide의 `history`, `trash-2` 같은 이름은 바뀌었습니다. 컨트롤 위의 아이콘은 `moving_icon`과 `icon_probe`로 쓰고, 동작은 `icon_motion.rs`의 `Motion::of`에 아이콘 이름별로 등록합니다. 한 번만 전체 변형을 하고 끝나면 변형이 없는 정지 상태로 돌아가야 하며(회전한 래스터는 정지 상태보다 흐립니다) 반복 동작은 하지 않습니다.
- 메뉴, 드롭다운 목록, 마우스 올림 도움말과 알림은 배경과 테두리로 구분하고 구성 요소 라이브러리의 기본 그림자를 명시적으로 끕니다. 대화 상자는 가림막과 그림자를 유지합니다. RTX 4080 SUPER, 4K, 150% 배율, HDR 끔 상태에서 캡처 도구를 시작하면 사라지던 밝은 빛무리가 있었으므로 리팩터링과 구성 요소 업그레이드 시에도 이 처리를 유지합니다.
- 테스트는 자체 `--hidden --test --identifier` 인스턴스만 시작하고 창 프로브로 활성화 없이 표시하고 캡처하며, 사용자 데스크톱을 빼앗는 활성화 경로는 호출하지 않습니다. 창은 활성화하지 않아도 합성 키 입력을 받으므로 `keys`와 한 번 누르기, 끌기 계열 포인터 제어는 모의 스냅숏(`--fixture`)에서만 동작하며 그 환경에서는 프로세스 끝내기 같은 실제 명령을 실행하지 않습니다. 실시간 데이터에서는 마우스 올림과 값 확인만 합니다. 메뉴의 키보드 경로는 `inspectMenu`로 확인합니다.
- 테스트 모듈에 `use super::*`를 쓰지 않습니다. GPUI의 `test` 속성이 표준 `#[test]`를 가려 "recursion limit reached while expanding `#[test]`" 오류가 나므로 항목별로 가져옵니다. glob 가져오기 사슬에서는 `Duration`이 모호하므로 `std::time::Duration`으로 씁니다.
- 표(`table_view`)와 세부 정보 창은 `hover_fills_in_place`로 표시되어, 마우스 올림 스타일이 배경색만 바꾸는 요소는 제자리에서 색만 바꾸고 속한 뷰는 다시 그리지 않습니다. 이 두 곳의 코드는 "마우스 올림이 뷰를 다시 그린다"는 것에 의존할 수 없으므로 포인터에 따라 바뀌는 내용이 스스로 다시 그리기를 요청하거나(`tips`가 포인터가 한 행에 250 ms 머문 뒤 표에 알립니다) 배경색 말고도 바뀌는 마우스 올림 스타일을 요소에 줍니다(`icon_probe`). 다른 영역의 마우스 올림, 누름과 도움말은 요소가 속한 뷰만 다시 그리고 그 안의 캐시된 뷰는 재생합니다. 샘플링은 내용이 함께 바뀌는 영역만 다시 그리므로(`Desktop::notify_snapshot`) 제목 표시줄이나 탐색에 표시하는 상태가 바뀌면 데스크톱에 알리거나 해당 영역을 새로 고칩니다. 다시 그리는 범위를 확인할 때는 `GOODGOOD_GPUI_FRAME_TRACE=1`과 `passive`가 붙은 포인터 제어를 쓰고(`docs/development/gpui.md` 참고), `passive`가 없는 테스트 제어는 모두 데스크톱 알림으로 끝나 실제 범위를 볼 수 없습니다.
- 표의 행은 GoodGood이 직접 그립니다(`tables/body.rs`). 구성 요소의 표는 머리글만 그리고 "행이 없는" 방식으로 행을 독립 뷰 `TableBody`에 넘기며, 각 행은 구성 요소와 같은 행 요소이고 행 안의 셀은 요소 하나가 배치하고 그립니다. 기하(이름 열, 가로 스크롤 열 영역, 칸마다의 위치와 장치 픽셀 반올림)는 구성 요소의 `render_table_row`와 `VirtualList` 알고리즘을 재현합니다. 구성 요소에 딸린 행은 보조 기술의 창 읽기와 열 교환 애니메이션 동안에만 남깁니다(`NativeTable::draws_rows`). 행이나 셀의 구조와 스타일을 고칠 때는 두 경로를 함께 고치고, 같은 프로그램을 기본값과 `GOODGOOD_TABLE_ROWS=component`로 각각 실행해 스크린숏을 픽셀 단위로 대조합니다(고정 그룹 머리글, 가로 스크롤, 선택 행과 오른쪽 클릭 행, 각 인터페이스 배율과 글자 크기를 포함). `TableBody`는 `following`으로 캐시하므로 표가 렌더링할 때 함께 렌더링되고 자체 상태를 보관하지 않습니다.
- 표의 두 스크롤 핸들은 `isolate_glides`로 설정되어 세로 이동 프레임은 `TableBody`만(구성 요소가 행을 그릴 때는 `TableFrame`) 다시 그리고 가로 이동 프레임은 `TableFrame`을 다시 그리며, 바깥 페이지 영역과 데스크톱은 재생하면서 원래 위치에 다시 붙입니다(`Window::request_isolated_animation_frame`). 그래서 고정 그룹 머리글, 그룹 이름과 프로세스 페이지가 아닌 세로 스크롤 막대는 `TableBody` 안에 그려집니다. 그룹 오버레이는 표 프레임의 위쪽에서 배치하고(`FromFrameTop`) 배치는 원점까지의 거리로 반올림하므로 원점이 다르면 장치 픽셀 하나가 어긋납니다. 이 뷰들 밖에서 표 스크롤 오프셋으로 그리는 내용은 이동 중에 스스로 프레임을 요청해야 합니다. `scrollbar::Scrollbar`를 다른 뷰가 그릴 때는 `ScrollHandle::gliding()` 동안 격리 프레임을 요청하며, 이런 읽기 쪽(떠 있는 머리글, 행으로 이동하는 오버레이 등)을 새로 만들 때도 같게 처리하고 프레임마다 대조합니다. `smooth_scroll::advance`에 매 단계 오프셋을 임시로 출력해 읽기 쪽이 그릴 때 읽은 오프셋(`scrollTrace` 테스트 제어)과 같은 프레임에서 일치하는지 확인합니다.
- 표에서 한 줄 텍스트만 표시하는 셀은 `tables/cell_text.rs`가 그리며, flex `div`, `truncate()` 래퍼와 텍스트 노드의 배치와 픽셀 반올림을 재현합니다(`gpui::taffy`의 규칙). 셀의 텍스트, 색, 사용량 배경색과 글꼴은 행별로 캐시하고(`cells::CellValues`), 행 목록, 페이지, 단위, 테마, 글자 크기와 언어가 바뀌면 무효화하며 도움말 문구는 여전히 포인터가 있는 행에 대해서만 만듭니다. 셀 모양에 영향을 주는 상태를 새로 만들면 무효화 조건에 넣습니다. 이 셀들의 글자 크기, 안쪽 여백, 정렬이나 말줄임을 바꿀 때는 `CellSpec`을 고치고, 변경 전후 빌드로 여러 인터페이스 배율(125%, 150% 포함), 글자 크기와 좁은 열에서 스크린숏을 픽셀 단위로 대조합니다.
- 이름 셀과 표시가 있는 셀에서 입력을 받지 않는 상자는 `frontend/plain.rs`의 `plain()`을 씁니다(`div`에서 상호 작용 상태를 뺀 것으로, 배치, 잘라 내기와 채우기가 같은 스타일의 `div`와 같습니다). 한 줄 텍스트만 있고 안쪽 여백과 테두리가 없는 상자는 `plain_text()`를 씁니다(상자와 텍스트를 한 노드로 합치고 측정과 말줄임은 GPUI의 텍스트 요소를 그대로 따릅니다). 이들은 리스너, id와 불투명도를 받지 않으므로 그것이 필요한 상자는 `div`나 요소로 만들고, 도움말 영역은 `on_prepainted`로 보고하며(안쪽 여백 상자로, 가장자리에 붙는 자식 요소와 같습니다) 자식 요소를 더하지 않습니다. `plain.rs`는 vendored GPUI의 `Div`, `Interactivity`와 `TextLayout`을 부분별로 그대로 옮긴 것이므로 이 부분을 고치거나 업그레이드할 때 함께 확인하고 나서 스크린숏을 대조합니다. 이 상자들을 고친 뒤에는 같은 단계 파일로 변경 전후 스크린숏을 비교하며, 스크린숏 사이에 한 행 전체나 컨트롤 하나의 마우스 올림 배경색(색차 약 10)만 다르면 배치가 바뀐 뒤 마우스 올림 상태가 새로 고쳐지는 시점 차이이므로 다시 실행해 확인하고 그리는 차이로 보지 않습니다.
- 표 셀은 자기 칸 안에서 잘립니다(구성 요소는 `overflow_hidden`을 덮고, 직접 그리는 행은 같은 범위로 자릅니다). 열 교환 애니메이션처럼 이웃한 셀을 넘어 그려야 할 때는 `flip::escaping`으로 표의 보이는 영역을 잘라 내기 범위로 삼아 늦게 그리며, 이를 위해 구성 요소를 고치거나 vendor하지 않습니다. 이런 애니메이션 동안에는 구성 요소가 행을 그립니다.
- 곡선의 시간은 수집 타임스탬프에서 오며 알 수 없는 구간과 일시 중지 의미를 유지합니다. 프레임마다 스냅숏을 복제하거나 표를 다시 만드는 일은 피합니다. 곡선, 프레임 스케줄링이나 캐시 로직을 고칠 때는 실제 표시와 숨김 상태의 비용을 확인하고, 정적 배치와 문구는 루트 규칙에 따라 국소 검증합니다.
- 차트 레이어(`ChartLayer`)는 페이지 전체 위에 그리므로 페이지 안의 텍스트는 곡선에 가려집니다. 곡선 위에 올릴 내용은 `charts::Overlay`로 차트 레이어에 맡겨 그립니다. Windows 합성은 정지한 내용이 그와 겹치는 모든 이동 요소(곡선 텍스처, 애니메이션 막대)보다 위에 있고 배경이 단색이거나 일반 이미지일 때만 곡선 레이어를 유지하므로, 그라데이션 배경이나 이동 요소 사이에 낀 정지 내용은 곡선을 프레임마다 다시 그리게 하고 곡선과 함께 프레임마다 움직이는 작은 이미지도 CPU와 GPU 비용을 눈에 띄게 늘립니다. 이 레이어들의 그리기 순서, 배경이나 합성 방식을 고친 뒤에는 `GOODGOOD_GPUI_DIAGNOSTICS=1`로 `gpu-chart-layers`의 `images`와 `gpu-chart-foreground-reject`를 확인합니다.
- `gpui_kit::base::ElementExt::on_prepaint`의 프로브는 위치가 지정되지 않은 절대 자식 요소로 텍스트 흐름 뒤에 놓이므로 측정되는 경계가 요소 자체보다 한 줄 높이만큼 낮습니다. 테스트 앵커를 기록할 때는 `canvas(...).absolute().inset_0()`을 씁니다.
- 업데이트 공개 키와 버전 서명 제약은 바꿀 수 없고 설치 전에 서명을 다시 검증합니다. 시간이 오래 걸리는 명령은 UI 스레드에서 실행하지 않습니다.
- 플랫폼 기능과 프런트엔드를 분리하고, macOS에서 쓸 수 없는 수집이나 작업은 모의 성공으로 반환하지 않습니다.
