# docs 에이전트 지침

## 독자 구분

- `README.md`(저장소 루트): 외부에 공개하는 소개로, 일반적인 오픈 소스 프로젝트를 참고합니다. 무엇인지, 기능, 시스템 요구 사항, 빌드 방법, 바로 가기 요약, 문서 입구, 로드맵 요약을 담습니다. 짧게 유지하고 구현 세부와 측정 과정은 넣지 않습니다. 내부 개발 규칙(커밋 규칙, 릴리스 절차, CI)도 문서 링크 뒤의 설명 문구까지 포함해 쓰지 않습니다.
- README 제목의 이모지에는 변형 선택자 U+FE0F를 붙이지 않습니다(예: 🛠️, ⌨️, 🗺️). GitHub이 앵커를 만들 때 이 보이지 않는 문자를 유지하므로 `#-제목` 형태의 링크가 동작하지 않습니다.
- README 미리보기를 갱신하려면 `node scripts/readme-previews.mjs`를 실행합니다. 현재 소스로 빌드한 창에서 Windows 11의 활성 상태 Mica 배경을 캡처하고 이름 오름차순으로 모의 앱과 실제 아이콘을 표시합니다. 네 장의 그림은 같은 구간에서 연속으로 측정한 CPU, 메모리, 디스크, 네트워크와 GPU 부하를 공유하며 한국어와 영어, 밝은 테마와 어두운 테마를 그림마다 확인합니다.
- README 기능 영역의 여섯 가지 동작 시연은 `node scripts/readme-features.mjs`가 만듭니다(그리기 코드는 `scripts/lib/feature-demos.mjs`). 각 시연은 CSS 키 프레임만 쓰는 독립 SVG이고 인터페이스 문구는 키 이름으로 `locales/`에서 가져오며, 헤드리스 브라우저에서 시연에 쓰는 글꼴로 측정한 뒤 배치합니다. 시연이 다루는 인터페이스 문구, 메뉴나 페이지 구조가 바뀌면 다시 만들고 언어별로 긴 문구가 잘리지 않는지 그림마다 확인합니다. 시연 데이터는 가상 값이고 원격 주소는 문서용 예약 대역을 씁니다.
- 일곱 개 README의 대응은 다음과 같습니다. `README.md`는 한국어(원문)이고 `README.en.md`, `README.es.md`, `README.de.md`, `README.ja.md`, `README.fr.md`, `README.ru.md`는 각각 영어, 스페인어, 독일어, 일본어, 프랑스어와 러시아어입니다. 공통 내용을 고치면 각 판을 함께 고칩니다. 위쪽 언어 탐색은 서로 링크하고 현재 언어는 굵게 표시하며 "읽는 언어" 같은 머리말을 붙이지 않습니다. 언어 설명 절을 따로 두지 않습니다.
- 스크린숏은 언어별로 따로 있습니다. 한국어 판(`screenshot-ko-*.png`)은 테스트 식별자의 한국어 설정과 모의 스냅숏으로 캡처하고 영어 판(`screenshot-en-*.png`)은 영어 설정으로 캡처하며, 모의 데이터의 프로세스와 서비스 설명도 그 언어로 바꿉니다. 그림의 언어와 문서의 언어가 다르면 그림의 언어를 밝힙니다. 각 판은 코드 서명 정책 앵커(한국어 판은 `코드-서명-정책`, 나머지는 `code-signing-policy`), 서명 상태, 책임자, 개인정보 처리 방침 입구와 SignPath 영어 감사 원문을 유지합니다.
- `docs/`: 사용자와 개발자를 위한 자세한 정보를 담습니다.
- `AGENTS.md`(루트와 각 하위 디렉터리): AI 에이전트만 보는 규칙과 경험을 적습니다. 이 내용을 README나 docs에 쓰지 않고, 사람을 위한 설명을 AGENTS.md에만 쓰지도 않습니다.

## 구조

- `docs/README.md`가 색인이고 각 하위 디렉터리의 `README.md`는 그 부분의 입구 페이지로서 같은 디렉터리의 다른 페이지를 링크합니다.
  - `guide/`: 사용자가 보는 기능과 조작
  - `development/`: 개발 환경, 명령, 빌드, 성능 측정
  - `architecture/`: 모듈 책임과 데이터 흐름
  - `design/`: 설계 원칙과 구현 결정(측정 근거 포함)
  - `roadmap.md`, `known-issues.md`
- 페이지를 추가하거나 옮기면 해당 디렉터리의 `README.md`, `docs/README.md`와 루트 `README.md`에서 영향받는 링크를 함께 고칩니다.
- 링크는 모두 상대 경로를 쓰고, 이번에 추가하거나 고친 링크를 확인하며 페이지를 옮길 때는 그 페이지를 가리키는 링크를 점검합니다.
- 문서만 고치는 변경은 루트의 검증 범위에 따라 차이를 확인하면 되고, 문서 사이트 구성 요소, 생성 로직이나 페이지 배치가 관련되면 해당 빌드나 화면도 함께 검증합니다.

## 작성 방식

- 한국어로 씁니다. API, 타입, 파일과 코드 식별자는 원문을 유지하고 코드 형식으로 표시합니다.
- 결론, 사실과 조작을 직접 서술하고 구체적인 근거로 뒷받침합니다. 먼저 부정한 뒤 전환하는 구성, 의도적인 교정과 중복된 한정은 줄입니다. 조작, 안전이나 데이터 해석에 영향을 주는 조건은 해당 내용에 붙여 한 번만 밝힙니다.
- 실측 수치에는 조건(머신, 빌드 종류, 새로 고침 간격)을 적습니다. 결론은 측정에서 나오며, 이전 결론을 뒤집을 때는 본문을 바로 고치고 잘못된 서술을 남기지 않습니다.
- 문서는 독자가 필요한 사용법, 동작, 기준선, 방법, 설계 결정과 그 근거를 중심으로 구성합니다. 측정 원자료와 회차별 검증 과정은 빌드 산출물 디렉터리에 둡니다.
- 검수 목록이나 "검수 대기", "아직 실측하지 않음" 같은 설명을 쓰지 않습니다. 사용자가 특정 환경에서 점검해야 하는 항목은 답변에서 직접 알립니다.
- 코드 동작이 바뀌면(바로 가기 키, 설정 항목, 기본값, 모듈 책임, IPC 명령) 해당 페이지를 함께 고칩니다. 루트 README의 기능 목록과 바로 가기 표에는 가장 자주 쓰는 내용만 넣습니다.
