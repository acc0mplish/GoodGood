# 하드웨어 데이터의 출처와 한계

GoodGood은 기본으로 표준 사용자가 접근할 수 있는 Windows 인터페이스와 그래픽 카드 드라이버에서 데이터를 읽습니다. “설정 → 권한 → 커널 센서”를 켜면 권한 있는 서비스가 PawnIO를 통해 프로세서 내부 표시값을 보충합니다. GoodGood은 드라이버를 설치하거나 시작할 때 필요에 따라 권한을 요청하고, 준비가 끝나면 스위치 상태를 저장합니다. 성능 페이지는 하드웨어가 실제로 제공하는 지표를 표시합니다.

| 데이터 | 출처 | 설명 |
|---|---|---|
| CPU 사용률 | Windows 고유 유휴 카운터, 프로세서 총 시간, 프로세스 주기 카운터 | 프로세스 사용률은 시스템 전체 논리 프로세서 용량으로 정규화하므로, 스레드 하나가 논리 프로세서를 가득 채우면 프로세스 사용률은 약 `100% ÷ 논리 프로세서 수`입니다. 샘플링 창과 집계 기준에 따라 Windows 작업 관리자와 대조한 결과가 달라질 수 있습니다. 시간 기준이나 주기 카운터를 쓸 수 없으면 CPU 시간 차이로 대체 |
| 누적 CPU 시간, 커널 사용량 | Windows 사용자 모드와 커널 모드 시간 카운터 | 시스템 원래 시간 기준을 유지. 시스템 타이머 해상도 때문에 짧게 실행한 누적 시간 차이와 사용률 환산 값이 어긋날 수 있음 |
| CPU 식별 | CPUID, Windows 하드웨어 레지스트리, 프로세서 토폴로지 API | 제조사, 제품군／모델／스테핑, 마이크로코드, 하드웨어 명령어 집합, 물리 코어와 논리 프로세서, 캐시 |
| CPU 클록 | 성능 카운터 `Processor Information`, 커널 MSR | 전체와 논리 프로세서별. 코어별 실제 클록, 유효 클록, 배수, C0 활성 비율. 지원하는 Intel 모델은 링 클록, 배수, 클록 상하한도 제공. 유효 클록은 APERF 시간 차이로 계산하고 코어별 유효 클록과 C0는 속한 논리 스레드의 평균이며, 절전이나 카운터 초기화 뒤에는 기준선을 다시 만듦 |
| CPU 기본 속도 | CPUID `0x16`, 없으면 Windows `ProcessorInformation` 전원 인터페이스 | 표시값에 포인터를 올리면 출처를 볼 수 있음 |
| CPU 유휴 상태 | Windows `Processor Information`, 매핑한 AMD SMU 표 | Windows의 C1／C2／C3는 시스템 유휴 분류를 뜻함. 지원하는 AMD 프로세서는 SMU의 C0／C1／CC6도 나열 |
| CPU 제한 상태 | Intel `IA32_THERM_STATUS`와 패키지 열 상태 MSR | 온도, PROCHOT, 임계 온도, 전력과 지원하는 전류／도메인 간 제한. 현재 비트와 이력 래치 비트를 따로 표시하고 읽어도 기록을 지우지 않음 |
| CPU 온도 | 프로세서 내부 센서, 표시값이 없으면 ACPI 열 영역(`Thermal Zone Information`)으로 대체 | 내부 온도는 커널 센서를 켜야 함. ACPI는 보통 패키지 근처 온도를 반영하고 일부 메인보드는 이 인터페이스가 없거나 고정값만 제공. 성능 페이지가 출처를 표시 |
| CPU 전력 | Windows `Energy Meter`, 커널 센서가 제공하는 RAPL／AMD 에너지 카운터 | 개요는 패키지 전력을 먼저 표시하고 결측이면 코어 전력을 표시. CPU 세부 정보는 패키지와 코어 곡선을 따로 그리고 내장 GPU 전력은 해당 GPU 페이지에서 봄. 절전과 비정상 에너지 차이는 기준선을 다시 만들고 0와트 표시값과 결측을 구분 |
| 코어별 온도, CPU 전압 | PawnIO 고정 CPU／SMU 모듈을 권한 있는 서비스로 읽음 | Intel DTS는 코어 온도, 열 여유, 스로틀링 상태를 제공하고, AMD는 명시한 SMU 표 버전에 따라 코어별 온도를 읽음. SVI2／SVI3 공급 전압과 VID 요청 전압을 따로 표시. SMT 스레드가 공유하는 코어 센서는 한 번만 집계 |
| 전력과 제한 | Intel RAPL, AMD 에너지 카운터와 SMU 표 | Intel 패키지, 코어, 내장 GPU, 메모리, 플랫폼 전력, PL1／PL2와 시간 창, TDP. AMD 코어별 전력과 표에 명시된 PPT／TDC／EDC 현재 값과 상한 |
| AMD 확장 데이터 | SMU 표, 정확한 버전으로 일치 | 코어, SoC, 기타 전원의 전압／VID／전류／VRM 온도, FCLK／UCLK／MCLK, VDDP／VDDG, I/O 다이와 L3 온도. 전원 레일 전력은 같은 스냅숏의 전압과 전류를 곱해 계산 |
| 메인보드 센서 | Nuvoton NCT6779／NCT679x | 하드웨어 채널 번호로 팬 회전 속도를 표시. ROG STRIX X670E-A / NCT6799D는 +5 V, +12 V, +3.3 V, AVCC, 대기 전압, 활성화된 배터리 전압과 메인보드·전원 온도를 추가로 제공. 모르는 메인보드에는 분압과 배선을 적용하지 않고, 확인하지 않은 채널을 CPU나 수랭 펌프로 표시하지 않음 |
| 배터리 | 배터리 클래스 드라이버(`powercfg /batteryreport` 뒤의 인터페이스) | 충전 수준, 충전·방전 전력, 전압, 설계／최대 충전 용량, 상태, 주기 횟수 |
| 디스크 | 저장소 IOCTL | 활성 시간, 읽기·쓰기 속도, 응답 시간, 모델, 용량, SSD／HDD, 포함한 볼륨. NVMe, SATA, ATA 버스의 디스크는 드라이버가 제공하면 온도를 표시. RAID 컨트롤러(Intel RST／VMD 포함) 뒤의 디스크와 USB, SCSI, SAS 등 버스의 디스크는 온도를 조회하지 않으며 근거는 [수집 계층의 hardware/ 절](../architecture/core.md#hardware)에 있음 |
| 디스크 세부 정보 | 저장소 속성, 오류 예측, NVMe 프로토콜 조회, PnP 장치 트리, 기존 권한 있는 서비스가 보충하는 ATA／SAT／SCSI 읽기 전용 조회 | 일련 번호는 제조사 SN을 먼저 표시. NVMe는 상태 로그와 PCIe 링크를 제공하고 컨트롤러 수준과 장치 수준 표준 조회 대체를 지원하며 RAID 컨트롤러 뒤의 디스크에는 NVMe 프로토콜 조회를 보내지 않음. ATA／SATA HDD와 SSD, SAT를 지원하는 USB／RAID 브리지 장치는 신원, SMART 특성과 임계값, ATA 표준, SATA 링크, PATA UDMA 모드, 장치가 보고하는 기능과 회전 속도를 제공. 매핑을 마친 SATA SSD는 모델별로 남은 수명, 누적 읽기·쓰기, 전원과 비정상 종료 통계를 해석하고, HDD는 전원 켜진 시간, 시작·정지, 헤드 로드, 섹터 이상, 인터페이스 CRC 카운트를 제공하며 모델과 단위는 [디스크 세부 정보 인터페이스](../architecture/core.md#디스크-세부-정보-인터페이스)에 있음. SCSI／SAS는 상태, 온도, 읽기·쓰기 오류 통계를 제공. 세부 정보 페이지를 열거나 “다시 읽기”를 클릭할 때 한 번 읽음. 확장 데이터에는 실행 중이고 프로토콜이 호환되는 권한 있는 서비스가 필요하고 장치와 드라이버가 해당 조회를 열어야 하며, 제조사 전용 브리지 프로토콜은 로드맵에 있음 |
| GPU | D3DKMT, 프로세스 엔진 카운터, PnP 드라이버 속성, DXGI/Direct3D 기능 조회, AMD ADL2·Intel IGCL 텔레메트리, NVIDIA는 NVML 코어 사용률로 보충 가능 | 엔진별 사용률, 전용／공유 비디오 메모리, 온도, 코어／메모리 클록, 현재 GPU의 드라이버 버전, 드라이버 날짜, DirectX API 버전과 기능 수준(FL). 드라이버 날짜는 장치 INF가 보고한 날짜를 쓰고 정적 정보는 열거할 때 읽어 캐시. 전체 값은 가장 사용량이 많은 엔진을 쓰고 유효한 프로세스 카운트와 NVIDIA 코어 표시값을 결합하며 인터페이스가 출처를 표시. 출처마다 적용 범위와 샘플링 창이 다를 수 있음. 온도, 클록, 전압은 드라이버 지원에 따라 표시하고 지원하는 0 클록과 0 전압은 숨기지 않음. NVIDIA는 전압을 제공하지 않음. 일부 드라이버는 전력을 전력 예산 대비 비율로 보고 |
| GPU 전력(와트) | NVIDIA NVML, AMD ADL2, Intel IGCL | 모두 System32에서 제조사 라이브러리를 읽어 PCI 버스, 장치, 기능 번호로 어댑터를 맞춤. NVML은 보드 전력과 상한을 제공하고, ADL은 보드 전력을 먼저 쓰고 칩 전력으로 대체하며, IGCL은 단일 GPU 전원 도메인의 마이크로줄 카운트와 장치 시간의 차이를 먼저 쓰고 활성화된 지속 전력 상한을 읽음. 전원 도메인을 쓸 수 없으면 지원하는 GPU 칩 에너지와 시간 차이로 보충 가능. 인터페이스는 전원 도메인 출처와 칩 출처를 따로 표시하고, 결측이나 카운터 초기화 뒤에는 기준선을 다시 만듦. AMD의 백분율 조정 범위는 와트로 환산하지 않음 |
| 프로세스별 GPU | 성능 카운터 `GPU Engine`과 `GPU Process Memory`(Windows 작업 관리자와 같은 출처) | 프로세스가 엔진마다 차지한 사용량과 사용한 GPU 메모리. 표준 권한으로도 모든 프로세스를 읽을 수 있음 |
| 프로세스별 디스크 읽기·쓰기 | `PROCESS_DISK_COUNTERS` | Windows 11 24H2 이상은 일반 프로세스 조회를 먼저 재사용하고, 다른 배치는 권한 있는 서비스나 관리자 권한으로 읽음. PID, 생성 시간, 샘플링 시각으로 디스크 바이트 속도를 계산. 결측은 “—”로, 수집한 유휴 값은 “0”으로 표시 |
| 프로세스별 네트워크 | 커널 네트워크 이벤트(ETW 공급자 `Microsoft-Windows-Kernel-Network`, 리소스 모니터와 같은 출처) | TCP와 UDP의 보내고 받은 바이트 수. 속도는 약 1초의 집계 창을 쓰고 0.5초 새로 고침 동안 최근 완전한 측정을 재사용하며, 창 전체에 트래픽이 없으면 0으로 처리. 세션은 관리자 권한 GoodGood이나 권한을 부여받은 권한 있는 서비스가 시작할 수 있고, 로컬과 서비스 수집을 모두 쓸 수 없으면 이 데이터를 표시하지 않음 |
| 메모리 모듈 | SMBIOS | 속도, 슬롯, 폼 팩터, DDR 세대 |
| 네트워크 | 인터페이스 표와 어댑터 주소 | 처리량, IP 주소 |

CPU 전체 사용률, 논리 프로세서별 사용률과 두 값의 커널 시간은 모든 프로세서 그룹을 포함합니다. 커널 시간과 사용률은 같은 샘플링 간격에서 읽어 그 간격의 프로세서 시간에서 차지한 비율로 환산하고 해당 사용률을 상한으로 삼습니다. 클록, 유휴 상태, 코어 토폴로지, 곡선은 그룹 번호와 그룹 안의 프로세서 번호로 대응하며, 없는 코어별 샘플은 곡선의 끊긴 구간으로 남기고 0% 사용률로 처리하지 않습니다.

CPU 전체 속도와 논리 프로세서 클록은 Windows의 직접 MHz 표시값을 먼저 쓰고, 전체 표시값이 없을 때만 논리 프로세서 표시값이 모두 있을 때 평균을 구합니다. 코어 종류가 같은 단일 소켓 구형 시스템은 기본 클록과 성능 백분율로 추정할 수 있고 100%를 넘는 터보 비율을 유지합니다. 하이브리드 아키텍처나 여러 프로세서 패키지에서 직접 표시값이 없으면 결측으로 두고, 성능 페이지는 “—”를 표시하며 개요 영역은 그 항목을 생략합니다. 커널 센서의 유효 클록은 계속 APERF 카운터로 읽습니다.

하이브리드 아키텍처 프로세서의 코어 유형은 Windows가 보고한 효율성 등급에서 옵니다. 등급이 가장 높은 것이 P 코어이고 나머지가 E 코어입니다. Intel Core Ultra의 LP E 코어는 E 코어와 같은 등급에 속하므로 캐시 토폴로지로 식별합니다. 나머지 코어가 공유하는 3차 캐시 밖에 있는 E 코어를 LP E 코어로 표시합니다. 그래서 Core Ultra 200V 계열의 E 코어 4개는 모두 LP E 코어로 표시되며 Intel 사양 페이지의 표기와 같습니다.

CPU 온도 곡선은 샘플마다 실제로 쓴 표시값으로 저장합니다. 패키지 온도를 먼저 쓰고 다음으로 가장 높은 코어 온도, 그다음 ACPI 열 영역으로 대체합니다. 출처나 가장 뜨거운 코어가 바뀌면 기존 기록을 유지하고, 모든 출처가 없으면 해당 시각에 끊긴 구간을 남기며 기록 곡선은 표시 범위가 끝날 때까지 유지됩니다.

CPU 세부 정보 페이지는 현재 켜져 있는 동안 감지한 센서 필드, 코어 행, 열을 유지합니다. 어느 표시값이 없으면 “—”를 표시하고 돌아오면 값을 갱신하며, 커널 센서를 끄거나 프로세서 신원이 바뀌면 쓸 수 있는 필드를 다시 식별합니다.

디스크 목록은 성능 카운터와 별개로 만들어지며 장치 인터페이스, 물리 디스크 번호, 볼륨 매핑을 결합해 장치를 식별합니다. 드라이버가 아직 성능 카운터를 제공하지 않아도 디스크와 읽을 수 있는 모델, 용량, 볼륨, 온도는 유지하고 활성 시간, 읽기·쓰기 속도, 응답 시간은 “—”로 표시하며 세부 정보 페이지는 계속 열 수 있습니다. 샘플링이 돌아오면 속도 기준선을 다시 만듭니다. 매체가 없다고 확인된 이동식 카드 리더는 디스크로 나열하지 않고, 결측 디스크가 있으면 개요 영역의 총 처리량도 알 수 없는 상태로 둡니다.

물리 디스크 성능 인터페이스를 쓸 수 없으면 그 디스크에 분명히 속한 탑재된 볼륨 카운터를 읽고 성능 페이지에 출처를 표시합니다. 볼륨 하나는 활성 시간, 읽기·쓰기 속도, 응답 시간을 제공하고, 여러 볼륨은 읽기·쓰기 속도를 합산하며 응답 시간은 작업 횟수로 가중하고 활성 시간은 결측으로 남깁니다. 드라이브 문자가 중복된 같은 볼륨은 한 번만 집계하고 디스크를 가로지르는 볼륨은 이 대체에 쓰지 않습니다. 볼륨 카운터는 해당 볼륨의 I/O를 덮으므로 탑재하지 않은 파티션과 물리 디스크를 직접 접근한 작업은 집계 범위에 들지 않고, 볼륨 수준도 읽을 수 없으면 관련 지표는 계속 “—”로 표시합니다. 출처, 볼륨 집합, 카운터가 바뀌면 기준선을 다시 만듭니다.

디스크 샘플링이 Windows의 장치 제거 요청을 받으면 들고 있던 장치 핸들을 닫고 읽기와 다시 검색을 잠시 멈춥니다. 꺼내기를 취소하면 샘플링을 다시 시작하고 속도 기준선을 다시 만듭니다. 이 처리는 드라이버가 고정 디스크로 보고하는 USB 외장 하드도 포함합니다. 장치를 빼면 목록에서 빠지고 다시 연결하면 이후 검색에서 찾습니다. 드라이버가 제거 알림을 지원하지 않으면 조회가 끝날 때 핸들을 닫습니다.

디스크 세부 정보 페이지의 정상 상태, 남은 수명, 온도, 예비 영역은 모두 초록을 쓰고 홈과 임계값 눈금은 중립색을 씁니다. 남은 수명 막대는 상태 표시와 같은 색이며 주의는 노랑, 나쁨은 빨강입니다. 온도가 장치가 보고한 경고／위험 임계값에 이르면 각각 노랑／빨강으로 표시하고 예비 영역이 임계값 미만이면 빨강으로 표시합니다.

논리 프로세서 그림 틀의 위쪽 가장자리는 100%를 뜻합니다. 틀 위에 코어 유형, 번호, 클록을 나열하고 오른쪽에 현재 사용률을 표시합니다. 행과 열 수는 사용 가능한 공간에 맞춰 조정되고 경계 크기 근처에서는 현재 배치를 유지합니다. 공간이 부족하면 세로로 스크롤할 수 있습니다.

CPU 사용률 집계를 검증한 x64 시스템은 Windows 10 LTSC 2019(17763), 21H2, 22H2와 Windows 11 21H2, 22H2, 23H2, 24H2, 25H2, 26H2이며, 전체, 논리 프로세서별, 프로세스별 사용률을 모두 표준 권한으로 수집할 수 있습니다.

## 시스템 호환 범위

설치 버전과 포터블 버전은 Windows 10 22H2(내부 버전 19045) 이상의 x64 시스템(Windows 11 포함)을 지원하고 DirectX 11을 지원하는 그래픽 장치와 드라이버가 필요합니다. 전체 기능 검증의 최소 기준선은 Windows 10 22H2이고, CPU 수집 별도 검증은 Windows 10 LTSC 2019(17763)와 21H2도 포함합니다.

| 기능 | Windows 10 22H2 | Windows 11 |
|---|---|---|
| 프로세스, 성능, 서비스, 시작 프로그램, 연결, 기록 인터페이스 | 지원. 관리 작업은 계정 권한이나 권한 있는 서비스 권한으로 실행 | 같음 |
| 프로세스별 디스크 읽기·쓰기 | 권한을 부여한 권한 있는 서비스나 관리자 권한이 필요 | 24H2 이상은 표준 권한으로 읽기 지원, 그 이전 버전은 권한 있는 서비스나 관리자 권한이 필요 |
| 프로세스별 네트워크 트래픽 | 권한을 부여한 권한 있는 서비스나 관리자 권한이 필요 | 같음 |
| 커널 센서 | 권한을 부여한 권한 있는 서비스와 PawnIO 2.2.0 이상이 필요 | 같음 |
| 창 배경 | 테마에 따라 바뀌는 단색 배경 | 22H2 이상은 Mica, 21H2는 단색 배경 |

PawnIO의 설치, 공식 2.0.1／2.1.0 업그레이드, 시작은 모두 직접 켤 때 시작되고 필요하면 UAC 권한을 요청합니다. 켜기를 마치면 앱과 Windows를 다시 시작해도 설정이 유지되고 권한 있는 서비스를 통해 읽기를 되살립니다. 구체적인 온도와 전압 같은 항목은 하드웨어와 드라이버 인터페이스에 따라 다르고, 물리 센서 표시값은 해당 하드웨어에서 검증해야 합니다. 설치와 문제 해결은 [커널 센서 설정](settings.md#커널-센서)을 참고합니다.

## 소비자용 하드웨어 호환 범위

호환 목표는 2010년 이후 출시한 소비자용 제품이며 인터페이스 기능과 프로세서 세대에 따라 수집 방법을 고릅니다. 센서 사용 가능 여부는 드라이버, 가상화 환경, 그래픽 카드 구성, 제조사 펌웨어, 시스템 보안 정책에 따라 달라집니다.

| 제품 범위 | 수집 방법과 한계 |
|---|---|
| Intel Core / Pentium / Celeron / Atom | 지원하는 Family 6 프로세서는 DTS, 패키지 온도, RAPL MSR을 씁니다. 온도 유효 비트와 온도 목표를 확인하고, 일부 Atom 세대는 에너지 단위가 다릅니다. 전압 요청은 명시적으로 인코딩한 모델에만 엽니다 |
| AMD Phenom II / Athlon / FX / A 시리즈 및 초기 APU | Family 10h–16h는 해당 모듈의 PCI / SMU 온도 인터페이스와 COFVID를 씁니다. 구식 Tctl은 제어 용도에 따라 “제어 온도”로 표시합니다 |
| AMD Ryzen / Threadripper, Ryzen 9 9950X 포함 | Family 17h–1Ah는 SMN 온도, 코어별·패키지 에너지, APERF／MPERF, SMU 표를 씁니다. Zen 4／Zen 5의 공급 전압은 SVI3 텔레메트리 필드에서 읽습니다. `0x00620205`는 16 코어 Granite Ridge 배치로 코어별 온도／전압, C0／C1／CC6, PPT／TDC 현재 값과 PPT／TDC／EDC 상한을 읽고, `0x00620105`는 별도의 8 코어 배치를 씁니다. `0x00380905`는 6 코어 Vermeer의 코어별 온도, 전압, 상주 비율을 제공하며, 이 계열은 기존 PawnIO 모듈로 고정된 CCD／코어 비활성 비트맵을 읽고 코어 수와 CoreId를 확인한 뒤 SMU 슬롯을 매핑하며 비활성 코어를 건너뜁니다. 비트맵이 없거나 일치하지 않으면 알 수 없는 상태로 두고 다시 시도합니다 |
| AMD Radeon / 통합 그래픽 | ADL2 PMLog, 인터페이스가 없으면 Overdrive 6 전력과 Overdrive 5 온도／클록／전압을 씁니다. 더 이전 드라이버이거나 이 인터페이스를 제공하지 않는 모델은 D3DKMT 데이터를 유지합니다 |
| Intel HD / UHD / Iris / Arc | D3DKMT를 기본으로 하고, IGCL을 지원하는 장치는 필드별 지원 표시에 따라 온도, 클록, 전압, 전력을 보충합니다. IGCL은 10세대 Core를 지원하지 않습니다. 단일 소켓 Comet Lake S/H(Family 6, Model A5h, 예: i7-10700K / UHD 630)는 커널 센서를 켜면 고정 IntelMCHBAR 모듈로 GT 온도, 클록, 요청 전압 VID를 읽고 RAPL PP1 전력을 하드웨어 신원에 맞춰 내장 GPU에 대응시킵니다. IGCL의 온도 같은 텔레메트리는 전원 도메인의 존재를 요구하지 않고, 범위가 표시되지 않은 여러 전원 도메인은 합산하지 않습니다. 열지 않은 필드는 쓸 수 없는 상태로 두고 CPU 온도나 패키지 전력으로 내장 GPU 데이터를 대신하지 않습니다 |

SMU 배치 표는 명확한 72개 버전을 수록하고 정의는 고정 커밋의 ZenStates-Core, LibreHardwareMonitor, GNR-SMU에서 가져왔습니다. 신원이 명확하지 않은 후보 필드는 제외합니다. `0x00620205`에는 `0x00621202`의 헤더와 전원 배치를 적용하지 않고, FIT 필드를 실시간 클록으로 쓰지 않으며, 확인하지 않은 EDC 실시간 값과 VRM／L3 후보를 표시하지 않습니다. 모르는 버전은 MSR／SMN 기본 표시값을 계속 제공하고 표 버전을 표시해 찾을 수 있게 하며, 이웃 버전을 적용하지 않습니다. 대형 Threadripper 표는 서명 모듈이 허용하는 첫 4 KiB 페이지만 읽습니다. 성능 페이지의 “내부 센서”는 전력, 전압, 클록, 온도로 묶고 “코어별 표시값”을 따로 나열하며 포인터를 올리면 출처를 볼 수 있습니다.

6 코어 Vermeer의 코어 비활성 비트맵은 [ZenStates-Core의 고정 레지스터 배치](https://github.com/irusanov/ZenStates-Core/blob/869b7e82572337e5a673e92230edc92bddf0e44b/Cpu.cs#L280)를 따르며 기존 서명 모듈로 읽기만 합니다. 코어 번호는 연속일 수 있고 SMU 표에는 비활성 슬롯이 남습니다. 비활성 슬롯의 0 전압과 100% CC6은 실제 코어 표시값으로 집계하지 않습니다.

AMD／Intel SDK는 별도 스레드에서 수집하고 인터페이스와 주 샘플링 스레드는 시효가 있는 캐시를 읽습니다. 커널 센서를 끄거나 15초 동안 아무도 읽지 않으면 권한 있는 서비스가 모듈 핸들을 해제하고 시스템은 공유 PawnIO 드라이버를 유지합니다.

GPU의 D3DKMT 성능 조회와 IGCL 텔레메트리가 잠시 실패하면 5초 간격으로 다시 시도하고 그동안 옛 값을 이어 쓰지 않습니다. 텔레메트리 항목은 그래픽 카드 모델과 드라이버 인터페이스 기능에 따라 제공되므로, 구형 Intel 내장 GPU의 일부 지표에는 전용 하드웨어 모니터링 인터페이스가 필요할 수 있습니다.

Comet Lake의 슬라이스 클록은 RC6 절전이나 슬라이스 종료 상태에서 0이 될 수 있고, GPU 페이지는 유효한 0 MHz 표시값을 유지합니다. 현재 클록은 레지스터 배수와 공칭 단계로 환산하고 최소／최대 작동 클록은 하드웨어 기능 범위를 뜻합니다. 공유 메모리 클록은 컨트롤러 구성을 DCLK로 환산하고 DDR 전송률은 그 약 두 배이며, 환산은 공칭 기준 클록을 기준으로 합니다. GT／미디어 활동률은 하드웨어 카운터에서 오고 Windows 엔진 곡선을 다시 쓰지 않습니다. 내장 GPU 전력은 서비스가 직접 읽은 유효 RAPL PP1 차이를 먼저 쓰고 없으면 Windows 카운터로 물러납니다. 전력과 활동률은 각자의 샘플링 구간을 반영하고 비동기 서비스 캐시는 새로 고침 주기 하나만큼 뒤처질 수도 있습니다. 성능 제한은 확인한 상태를 표시하고 포인터를 올리면 항목별 현재와 이력 래치 상태를 볼 수 있으며, 명확한 레지스터 정의가 없는 전압 제한 값은 만들지 않습니다.

배치 근거: [Intel 10세대 Comet Lake 데이터시트, 615212-003](https://cdrdv2-public.intel.com/615212/615212-003.pdf), 9.8, 9.9, 9.30–9.32, 9.36, 9.38, 9.41절.

AMD `0x00620205`의 SoC 설정 전압은 설정값으로 명확히 표시하고 SVI3 텔레메트리 전압을 대신하지 않으며, 뜻을 확인할 수 없는 필드는 VID 상한으로 표시하지 않습니다. PPT／TDC／EDC 상한은 현재 펌웨어 구성을, UCLK／MCLK는 실제 메모리 분주를 반영하고 공칭 기본값으로 덮어쓰지 않습니다.

현재 공식 PawnIO Intel 모듈은 성능 제한 사유 레지스터와 하드웨어 코어／패키지 C-state 카운터를 모두 열지 않습니다. 그래서 Intel은 허용된 열 상태와 전력／전류 제한, Windows 유휴 분류를 제공합니다. PL1／PL2 세부 사유, 네이티브 패키지 C6／C10, 노트북 EC 팬과 전원 컨트롤러 텔레메트리는 추정값으로 대신하지 않습니다.

인터페이스 자료: [Intel IGCL](https://github.com/intel/drivers.gpu.control-library), [AMD ADL](https://github.com/GPUOpen-LibrariesAndSDKs/display-library), [PawnIO 모듈](https://github.com/namazso/PawnIO.Modules), [AMD Family 17h OSRR](https://www.amd.com/content/dam/amd/en/documents/processor-tech-docs/programmer-references/56255_OSRR.pdf).
