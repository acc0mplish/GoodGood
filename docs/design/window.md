# 창 모양

창은 GPUI Kit의 `TitleBar`와 Windows 네이티브 창 관리를 씁니다. Windows 11 22H2(내부 버전 22621) 이상은 기본으로 Mica를 쓰고, Windows 11 21H2, Windows 10, 시스템 버전을 읽지 못한 경우에는 불투명 배경을 씁니다. Mica 지원 판정은 렌더러가 쓰는 `DWMWA_SYSTEMBACKDROP_TYPE`과 같은 버전 경계를 유지해 배경 인터페이스를 쓸 수 없을 때 투명 표면이 남지 않게 합니다. 창 테마는 인터페이스 색상 팔레트와 함께 바뀌며, 색 정의는 [테마 설정](../../resources/theme.json)에 있습니다.

Windows 시작 매개변수 `--opaque-window`는 HWND에 묶인 불투명 스왑 체인을 골라 GoodGood이 테마 배경색을 그립니다. Mica 배경을 지원하는 시스템은 기본으로 그 재질을 유지합니다. 두 창 모두 표시하기 전에 곡선 채우기와 배경색을 섞습니다.

그래픽 장치에 이상이 생긴 뒤의 복구는 창 목록을 먼저 복사하고 목록 잠금을 푼 다음 동기적으로 인터페이스에 알려 렌더링 리소스를 다시 만들고 다시 그리므로, 복구 중에도 창을 만들거나 닫을 수 있습니다. 진단 로그는 장치 손실 오류 코드, 복구 시작, 대체 장치 생성, 창 복구 완료를 기록해 중단 단계를 찾을 수 있게 합니다.

“하드웨어 가속” 설정은 렌더링 장치를 어느 어댑터에 만들지 정합니다. 켜면 시스템의 어댑터 순서대로 첫 번째 사용 가능한 GPU를 고르고, 끄면 소프트웨어 표시가 붙은 어댑터(Microsoft 기본 렌더링 드라이버, 즉 WARP)를 골라 CPU가 같은 Direct3D 11 그리기를 수행하며, 그 어댑터를 쓸 수 없으면 원래 순서대로 고릅니다. 설정은 창을 만들기 전에 읽습니다. 실행 중에 전환하면 프레임 시계 스레드가 현재 장치가 설정과 다른 것을 확인하고 위 복구 절차대로 새 장치로 바꾸며, 주 창과 알림 영역 팝업 창이 렌더링 리소스를 함께 다시 만들고 다시 그립니다. 기존 장치가 여전히 유효하므로 장치 손실 뒤의 두 차례 대기를 줄일 수 있습니다. 보이는 창은 기존 장치의 합성 대상과 마지막 프레임을 유지하고 새 장치가 첫 프레임을 제출한 뒤 새 스왑 체인으로 넘어가므로 전환 중에 빈 화면이 생기지 않습니다. 숨겨졌거나 최소화된 창, `--opaque-window` 창은 기존 장치 리소스를 먼저 해제합니다. 소프트웨어 렌더링 장치도 곡선 합성 레이어를 쓰며, [Windows 합성](charts.md#windows-합성)을 참고합니다. 진단 로그의 시작 기록에는 `hardware_acceleration`이, 어댑터 기록에는 `software`가 들어갑니다.

제목 표시줄은 높이 48 px이고 로고, 현재 페이지의 검색 상자, 창 단추만 둡니다. 검색 상자는 창 너비의 30%를 차지하며 자리 표시자 글자 너비와 480 px 사이로 제한되고, 창이 좁을수록 끌 수 있는 영역이 더 남습니다. 제목 표시줄의 나머지 부분은 끌기 영역(`WindowControlArea::Drag`)으로 등록하고 두 번 클릭하면 최대화합니다. 페이지 컨트롤과 “추가 작업” 메뉴는 페이지 막대에 있습니다. 위쪽 탐색이면 탭 오른쪽에, 측면 탐색이면 페이지 위쪽에 놓입니다. 탭(또는 페이지 이름)과 컨트롤 사이에는 최소 16 px 여백을 두고 이 역시 끌기 영역으로 등록하며, 공간이 부족하면 페이지 막대가 다음 압축 단계로 들어갑니다. 일시 중지와 새로 고침 빈도는 상태 표시줄에서 새로 고침 상태를 보여 주는 자리에 놓고, 업데이트 알림은 상태 표시줄의 버전 배지가 표시합니다. 단추를 제목 표시줄에 모으면 끌기 영역이 조각나고 창이 좁아질 때 컨트롤과 검색 상자가 줄을 바꿔야 하므로, 적용 범위에 따라 나누어 배치합니다.

기본 시작 크기와 최소 크기는 [앱 설정](../../resources/app.json)에서 오며 각각 1000×680과 640×480입니다. 창 위치 기록이 있으면 마지막으로 저장한 크기를 씁니다. 기본 디스플레이의 사용 가능한 영역(작업 표시줄 제외)이 최소 크기보다 작으면 최소 크기는 사용 가능한 영역을 한도로 합니다. 숨김 상태로 시작할 때 플랫폼 계층은 DPI에 맞춰 초기 클라이언트 영역을 보정하고 현재 데스크톱 포커스를 유지합니다. 끌기, 크기 조정, 시스템 단추, 적중 테스트는 네이티브 프레임워크가 처리합니다.

창 위치나 최대화 상태를 복원할 때 네이티브 크기 알림이 인터페이스 갱신 안에서 동기적으로 도착할 수 있습니다. 이때는 알림을 보관하고 합친 뒤, 갱신이 끝난 다음 최신 클라이언트 영역 크기와 배율을 읽어 다시 배치하고 창 전체를 그립니다. 일반적인 끌기 크기 조정은 여전히 동기적으로 갱신합니다.

작업 관리자 대체 진입점에서 콜드 스타트할 때는 주 창을 숨긴 채로 먼저 만들고 저장한 위치를 복원합니다. 최대화 복원은 활성화하지 않는 최소화와 복원으로 수행하고, 복원할 때 실제 클라이언트 영역에 맞춰 그리기 버퍼를 갱신하며 크기가 같으면 기존 버퍼를 재사용해 배치와 그리기 범위가 일치하게 합니다.

네이티브 창 메시지가 샘플링 주기와 곡선 스케줄링을 이끕니다. 최소화하거나 알림 영역으로 숨기면 연속 그리기를 멈추고, 복원하면 새 스냅숏을 요청합니다. 테마, DPI, 크기 변화는 대상 창 캡처로 확인하며, 방법은 [성능 측정](../development/performance.md)을 참고합니다.

숨겨진 창이 `WM_PAINT`를 받으면 `BeginPaint` / `EndPaint`로 확인만 하고 화면을 그리지 않으며, 표시할 때 다시 그립니다. 창이 사라진 뒤 불투명도를 되돌리면 숨겨진 창에 그릴 영역이 남습니다. `ValidateRect`는 숨겨진 창에 성공을 돌려주지만 그 영역을 지우지 않으므로, 시스템이 메시지 큐가 비는 동안 `WM_PAINT`를 반복해서 만들어 내고 인터페이스 스레드가 잠들지 못합니다. i5-13500HX, 배포 빌드, 백그라운드 샘플 간격 5초인 테스트 인스턴스에서 닫기 단추로 알림 영역에 숨긴 뒤 인터페이스 스레드가 이 때문에 코어 약 0.84개를 계속 점유했고, 최소화는 영향을 받지 않았습니다. 위 확인 방식으로 바꾼 뒤 알림 영역과 최소화의 프로세스 CPU 시간은 모두 1초에 약 10 ms였고, 숨겨진 동안 프레임을 제출하지 않으며, 숨긴 시간이 설정값에 이르러 돌려준 메모리도 다시 점유되지 않았습니다.

창을 직접 활성화할 때 독립된 항상 위 창이 주 창 중심을 덮고 가리는 면적이 3분의 1에 이르면 GoodGood이 임시로 최상위 레이어로 들어가 앞으로 나아갑니다. 검사는 창 속성만 읽고 상대에게 동기 메시지를 보내지 않으므로 상대가 메시지 처리를 멈춰도 수행할 수 있습니다. 활성화를 잃거나 숨기면 일반 레이어로 돌아가고, 다른 일반 창으로 전환하면 GoodGood을 새로 활성화된 창 뒤로 보내 그 창의 앞뒤 순서를 유지합니다. 원래부터 항상 위였던 창은 상태를 그대로 유지합니다. 작은 도움말과 주 창이 소유한 팝업은 원래 레이어를 유지합니다.

창 크기가 바뀔 때 플랫폼 계층은 `WM_NCCALCSIZE`에서 곧 적용될 클라이언트 영역에 맞춰 그리고 프레임 하나를 제출하며, 그 뒤에 시스템이 새 크기를 적용합니다. DWM은 이 메시지가 돌아온 다음 합성에서 새 크기를 표시하는데 `WM_SIZE`는 `SetWindowPos`가 끝날 때 도착하므로, 프로세스 간 크기 조정을 측정하면 4–13 ms 늦습니다. `WM_SIZE`를 기다렸다가 그리면 새 크기가 옛 내용과 함께 두세 번의 새로 고침 동안 표시되고, 드러난 가장자리 띠는 창 배경색이며 제목 표시줄 단추가 제자리에 남습니다. 165 Hz 디스플레이, 성능 페이지에서 각각 32회 크기를 조정한 측정에서 새 크기에 옛 내용이 표시된 시간은 배포 빌드가 평균 10.0 ms(최장 18.7 ms)에서 2.3 ms로 줄어 20회는 옛 화면이 없었고, 개발 빌드는 12.3 ms에서 1.6 ms로 줄어 24회가 그러했으며 나머지는 각각 새로 고침 한 번이었습니다. 남은 새로 고침 하나는 DWM에서 옵니다. DWM이 제출된 프레임을 새 크기보다 한 번 늦게 합성해 표시하는 경우가 있기 때문입니다. 돌아오기 전에 GPU 완료를 기다리는 것으로는 이 경우를 줄일 수 없고, 다음 합성 시계를 기다리거나 동기화 간격 0으로 제출하면 새 내용이 새 크기보다 새로 고침 한 번 먼저 표시되어 두 경우를 합친 손실이 지금보다 적지 않습니다.

메뉴, 드롭다운 목록, 떠 있는 도움말, 알림은 배경과 테두리로 계층을 구분하고 그림자를 모두 끕니다. 대화 상자는 마스크와 그림자를 씁니다. 마스크가 있는 동안에도 창 단추는 동작합니다. 아이콘은 원래 밝기를 유지하고 단추 배경색은 제목 표시줄과 함께 어두워집니다. 일부 NVIDIA 디스플레이 환경에서는 반투명 페이지 위에 떠 있는 요소의 그림자를 그리면 밝은 광채가 생기는데, 그림자를 끄면 이 현상을 피할 수 있습니다. 메뉴, 하위 메뉴, 드롭다운 목록을 닫을 때는 펼쳐진 쪽으로 잘리며 접히고(83 ms, 일정한 속도) 페이드 아웃하지 않습니다. 페이드 아웃하는 동안 떠 있는 요소 전체가 반투명해지고 같은 환경에서는 전체가 밝아져 닫히는 순간 하얗게 번쩍이기 때문입니다. 두 현상은 화면에서만 나타나고 화면 캡처와 화면 녹화에는 기록되지 않습니다. 창의 플립 스왑 체인이 그래픽 카드 오버레이 평면으로 표시되는 것과 관련이 있는 것으로 보이며, `GOODGOOD_GPUI_COMPOSED_PRESENT=1`을 설정하면 창이 DirectComposition 비트맵을 거쳐 합성기로 그려지므로 이 현상이 나타나는 컴퓨터에서 대조할 수 있습니다. 떠 있는 요소의 등장과 퇴장 방식을 바꿀 때는 넓은 반투명 픽셀을 반투명 페이지 위에 겹치지 않게 합니다. 일반 도움말과 줄바꿈 도움말은 `widgets::tooltip_text`를 함께 쓰며, 여기에서 구성 요소 라이브러리의 기본 그림자를 덮어씁니다.

## 영역별 ClearType (보류)

기본 Mica 창의 읽기 영역은 반투명 배경색과 보정한 회색조 글자를 씁니다. 전체 창 불투명 모드는 시스템 설정에 따라 RGB 서브픽셀 앤티앨리어싱을 쓸 수 있습니다. 현재 구현은 [네이티브 인터페이스](../architecture/frontend.md#배율과-조판)를 참고합니다.

대안 구현은 공통 렌더러에서 같은 글자의 RGB와 회색조 적용 범위를 함께 캐시합니다. 글자를 그릴 때 같은 그리기 표면에 보이는 글자를 덮는 완전히 불투명한 배경색이 이미 있고 글자가 장치 픽셀에 정렬되어 있으면 RGB를 씁니다. Mica가 비치는 글자, 모서리 가장자리에 걸친 글자, 페이드 인하거나 크기가 바뀌는 글자는 회색조를 씁니다. 캐시를 재생할 때는 그 시점의 배경, 자르기, 변환으로 다시 판단합니다.

프로토타입은 프로세스 표, 성능 세부 정보, 기록 목록, 설정 카드에 테마 단색을 깔아 RGB 적용 범위를 넓혔습니다. 이 영역들이 Mica도 가려 현재 유지하는 재질 계층의 모양 요구와 충돌하므로 방안을 보류했습니다. 나중에 다시 검토한다면 이미 단색 배경이 있는 메뉴와 팝업부터 시작해 주요 읽기 영역의 재질을 유지합니다.
