# 네이티브 인터페이스

[`src-gpui/src/frontend`](../../src-gpui/src/frontend)에는 창 레이아웃, 가상 표, 차트, 메뉴, 대화 상자와 각 페이지가 있습니다. `Desktop`이 인터페이스 상태를 보유하고, 샘플링과 시스템 작업은 [네이티브 호스트](host.md)가 조정합니다.

## 데이터, 정렬과 환경 설정

`model`은 PID와 생성 시간으로 프로세스를 식별하고 앱 그룹과 프로세스 트리를 만듭니다. 각 페이지는 선택, 필터와 정렬을 따로 저장합니다. `collation`은 Windows의 ICU로 인터페이스 언어에 맞는 정렬 키를 만들고, 숫자는 값으로 비교하며 문자는 대소문자와 악센트를 무시합니다. 정렬을 일시 중지한 동안에는 행 위치가 고정되고 값은 계속 갱신되며, 펼치거나 접을 때도 같습니다. 새로 표시되는 행은 속한 항목 뒤에 붙습니다(`Desktop::holds_order`).

`lists`는 서비스, 시작 프로그램과 연결의 표 행을 만듭니다. 연결 데이터는 2초마다 읽고, 프로세스 이름과 아이콘은 샘플링에서 가져옵니다. 백그라운드 스레드가 새 연결이나 소유 프로세스 변화에 따라 행을 준비하고 인터페이스 스레드가 결과를 받습니다. 다시 들어올 때는 필터, 검색, 정렬과 메모가 여전히 일치하는 캐시를 곧바로 표시할 수 있습니다.

`process_icons`는 현재 스냅숏 기준으로 프로그램과 WebView2 호스트의 아이콘을 유지하며, 표, 세부 정보 창과 규칙 인터페이스가 같은 이미지를 공유합니다. 스냅숏을 교체하면 만료된 아이콘을 GPUI 디코딩 캐시와 창 텍스처 아틀라스에서 함께 제거해 GPU 페이지가 회수할 수 있게 하고, 일시 중지 상태에서는 원래 스냅숏의 PNG를 계속 보유합니다.

인터페이스 환경 설정은 메모리에서 즉시 적용되고 백그라운드 스레드가 디스크에 기록하며, 종료 전에 기록을 마칩니다. `tableSort.<표>`는 표별 정렬을, `services.filter`와 `connections.filter`는 서비스와 연결의 상태별 필터를, `connections.protocolFilter`는 연결의 프로토콜별 필터를 저장합니다.

성능 페이지의 `cpuKernelTime`은 CPU 차트에 커널 시간을 겹쳐 그릴지 저장하며 기본값은 켜짐입니다. `perfHiddenDevices`는 장치 목록에서 숨긴 장치의 식별자(`performance/rail.rs`의 `stable_key`)를 저장합니다. 디스크는 버스, 모델과 용량, 네트워크 어댑터는 어댑터 모델과 연결 이름, 그래픽 카드는 이름, 배터리는 이름과 일련 번호이며, 식별자가 같은 장치는 목록 순서대로 번호를 덧붙입니다. 디스크 번호와 어댑터 LUID는 연결 순서와 재시작에 따라 바뀌므로 식별자로 쓰지 않습니다. 목록은 최소 한 항목을 표시하며, 저장된 선택으로 현재 장치가 모두 숨겨지면 첫 항목을 표시합니다.

## 표, 스크롤과 도움말

`tables::groups`는 프로세스 행에서 사용자 및 분류 그룹의 행 범위와 색(`Tone`, 색 값은 테마의 `group-*`)을 구하고, 목록 위이자 페이지가 그리는 스크롤 막대 아래에 위쪽에 고정된 그룹 머리글, 스크롤 막대 옆의 그룹 표시와 그룹 이름을 그립니다. 이들은 표 행이 있는 뷰(`TableBody`, 구성 요소가 행을 그릴 때는 표 프레임 `TableFrame`)가 목록 바깥에 그리므로 행 재배치를 따르지 않습니다. 휠 부드러운 스크롤은 목록 자체의 사전 그리기 단계에서 오프셋을 진행하고, 고정 머리글과 그룹 이름은 각자의 사전 그리기 단계에서 진행된 오프셋으로 위치를 다시 잡아(`Follow`) 같은 프레임에서 행과 정렬됩니다. 고정 머리글은 불투명한 배경으로 아래 행을 가려 마우스 올림과 클릭은 막고 휠은 통과시킵니다.

`tables`의 머리글은 구성 요소 라이브러리의 `DataTable`을 사용하고, 보이는 행은 GoodGood이 직접 가상화해 그립니다(아래 참조). 프로세스 표의 이름 열은 왼쪽에 고정되고 다른 열은 저장된 순서대로 배열됩니다. 자동 너비는 머리글과 합계를 측정하며, 머리글은 구성 요소가 정렬 아이콘용으로 남기는 오른쪽 안쪽 여백을 더 계산합니다. 백분율, 메모리, 속도 같은 숫자 열과 그 합계는 형식의 흔한 최댓값으로 너비를 미리 확보하고(`tables::widths::envelope`), 다른 열은 전체 프로세스 목록을 측정합니다(`tables::WidthRows`). 모든 그룹을 펼치고 검색 조건이 없는 상태에서 표시되는 행과 별도로 생성하며, 행마다 이름 셀의 구성과 각 열의 텍스트만 유지하고(`WidthRow`) 프로세스 데이터는 보관하지 않습니다. 목록은 백그라운드 스레드에서 생성하며 샘플링에 따라 최대 5초에 한 번이고, 뷰 전환, 이름 정렬, 그룹화 방식, 선택한 열이나 언어가 바뀌면 즉시 생성하며 완료 전에는 기존 목록을 사용합니다. 검색과 접기는 표시되는 행만 바꾸고 다시 측정하지 않으며, 두 생성 사이에는 보이는 행만 측정하고 너비만 늘립니다. 숫자는 고정 폭 숫자로 측정하고 숫자 열은 줄이지 않으며 8 px 단위로 반올림합니다. 이름, 경로 같은 텍스트 열은 두 너비를 기록합니다. 하나는 대부분의 행에 필요한 너비(사분위 범위 상한을 넘는 행은 너무 길다고 보고 전체 행의 95% 이상을 담도록 함)이고 다른 하나는 모든 행에 필요한 너비(`Natural`)입니다. `widths::allocate`는 먼저 각 열에 앞의 너비를 주고, 표의 남은 너비를 열별 차이 비율로 나누어 뒤의 너비까지 채우며 어떤 열도 늘리지 않습니다. 텍스트 열은 한 단계 넘게 좁아질 때만 갱신합니다. 드래그한 열은 `processColumns.overrides`에 수동 너비로 남아 배분에 참여하지 않고 다른 열의 너비에 영향을 주지 않으며, 열 경계를 두 번 클릭하면 해제됩니다. "전체 너비"는 드래그하지 않은 이름 열이 남은 너비를 차지하게 합니다. 머리글의 열 경계는 구성 요소의 조절 핸들이 마우스 올림을 넘겨받고, GoodGood은 머리글에 캔버스를 놓고 창 수준 마우스 이벤트로 포인터가 있는 경계를 판단해(`header::edge_probe`) 안내선을 그립니다. 너비 변화는 `TableFrame`이 프레임마다 보간하고(`WidthGlide`), 창 크기, 글자 크기나 언어가 바뀌면 바로 적용합니다. 글자 크기나 언어가 바뀌면 다시 측정합니다. 머리글을 드래그하거나 스크롤하는 동안에는 너비를 고정하고, 합계는 각 열 안에서 잘라 내며 함께 스크롤합니다. 프로세스 머리글의 드래그는 GoodGood이 직접 처리합니다. 인접한 열의 중앙선을 넘으면 교환하고 순서를 저장하며, 자리를 바꾼 열은 `flip`으로 원래 위치에서 새 위치로 미끄러집니다. 이동 중인 셀 내용은 표의 보이는 영역을 잘라 내기 범위로 삼아 늦게 그리므로 셀 자체의 잘라 내기에 걸리지 않습니다.

표를 다시 만들 때마다 모든 보이는 셀을 다시 배치하며 노드 수가 프레임 비용을 결정합니다. 구성 요소의 표는 보이는 셀마다 두 겹의 래퍼를 만들고 행의 가로 스크롤 열을 각각 독립 배치로 취급합니다(셀마다 배치 루트 하나). `tables::body`는 GoodGood이 행을 직접 그리도록 바꿉니다. 구성 요소의 표는 머리글만 그리고, 행은 독립 뷰 `TableBody`에 두며 각 행은 같은 행 요소(배경색, 마우스 올림, 선택과 오른쪽 클릭 표시, 클릭과 오른쪽 클릭)입니다. 행 안의 셀은 요소 하나가 배치합니다. 이름 셀은 기존 배치로 한 번 배치하고, 가로 스크롤 열은 구성 요소의 알고리즘으로 위치를 구해 장치 픽셀로 반올림한 뒤 바로 그리며, 상태 점, 스위치나 태그가 있는 셀은 각자의 요소를 유지합니다. 이름 셀과 표시가 있는 셀에서 입력을 받지 않는 상자는 `plain`으로 만듭니다. 스타일은 `div`와 같고 배치, 잘라 내기와 채우기가 일치하지만 상호 작용 상태가 없습니다. 한 줄 텍스트만 있는 상자(이름, 이미지 이름, 그룹 머리글)는 텍스트와 하나의 배치 노드로 합치고(`PlainText`), 이름 셀의 바깥 테두리와 안쪽 여백 상자도 하나로 합칩니다. 펼치기 버튼, 스위치, 아이콘과 이미지는 여전히 각자의 요소입니다. 키보드로 선택 행을 옮기는 처리는 `TableFrame`이 구성 요소보다 먼저 합니다. 보조 기술이 창을 읽거나 열을 드래그하고 열 교환 애니메이션이 도는 동안에는 구성 요소가 행을 그리며, 두 방식의 그리기는 픽셀 단위로 같습니다. 릴리스 빌드, 1240×800 창과 고정 스냅숏에서 프로세스 목록을 세로로 스크롤하는 한 프레임이 약 4.5 ms에서 2.3 ms로 줄었고, 스크롤 중 인터페이스 스레드의 CPU 시간이 약 40% 감소했습니다.

한 줄 텍스트만 표시하는 셀(값, PID, 경로, 설명, 분류 머리글의 합계 등)은 `tables::cell_text`가 그립니다. 이 함수는 안쪽 여백이 있는 flex `div`, `truncate()` 래퍼와 텍스트 노드의 배치 규칙으로 텍스트를 놓아 장치 픽셀 위치, 정렬, 말줄임표, 잘라 내기와 도움말 영역이 이 노드들과 같아지며 텍스트를 다시 측정하지 않습니다. 셀의 텍스트, 색, 사용량 배경색과 글꼴은 행별로 캐시하고(`cells::CellValues`), 이름 셀에 필요한 구성원 수, 아이콘과 표시도 행마다 한 번 계산합니다(`NameFacts`). 행 목록, 페이지, 단위, 테마, 글자 크기나 언어가 바뀌면 다시 생성하며, 스크롤과 마우스 올림에서는 프로세스 데이터를 읽지 않습니다.

`scrollbar`는 스크롤 핸들에서 범위와 오프셋을 얻어 내용 가장자리에 슬라이더를 그립니다. 드래그하면 바로 위치를 잡고, 트랙을 클릭하면 뷰포트의 87.5%를 넘깁니다. 가상 표의 세로 휠, 가로 휠과 Shift+휠은 같은 부드러운 스크롤을 쓰며, 안쪽이 가장자리에 닿으면 바깥쪽이 처리합니다. 구현은 [GPUI 패치](../../vendor/gpui-pre/GOODGOOD-PATCHES.md)를 참조하십시오.

`tips`는 표마다 포인터를 통합 추적하고 포인터 아래 행만 이름, 값이나 설명의 위치를 보고하게 합니다. 포인터가 다른 행으로 옮겨 가면 표를 다시 만들지 않고, 그 행에 250 ms 머문 뒤 표를 한 번 다시 만들어 그 행이 보고합니다. 빠르게 지나가는 행은 다시 만들기를 유발하지 않습니다. 도움말은 포인터가 해당 부분에 들어간 뒤 500 ms가 지나면 독립 뷰가 표시하며, 다시 만들기를 기다린 시간도 여기에 포함됩니다. 키 입력, 마우스 누름, 스크롤이나 포인터가 떠나면 숨깁니다. 메뉴는 `menus`가 포인터 근처에 배치하고 창 가장자리에 가까우면 방향을 조정합니다. 방향키로 포커스를 옮기고 하위 메뉴에 들어가며 Esc로 돌아옵니다. 메뉴와 하위 메뉴는 닫힐 때 열린 쪽으로 잘라 내며 접힙니다(이유는 [창](../design/window.md) 참조). 메뉴가 열리고 접히는 동안에는 표와 컨트롤의 마우스 올림 도움말을 표시하지 않습니다.

## 영역 그리기와 곡선

`regions`는 제목 표시줄, 탐색(위쪽 탐색일 때 페이지 표시줄 포함), 측면 탐색일 때의 페이지 머리글, 페이지, 표와 프로세스 페이지의 개요 영역 및 세부 정보 창을 각각 캐시합니다. 영역 안의 스크롤이나 애니메이션은 관련 영역만 다시 그리고 나머지 영역은 이전 프레임의 그리기 결과를 재생하며, 데스크톱 전체와 함께 재생한 영역은 이후에도 따로 재생할 수 있습니다. 표의 세로 부드러운 스크롤에서는 행이 있는 뷰만 다시 만듭니다(행, 고정 그룹 머리글과 그룹 이름, 다른 표는 세로 스크롤 막대까지). 머리글, 페이지 영역과 데스크톱은 자체 요소 트리를 다시 만들지 않고 이전 프레임의 그리기 결과를 재생하며 행은 원래 위치에 다시 그립니다. 가로 스크롤 프레임에서는 표 전체를 다시 만듭니다. 휠이 한 칸 돌 때의 프레임은 여전히 전체를 다시 만듭니다. 프로세스 페이지의 세로 스크롤 막대는 페이지 영역이 그리며, 드래그하는 동안 페이지 영역이 프레임마다 다시 만들어집니다.

새 샘플링은 그것을 표시하는 부분만 다시 만듭니다. 프로세스 페이지는 목록, 개요 영역과 상태 표시줄을 다시 만들고, 세부 정보 창은 선택한 프로세스를 표시할 때 샘플링에 따라 다시 만들며 본체 구성 정보를 표시할 때는 하드웨어 정보가 바뀐 뒤에만 다시 만듭니다. 성능, 기록 같은 페이지는 페이지 영역과 상태 표시줄을, 서비스, 시작 프로그램과 연결 같은 페이지는 상태 표시줄만 다시 만듭니다. 제목 표시줄과 탐색은 샘플링에 따라 다시 만들지 않습니다. 센서 상태가 바뀌거나 팝업, 메뉴가 열리고 드래그하는 동안에는 샘플링이 창 전체를 다시 만듭니다. 새 목록 행, 팝업이나 배치 변화는 해당 내용을 필요할 때 다시 만듭니다.

마우스 올림, 누름, 놓기와 도움말의 표시·소멸은 요소가 있는 뷰만 다시 그립니다. 표와 세부 정보 창은 `hover_fills_in_place`로 표시됩니다. 이 안에서 마우스 올림 스타일이 배경색만 바꾸는 요소(목록 행, 세부 정보 항목과 버튼)는 이미 그려진 화면의 배경색을 직접 바꿔 제출하고 뷰를 다시 만들지 않습니다. 이 두 곳에서 포인터에 따라 바뀌는 내용은 스스로 다시 그리기를 요청합니다. 셀 도움말은 `tips`가 포인터가 멈춘 뒤 요청하고, 효과가 있는 아이콘은 `icon_probe`에 내장된 마우스 올림 스타일이 촉발합니다. 구현은 [GPUI 패치](../../vendor/gpui-pre/GOODGOOD-PATCHES.md)를 참조하십시오.

페이지와 성능 장치를 전환할 때는 목표 위치로 먼저 배치하고 그릴 때 밀어 넣습니다. 페이지 밀어 넣기는 새 페이지가 처음 나타난 프레임부터 시간을 셉니다. 새 페이지의 첫 프레임은 배치와 그리기를 온전히 마쳐야 하고, 성능 페이지는 먼저 배치만 측정하고 표시하지 않습니다. 전환 시각부터 세면 페이지가 나타나는 순간 이미 거리의 대부분을 지나 있게 됩니다. 페이지와 탐색 선택 표시의 이동은 모두 250 ms를 쓰고, 페이지는 페이드 인하지 않으며 곡선은 ease-out cubic을 사용합니다. Fluent의 등장 곡선은 변위를 앞부분에 몰아 두므로 페이드 인으로 가립니다. 세부 정보 창과 다중 코어 그리드는 실시간 변환으로 화면을 재생하고, 차트와 속한 영역이 같은 프레임에서 함께 움직이고 잘립니다. `ChartLayer`는 스크롤 프레임에서 캐시한 곡선 텍스처를 평행 이동하고 데이터나 그리기 스타일이 바뀌면 다시 래스터화합니다. 레이어, VRAM 예산과 값 범위 변화는 [곡선과 시간 축](../design/charts.md)을 참조하십시오. 정보 페이지의 점 격자(`hundred.rs`)는 차트 레이어 위의 `HundredLayer`가 그리며, 페이지는 자리만 비워 두고 그 경계와 잘라 내기 범위를 기록합니다. 도입 애니메이션의 각 프레임과 샘플링마다 그 레이어만 다시 그리고 페이지를 다시 배치하지는 않습니다.

## 대화 상자와 입력

대화 상자는 열릴 때 가운데에 놓입니다. 본문과 바닥글 높이를 처음 측정하는 프레임은 표시하지 않습니다. 구성 요소는 아직 위치를 잡지 않은 상태에서 대화 상자를 뷰포트 높이의 1/10 지점에 그리고 자체 불투명도로 표면 스타일을 덮으므로, 표시하면 한 프레임 어긋난 화면이 스쳐 지나갑니다. 폼은 비동기 조회가 반환되거나 설명을 펼칠 때 위쪽 위치를 유지하고 높이는 167 ms 동안 새 값으로 전환합니다. 업데이트 창과 업데이트 내용 창은 내용을 로드하고 펼치며 높이가 전환되는 동안 가운데를 유지합니다. 그 안에서 버전을 펼치거나 접으면 내용이 자체적으로 높이를 전환하고, 길이와 곡선은 웹사이트 변경 기록을 따릅니다(픽셀당 1.6 ms, 240–420 ms로 제한, `cubic-bezier(0.2, 0.8, 0.2, 1)`). 이때 창은 내용 높이를 그대로 따라가고 자체 전환을 겹치지 않으며, 마우스 올림 강조와 등장 애니메이션도 같은 곡선을 씁니다. 사용 가능한 창 높이에 이르면 본문은 스크롤 핸들을 유지하는 네이티브 스크롤 컨테이너를 사용하고 휠은 페이지의 부드러운 애니메이션을 따르며 바닥글은 고정됩니다. 창 크기를 조절하면 다시 가운데에 놓습니다.

대화 상자의 본문과 바닥글 측정은 1/64 물리 픽셀보다 작은 높이 차이를 무시해, 소수 배율에서 부동 소수점 오차가 배치와 높이 전환을 반복해서 촉발하지 않게 합니다. 내용 증감과 창 크기 변화는 실제 측정대로 갱신합니다.

`widgets::text_field`는 텍스트 상자의 포커스와 테두리 스타일을 통일합니다. 입력 요소는 `widgets::input`이 만들고, 오른쪽 클릭 메뉴는 시스템 네이티브 메뉴이며 잘라 내기, 복사, 붙여넣기와 모두 선택 문구는 `common.edit`에서 가져와 인터페이스 언어를 따릅니다. 숫자 상자는 클릭과 길게 누르기로 증감하고 방향키로 한 단계 움직이면 즉시 제출합니다. 프로세스 페이지의 `SearchComposer`는 목록이 텍스트 입력을 받을 때 입력기용 입력 컨텍스트를 유지합니다. 조합을 시작하면 텍스트와 포커스를 검색 상자에 넘기고, 취소하면 원래 내용과 포커스를 되돌립니다. 팝업, 메뉴와 포커스가 있는 입력 상자가 키 입력을 먼저 처리합니다.

## 배율과 조판

`appearance`는 `Window::set_content_zoom`으로 인터페이스 배율을 Windows DPI와 합치고, 배치, 그리기와 적중 테스트가 같은 좌표를 공유합니다. 글자 크기는 13 px 기준으로 따로 환산합니다. 개요 영역은 카드 너비에 따라 큰 숫자와 단위를 조정하고 보조 값을 한 줄로 배열하며 공간이 부족하면 글자 크기를 줄입니다. 제목 표시줄에는 로고, 검색 상자와 창 버튼만 있고 검색 상자 너비는 창 너비에 따라 바뀝니다. 창이 좁으면 페이지 표시줄이 먼저 텍스트가 있는 항목을 드롭다운 버튼으로 바꾸고, 다음으로 페이지 컨트롤을 다음 줄로 옮깁니다. 단계는 실제로 측정한 너비로 판단하며 언어와 글자 크기에 따라 달라집니다. 각 페이지는(글자 크기, 언어와 탐색 위치까지 포함해) 단계별로 필요한 너비를 기억하므로 다시 돌아올 때 현재 너비로 단계를 바로 정합니다. 아직 측정하지 않았으면 들어가지 않는 단계가 그리는 프레임은 배치만 측정하고 표시하지 않으며(`Window::defer_presentation_until_layout`), 컨트롤이 줄 끝에 먼저 나타났다가 다음 줄로 뛰는 일이 없습니다.

`theme`은 [`theme.json`](../../resources/theme.json)에서 색상표, 글꼴과 줄 높이를 읽습니다. 라틴 문자는 Segoe UI Variable을 쓰고 큰 숫자는 Display 광학 크기를 쓰며, 한국어는 맑은 고딕으로 대체합니다. 선택한 탭과 그룹 머리글은 500 굵기를 씁니다. 도움말 상자는 시스템 도움말 글꼴과 줄 높이를 따로 설정합니다. 본문 기본 줄 높이는 글자 크기의 1.4배이고, 줄바꿈은 UAX #14와 ICU의 동아시아 조정 규칙을 사용합니다.

텍스트 앤티에일리어싱은 DirectWrite의 휘도 적응 대비 보정을 사용합니다. 추가 강조는 전경 휘도 50%–75% 사이에서 점차 약해지고, 더 밝은 텍스트는 원래 커버리지와 감마 보정을 유지합니다. 어두운 배경의 밝은 텍스트는 이 방식으로 가장자리가 두꺼워지는 것을 피하고, Markdown의 굵은 글자와 강조 단계는 원래 설정을 유지합니다. [DirectWrite 혼합 구현](https://github.com/microsoft/terminal/blob/1283c0f5b99a2961673249fa77c6b986efb5086c/src/renderer/atlas/dwrite.hlsl)을 참조하십시오.

인터페이스는 글꼴의 고정 폭 숫자 기능(`tnum`)을 모두 켜고 텍스트 측정도 같은 설정을 사용합니다. 프로세스 목록, 성능 값, 차트 레이블, 세부 정보, 상태 표시줄과 도움말 상자의 숫자는 자릿수와 형식이 같으면 너비가 유지되어 새로 고칠 때 가로로 흔들리지 않습니다. 프로세스 CPU, GPU 열과 그룹 합계는 퍼센트 기호를 표시하고, 자동 열 너비는 퍼센트 기호 자리를 확보합니다.

글자는 DirectWrite가 그 글꼴, 크기와 배율에 권장하는 렌더링 방식으로 래스터화하여 Windows와 Chromium에 맞춥니다. 한국어 대체 글꼴인 맑은 고딕은 모든 크기에서 대칭 스무딩을 요청하므로 양방향 앤티에일리어싱으로 그려지고, Segoe UI Variable도 모든 크기에서 양방향 앤티에일리어싱을 씁니다. 가로 방향 스무딩만 요청하는 힌팅 글꼴은 그 요청대로 가로 방향으로만 그립니다. 행의 어센트와 디센트는 대체 글꼴이 아니라 텍스트가 요청한 글꼴의 측정값을 쓰므로 한국어만 있는 줄, 라틴 문자만 있는 줄과 한글·라틴 문자가 섞인 줄이 같은 줄 높이에서 같은 기준선을 씁니다. Mica 창은 DirectWrite의 서브픽셀 커버리지를 휘도 가중 그레이스케일 마스크로 바꾸고 합성할 때 시스템 대비와 감마를 적용합니다. 전체 창 단색 모드는 시스템 설정에 따라 RGB ClearType을 쓸 수 있습니다. 영역 수준 ClearType 방식과 절충은 [창 모양](../design/window.md)을 참조하십시오.

`inline`은 고정 폭 자리 표시자로 버튼과 키캡을 한 줄 텍스트에 넣어 컨트롤이 텍스트와 함께 줄바꿈되게 합니다. 숫자와 단위, 제목과 모델은 첫 줄 기준선에 맞추고 기준선은 장치 픽셀로 반올림합니다. 관련 패치는 [GPUI](../../vendor/gpui-pre/GOODGOOD-PATCHES.md)와 [Windows 플랫폼 계층](../../vendor/gpui-pre-windows/GOODGOOD-PATCHES.md)을 참조하십시오.
