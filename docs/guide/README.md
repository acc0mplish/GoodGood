# 인터페이스와 조작

GoodGood 창은 위쪽에 제목 표시줄이 있고 그 아래에 탐색 창, 현재 페이지, 상태 표시줄이 있습니다. 탐색 창은 기본으로 제목 표시줄 아래에 있으며 창 왼쪽으로 옮길 수도 있고, 프로세스 페이지는 목록 위에 시스템 개요 영역을 표시할 수 있습니다.

“설정 → 언어 및 모양 → 프로세스 개요 영역”에서 “자동”(기본값), “항상 표시”, “숨김”을 고릅니다. 자동 모드는 고정된 높이 예산으로 개요 영역, 표 머리글, 스크롤 막대, 가상의 프로세스 10행만큼의 공간을 확보하고 창 공간이 부족하면 접습니다. 계산은 페이지 전체 높이를 쓰며 실제 프로세스 수, 그룹 접힘, 검색 필터, 스크롤 위치, 개요 영역의 현재 표시 여부와 무관하므로, 접은 뒤 공간이 늘어 다시 펼치는 일이 반복되지 않습니다. 펼칠 때와 접을 때는 높이 전환과 함께 목록이 움직이고, 인터페이스 애니메이션을 끄면 바로 바뀝니다. 숨긴 동안에도 데이터 수집과 곡선 기록은 계속됩니다.

## 첫 실행

처음 시작하면 시작 가이드가 표시되며 자주 쓰는 설정을 차례로 마칩니다. 표시 언어, 탐색 위치·인터페이스 애니메이션·차트 애니메이션·새로 고침 빈도, Windows 로그인 시 시작·창을 닫을 때 알림 영역에 유지·최소화 및 백그라운드 상주 시의 새로 고침 간격·창 표시와 숨기기 바로 가기, 자동 업데이트 확인·업데이트 채널·다운로드 소스, 선택 사항인 관리자 실행(권한을 부여하면 가이드를 마칠 때 권한을 전환합니다), 선택 사항인 권한 있는 서비스와 그 권한 범위(가이드에서 바로 설치할 수 있으며 관리자 권한이 필요하고, 건너뛴 뒤 “설정 → 권한”에서 설치할 수도 있습니다), 선택 사항인 커널 센서(권한 있는 서비스에 의존하며 켜면 PawnIO 드라이버를 자동으로 준비하고 관리자 권한이 필요합니다), GoodGood으로 Windows 작업 관리자를 대체할지 여부(권한 있는 서비스에 의존하며 마찬가지로 관리자 권한이 필요합니다), 마지막으로 자주 쓰는 조작 안내를 설정합니다. 각 단계의 변경은 즉시 저장되고 어느 단계에서든 “건너뛰기”를 클릭하거나 Esc를 눌러 마칠 수 있으며, 이후 [정보](#정보) 페이지에서 가이드를 다시 열 수 있습니다.

포터블 버전은 가이드 첫 단계의 “표시 언어” 아래에서 설치 버전과 비교해 없는 기능을 안내합니다. 앱 내 업데이트, 시작 메뉴 바로 가기와 제거 항목이 없고, 권한 있는 서비스와 작업 관리자 대체가 버전에 맞춰 자동으로 업데이트되지 않습니다. “웹사이트에서 다운로드”는 웹사이트 다운로드 페이지를, “GitHub에서 다운로드”는 GitHub의 최신 릴리스를 엽니다. 첫 실행 가이드를 마치면 오른쪽 아래에서 같은 내용과 두 다운로드 진입점을 한 번 더 알리며 약 30초 뒤에 자동으로 접히고 포인터가 머무는 동안은 유지됩니다. 이전에 가이드를 마친 계정은 다음에 포터블 버전으로 시작해 창을 표시할 때 안내를 받습니다. 이 안내는 Windows 계정마다 한 번만 표시되고 정보 페이지에서 가이드를 다시 열 때는 나타나지 않으며, 안내가 표시된 실행에서는 별표 알림을 표시하지 않습니다. 작업 관리자 대체 진입점으로 시작한 실행에서는 안내를 미루어 이후의 일반 시작에서 표시합니다. 설치 버전과 포터블 버전은 설정과 기록을 함께 쓰므로 설치 버전으로 바꾼 뒤 다시 설정할 필요가 없습니다.

## 페이지

프로세스 페이지와 연결 페이지의 페이지 막대에는 모두 “시스템 프로세스 숨기기” 단추가 있고 기본값은 꺼짐이며, 켜면 강조색으로 표시합니다. 두 페이지는 스위치를 따로 저장하고, 프로세스 페이지에서는 앱 보기, 트리, 목록 모두에 적용됩니다. 숨기기는 목록에만 영향을 주며 시스템 개요, 수집, 기록, 규칙은 전체 데이터를 그대로 유지합니다. 프로세스 페이지에서 숨기기를 켜면 이름 열 위의 집계가 “프로세스 607개(27개 숨김)” 형식으로 표시되며, 앞의 값은 전체 프로세스 수이고 괄호 안은 숨긴 프로세스 수입니다. 부모 프로세스를 숨겨도 나머지 자식 프로세스는 계속 표시됩니다. 서비스나 연결 같은 진입점에서 숨겨진 프로세스로 이동하면 대상을 표시하기 위해 프로세스 페이지의 숨기기 스위치를 자동으로 끕니다.

단추는 아이콘만 표시하며 포인터를 올리면 설명을 볼 수 있습니다. 규칙은 “설정 → 언어 및 모양 → 시스템 프로세스 숨기기 규칙”에 있습니다. 기본값은 Windows 구성 요소를 식별하며 Windows 탐색기, 명령 프롬프트, 콘솔, PowerShell(`explorer.exe`, `cmd.exe`, `conhost.exe`, `openconsole.exe`, `powershell.exe`, `pwsh.exe`)은 항상 표시합니다. “항상 표시”와 “추가로 숨기기” 목록을 편집할 수 있고, 실행 파일 이름으로 일치를 판단하며 대소문자를 구분하지 않고 두 페이지가 목록을 공유합니다. “저장”을 클릭하면 적용되고 저장됩니다. “항상 표시”가 우선하며, 기본 규칙을 복원한 뒤에는 저장해야 합니다.

프로세스 페이지는 가장 바깥 수준에서 로그인한 사용자별로 그룹화할 수 있고 “설정 → 언어 및 모양 → 사용자별로 프로세스 그룹화”가 이를 제어합니다. “자동”(기본값)은 여러 사용자가 동시에 로그인한 동안에만 그룹화하며 연결이 끊겼지만 로그오프하지 않은 세션도 포함하고, “항상 그룹화”와 “그룹화 안 함”은 선택한 상태로 고정합니다. 사용자가 로그인하거나 로그오프하면 목록은 다음 샘플링에서 갱신되며 다시 시작할 필요가 없습니다.

사용자마다 한 그룹이 되고 현재 세션의 사용자가 앞에 오며 나머지 사용자는 이름순으로, 마지막에 “시스템”이 옵니다. 그룹의 순서는 열 정렬에 따라 바뀌지 않습니다. 프로세스는 자신이 속한 세션의 로그인 사용자에게 들어가고 같은 사용자의 여러 세션은 한 그룹으로 합쳐지며, 두 사용자 이름이 같으면 “도메인\사용자 이름”으로 표시합니다. 로그인한 사용자가 없는 세션은 “시스템”에 들어가며, 시스템 서비스가 실행되는 세션 0과 로그인 화면에 머무는 세션이 여기에 포함됩니다. 그룹 행은 사용자 이름, 프로세스 수, 각 열의 리소스 합계를 표시하고 사용자의 모든 세션이 끊긴 경우 “연결 끊김”을 표시합니다. 클릭하면 접거나 펼칠 수 있고 접힌 상태는 설정과 함께 저장됩니다.

그룹 안의 표시는 그룹화하지 않을 때와 같습니다. 세 가지 보기, 이름순 정렬 시의 세 가지 범주, 열 정렬, 검색, “시스템 프로세스 숨기기”가 모두 각 그룹 안에서 동작합니다. 프로세스 트리는 같은 그룹 안의 부모·자식만 잇고, 다른 그룹에 속한 부모 프로세스의 프로세스는 해당 그룹의 최상위에 표시합니다. 같은 프로그램을 두 사용자가 실행하면 앱 보기에서 각자의 그룹 안에 한 행씩 차지하고, 자세히 창의 프로세스 수, 리소스, 곡선은 그 사용자의 프로세스만 집계합니다. 한 범주(예: “Windows 프로세스”)를 접으면 모든 사용자 그룹에서 함께 적용되고, 검색할 때는 일치하는 항목을 모두 표시하며 일치하는 항목이 없는 사용자 그룹은 표시하지 않습니다.

사용자 그룹 행에서 마우스 오른쪽 단추로 클릭하면 접기·펼치기 외에 작업 관리자의 “사용자” 페이지와 같은 두 항목이 있습니다. “사용자 계정 관리”는 제어판의 사용자 계정 페이지를 열고, “로그오프”는 확인 후 해당 사용자의 모든 세션을 끝내므로 실행 중인 프로그램이 함께 닫히고 저장하지 않은 데이터가 손실될 수 있습니다. 현재 사용자를 로그오프하는 것은 “시작” 메뉴에서 로그오프하는 것과 같아 프로그램이 저장을 요청할 수 있고, GoodGood은 세션과 함께 종료됩니다. 다른 사용자를 로그오프하려면 관리자 권한이 필요하며 관리자로 실행한 GoodGood에서만 사용할 수 있고, 그렇지 않으면 항목을 고를 수 없으며 “관리자 권한이 필요합니다”를 표시합니다. “시스템” 그룹은 접고 펼치기만 할 수 있습니다.

연결 페이지에서 숨기기를 켜면 PID가 0인 “소유 프로세스 없음” 기록도 걸러 냅니다. 이런 기록은 TCP가 닫힌 뒤 프로토콜이 회수하기를 기다리는 `TimeWait` 단계에서 흔히 보이며, UDP의 PID 0은 시스템이 소유 정보를 제공하지 않았다는 뜻입니다. 이 기록에는 위치를 찾거나 끝낼 사용자 프로세스가 없습니다. 다른 PID의 신원 정보가 일시적으로 없을 때는 계속 표시합니다.

## 프로세스 열 선택

프로세스 목록의 표 머리글에서 마우스 오른쪽 단추로 클릭하면 열 메뉴가 열립니다. 포인터가 있는 열은 바로 오름차순이나 내림차순으로 정렬하거나, 그 열을 숨기거나(이름 열 제외), “이 열 자동 맞춤”을 실행할 수 있습니다. “일반”, “CPU”, “메모리”, “디스크 및 I/O”, “네트워크”, “GPU” 여섯 하위 메뉴가 46개 속성을 모두 나열하고 선택한 수를 표시하며, 클릭하면 해당 열을 표시하거나 숨기고 하위 메뉴는 열린 채로 남아 연달아 조정할 수 있습니다. 메뉴 아래에는 “열 선택…”, “자동 너비”, “전체 너비”, “기본 열 복원”이 있습니다.

“열 선택” 대화 상자의 왼쪽은 범주별로 속성과 설명을 묶어 나열하고 범주로 필터링하거나 열 이름이나 설명으로 검색할 수 있으며, 범주 제목 옆의 “모두 선택”, “지우기”는 그 범주에 현재 나열된 속성에 적용됩니다. 오른쪽의 “열 순서”는 선택한 열을 표 순서로 나열합니다. 끌면 항목이 떠올라 포인터를 따라가고 나머지가 실시간으로 자리를 비웁니다. 포인터를 올리면 위로 이동, 아래로 이동, 제거를 실행할 수 있습니다. 변경은 “확인”을 클릭하면 적용되고 저장되며, “취소”나 Esc는 기존 설정을 유지합니다. 이름 열은 항상 맨 앞에 고정되고 선택한 열은 앱, 트리, 목록 세 보기가 공유하며 다시 시작한 뒤에도 유지됩니다.

표 머리글을 끌어 열 순서를 바꿀 수 있고 이름 열은 가장 왼쪽에 고정됩니다. 끄는 동안 열 전체가 포인터를 따라가고 이웃한 열의 중앙선을 넘으면 자리를 바꾸며 나머지 열이 부드럽게 비켜 줍니다. 놓으면 그 열이 새 자리로 미끄러져 들어갑니다. 순서는 저장되며 잠시 숨겼다가 다시 선택한 열은 원래 자리로 돌아옵니다. 애니메이션은 “인터페이스 애니메이션” 설정을 따르고 끄면 바로 자리를 바꿉니다.

“자동 너비”는 기본으로 켜져 있으며 열 제목, 합계 값, 각 행의 내용, 글꼴 크기에 따라 너비를 배분합니다. 각 열은 내용에 필요한 너비만 차지하고 남는 공간은 표 오른쪽에 남깁니다. 백분율, 메모리, 속도 같은 숫자 열과 그 합계 값은 그 형식에서 흔한 최대값에 맞춰 너비를 확보하므로 처음 표시할 때 거의 최종 너비가 되고 표시값이 바뀌어도 열 너비가 변하지 않습니다. 이런 열은 8 px 단위로만 넓어지고 줄어들지 않습니다. 이름, 경로, 설명 같은 텍스트 열은 모든 프로세스를 기준으로 측정하며 접힌 그룹과 검색으로 표시되지 않은 프로세스도 포함합니다. 그래서 다른 행으로 스크롤하거나 그룹을 펼치거나 접거나 검색할 때 열 너비가 바뀌지 않습니다. 표 너비가 부족하면 텍스트 열은 대부분의 프로세스(최소 95%의 행)가 온전히 표시되는 너비를 쓰고 뚜렷하게 긴 소수 내용은 말줄임표로 자르며 포인터를 올리면 전체를 볼 수 있습니다. 너비가 넉넉하면 모든 내용이 온전히 표시될 때까지 차례로 넓힙니다. 이름 열에서는 이미지 이름이 프로세스 이름보다 먼저 잘리고, 효율성 모드, 일시 중단, 고정 표시가 글자 바로 뒤에 붙습니다. 텍스트 열은 내용이 한 단계 이상 짧아졌을 때만 좁혀 열 너비가 되풀이해 바뀌지 않게 합니다. 열 너비가 바뀔 때는 부드럽게 전환하고 인터페이스 애니메이션 설정을 따르며, 창 크기를 조정할 때는 바로 따라가고 글꼴 크기나 인터페이스 언어를 바꾸면 다시 계산합니다.

포인터를 표 머리글의 열 경계로 옮기면 강조색 세로선이 표시되고 잠시 머무르면 “끌어서 크기 조정, 두 번 클릭하여 자동 맞춤”을 알립니다. 끄는 동안 세로선이 목록 아래까지 이어지고 지나가는 머리글에는 마우스 올림 효과와 설명이 표시되지 않습니다. 자동 너비가 켜져 있어도 열 경계를 끌어 한 열의 너비를 조정할 수 있습니다. 그 열은 직접 정한 너비를 유지하고 다른 열 너비는 그대로이며 오른쪽 열들이 함께 밀리고 나머지 열은 계속 내용에 맞춰 조정됩니다. 열 경계를 두 번 클릭하거나 머리글 메뉴에서 “이 열 자동 맞춤”을 고르면 그 열이 자동 너비로 돌아오고, 돌아올 때 열 전체를 강조색으로 표시하며 너비 전환과 함께 사라집니다. “자동 너비”를 다시 켜면 모든 열이 자동 너비로 돌아갑니다. “자동 너비”를 끄면 각 열이 저장한 직접 너비를 유지하고, 열 경계를 두 번 클릭하면 그 열이 모든 내용에 맞춰지며, 자동 너비를 다시 끄면 저장한 직접 너비로 돌아갑니다. “전체 너비”는 기본으로 꺼져 있고 자동 너비가 켜져 있을 때 쓸 수 있습니다. 이름 열이 표 오른쪽까지 이어져 빈 공간이 남지 않고, 이름 열의 너비를 끌어 조정한 적이 있으면 그 너비를 유지합니다. 공간이 부족하면 가로로 스크롤해 선택한 열을 보고 이름 열은 고정됩니다. 가로 휠, Shift+휠, 스크롤 막대 트랙 클릭 모두 스크롤 애니메이션을 지원하고 인터페이스 애니메이션 설정을 따릅니다. “기본 열 복원”은 처음 선택, 순서, 자동 너비, 전체 너비를 함께 되돌립니다.

세 보기의 “이름”은 모두 앱 이름이나 파일 설명을 먼저 표시하고 실행 파일 이름을 보조 글자에 둡니다. “이미지 이름” 열은 항상 실행 파일 이름을 표시합니다. 앱 그룹을 펼친 자식 프로세스는 실행 파일 이름을 유지해 구성원을 구분하기 쉽게 합니다.

프로세스 트리는 기본으로 모든 분기를 접습니다. 부모 프로세스 왼쪽의 화살표, 두 번 클릭, 좌우 방향 키, 상황에 맞는 메뉴의 “펼치기”, “접기”로 분기 하나씩 조정할 수 있고, 프로세스 표의 열 제목(이름, CPU 등)에서 마우스 오른쪽 단추로 클릭하면 “모두 확장”과 “모두 축소”를 고를 수 있습니다. 펼친 상태는 현재 실행 중에 유지되고 다시 시작하면 다시 접히며 새로 나타난 분기는 기본으로 접힙니다. 검색할 때는 일치하는 프로세스의 상위를 자동으로 펼치고 접기 조작을 잠시 막으며, 검색을 지우면 원래 펼친 상태로 돌아갑니다.

선택할 수 있는 열에는 부모 PID, 이미지 이름과 경로, 설명, 회사, 파일 버전, 아키텍처, 권한 상승 여부, 명령줄, 세션, 시작 시간, 프로세스 상태, CPU 누적 시간, 우선 순위, 작업 집합과 최대 작업 집합, 커밋 크기, 가상 주소 공간, 페이지 오류 횟수, 메모리 우선 순위, I/O 누적 바이트, I/O 우선 순위, 네트워크 받기와 보내기, GPU 엔진과 비디오 메모리 사용량이 있습니다.

앱 그룹은 현재 리소스 카운트와 누적 시간, I/O 바이트를 합산합니다. 가상 주소 공간과 최대 작업 집합은 프로세스 단위로 표시하며 앱 그룹을 펼쳐 확인합니다. 가상 주소 공간은 예약한 주소 범위와 커밋한 주소 범위를 포함하므로 브라우저 같은 프로그램은 수 TB를 예약할 수 있습니다. 현재 전용 커밋 사용량은 “커밋 크기”에 있습니다. 최대값, 주소 범위, 누적 카운트는 보통 배경색을 씁니다. PID, 시작 시간, 우선 순위, 상태 같은 인스턴스 속성은 프로세스 한 행에만 표시하고, 경로나 회사 같은 글자는 구성원이 같을 때 공통 값을 표시합니다. 네트워크 수집을 쓸 수 없을 때는 네트워크 열을 숨기고 선택은 남겨 두어 나중에 되살립니다. 현재 정렬한 열을 해제하면 이름 오름차순으로 배열합니다.

## 제목 표시줄, 탐색 창, 개요 영역과 상태 표시줄

- **개요 영역**: CPU, 메모리, 가장 사용량이 많은 디스크, 네트워크, GPU. 큰 숫자 아래에 보조 표시값이 있습니다. CPU는 클록, 온도, 전력이고, GPU는 온도와 전력(현재 가장 사용량이 많은 그래픽 카드 기준)이며, 메모리는 사용 비율, 디스크는 활성 시간, 네트워크는 받기와 보내기 속도입니다. 없는 표시값은 표시하지 않고 카드가 좁으면 숫자와 보조 표시값의 글꼴 크기가 함께 줄어듭니다. 곡선은 카드를 가득 채우고 글자 아래에서 사라지며, 위쪽 가는 선이 양 범위 상한을 표시하고 오른쪽 위에 상한 값을 적습니다(사용률은 100%, 메모리는 전체 용량, 디스크와 네트워크는 현재 단계). CPU 온도와 전력의 출처는 포인터를 올려 확인하고, GPU 전력은 와트를 먼저 표시하며 상대 표시값만 있을 때는 `% TDP`를 표시합니다. 카드를 클릭하면 “성능” 페이지의 해당 장치로 이동합니다.
- **탐색 창**: 기본으로 탭 형태로 제목 표시줄 아래에 놓이고 탭 오른쪽에 페이지 막대가 있습니다. “설정 → 언어 및 모양”이나 첫 실행 가이드에서 측면 탐색 창으로 바꿀 수 있습니다. 창 왼쪽에 놓이고 “설정”과 “정보”는 아래쪽에 있습니다. 기본으로 아이콘만 표시하며(포인터를 올리면 페이지 이름과 바로 가기를 볼 수 있습니다) 위쪽의 ☰ 단추를 클릭하면 페이지 이름이 나타나고 다시 클릭하면 접힙니다. 펼친 뒤에는 사이드바 오른쪽 가장자리를 끌어 너비를 조정하고(150–320 px) 두 번 클릭해 기본 너비로 되돌립니다. 위치, 펼친 상태, 너비는 다시 시작한 뒤에도 유지됩니다.
- **제목 표시줄**: 빈 곳을 끌어 창을 옮기고 두 번 클릭해 최대화하며, 가장 오른쪽에 최소화, 최대화, 닫기 단추가 있습니다(최대화 단추에 포인터를 두면 Windows 11이 스냅 레이아웃을 표시합니다). 왼쪽에는 GoodGood 로고와 이름이 있고 가운데에는 현재 페이지의 검색 상자가 있으며 너비는 창 너비의 약 30%(자리 표시자 글자보다 좁지 않고 480 px을 넘지 않음)이고, 공간이 넉넉하고 입력 중이 아니면 오른쪽 끝에 바로 가기 Ctrl+F를 표시합니다. 양쪽 공간이 넉넉하면 검색 상자가 창 가운데에 놓이고 그렇지 않으면 왼쪽 이름 뒤에 붙습니다.
- **페이지 막대**: 위쪽 탐색이면 탭 오른쪽에, 측면 탐색이면 페이지 위쪽에 놓이며 왼쪽에 페이지 이름을 표시합니다. 이어서 현재 페이지의 컨트롤과 “추가 작업” 단추가 있습니다. 프로세스 페이지는 보기 전환(앱, 트리, 목록이며 아이콘만 표시), 시스템 프로세스 숨기기와 자세히 창 단추이고, 서비스 페이지는 선택한 서비스에 대한 시작·중지·다시 시작이며, 연결 페이지는 시스템 프로세스 숨기기, 기록 페이지는 시간 범위와 “최신 데이터로 돌아가기”입니다. 서비스 페이지와 연결 페이지의 필터는 목록 “상태” 열의 표 머리글에 있습니다. 머리글 오른쪽 끝의 ⌄를 클릭해 전체, 실행 중, 중지됨을 고르고(연결 페이지는 전체, 수신 대기, 연결됨) 연결 페이지의 “프로토콜” 열에는 전체, TCP, TCPv6, UDP, UDPv6를 고르는 프로토콜 필터가 따로 있으며 상태 필터와 함께 동작합니다. 필터가 걸려 있으면 그 단추가 강조색 깔때기 아이콘으로 표시됩니다. 머리글의 나머지 부분을 클릭하면 여전히 그 열로 정렬합니다. “추가 작업”은 모든 페이지에서 가장 오른쪽에 있고 “새 작업 실행…”(Ctrl+N), “파일을 사용하는 프로세스 찾기…”, 서비스 페이지의 “Windows 서비스 관리자 열기”, 바로 가기 안내가 들어 있습니다. 탭(또는 페이지 이름)과 컨트롤 사이의 빈 곳에서도 창을 끌고 두 번 클릭해 최대화할 수 있습니다. 창이 좁으면 기록 페이지의 시간 범위가 먼저 현재 선택을 보여 주는 드롭다운 단추로 바뀌고, 그래도 자리가 모자라면 페이지 컨트롤이 아래 별도 행으로 내려갑니다. 포인터를 올리면 단추 이름은 계속 볼 수 있습니다.
- **상태 표시줄**: 가장 왼쪽에 버전 번호가 있고 테스트 빌드는 버전 번호 뒤에 커밋 수를 붙입니다(포인터를 올리면 전체 버전과 업데이트 채널을 볼 수 있습니다). 클릭하면 이 버전의 새로운 기능이 열리고, 마우스 오른쪽 단추로 클릭하면 버전 번호를 복사하며, 새 버전이 있으면 업데이트 표시로 바뀝니다([설정 → 업데이트](settings.md#업데이트) 참고). 이어서 스레드 수, 핸들 수, 캐시됨, 페이징된 풀, 가동 시간이 있고 창이 좁으면 마지막 항목부터 차례로 숨깁니다. 오른쪽 끝에는 새로 고침 컨트롤과 권한 표시가 있습니다. 새로 고침 컨트롤 왼쪽에 새로 고침 상태를 표시하고(예: “1초마다 업데이트”, “업데이트 일시 중지됨”) 클릭하면 새로 고침 빈도를 고를 수 있으며 다시 클릭하면 접힙니다. 오른쪽 끝의 단추를 클릭하면 새로 고침을 일시 중지하거나 다시 시작하고 모든 페이지에 적용되며, 위치는 상태 글자에 따라 움직이지 않습니다. 권한 표시가 “관리자”이면 GoodGood이 관리자 권한으로 실행 중이고, “권한 있는 서비스”이면 GoodGood이 표준 권한으로 실행되며 관리자 권한이 필요한 작업은 연결된 권한 있는 서비스가 수행합니다. “표준 사용자”이면 둘 다 아닙니다. 포인터를 올리면 설명을 볼 수 있습니다.

새로 고침을 일시 중지하면 화면의 데이터만 고정되고 기록과 규칙은 그대로 진행됩니다(이 동안에는 5초마다 샘플링합니다).

메모리 페이지의 구성 막대는 “사용 중”, “수정됨”, “대기”, “사용 가능”을 구분합니다. 수정된 내용은 디스크에 먼저 기록해야 다시 쓸 수 있고, 대기 메모리는 사용 중이 아닌 캐시 데이터와 코드를 담으며, 사용 가능한 메모리는 바로 할당할 수 있습니다. “캐시됨”은 대기와 수정된 메모리를, “사용 가능”은 대기와 사용 가능한 메모리를 포함합니다. 네 항목의 설명은 아래 색상 블록 아이콘에 포인터를 올릴 때만 표시되고 설명 글자는 샘플링 값에 따라 바뀌지 않으며, 머무는 동안 아이콘 위치가 고정됩니다. 구성 세부 정보가 없으면 “—”를 표시합니다. 프로세스 합계와 시스템 전체 사용량의 차이는 [메모리 집계 기준](#메모리-집계-기준)을 참고합니다.

프로세스 페이지나 성능 페이지에서 Ctrl을 누르고 있으면 새로 고침이 잠시 일시 중지되고 곡선은 일시 중지한 순간의 위치를 유지합니다. Ctrl을 놓거나 다른 창으로 전환하거나 창을 숨기면 임시 일시 중지가 풀립니다. 직접 일시 중지한 상태는 유지되며, Ctrl을 누른 채 상태 표시줄의 일시 중지 단추를 클릭하면 놓은 뒤에 일시 중지를 유지할지 새로 고침을 다시 시작할지 고를 수 있습니다.

포인터가 프로세스 목록 위에 있거나 상황에 맞는 메뉴나 확인 대화 상자가 열려 있으면 행 위치가 고정되고 리소스 표시값은 계속 갱신됩니다. 이때 그룹과 자식 프로세스를 펼치거나 접으면 펼친 행은 해당 항목 아래에 표시되고 나머지 행은 위치를 유지합니다. 포인터를 옮기거나 메뉴와 대화 상자를 닫으면 정렬이 돌아옵니다. 그래서 행 순서가 현재 정렬과 다르면 정렬 열 머리글의 화살표가 강조색 일시 중지 아이콘으로 바뀌고, 포인터 때문에 생긴 경우에는 상태 표시줄에 “정렬 일시 중지”가 함께 표시되며 포인터를 올리면 설명을 볼 수 있습니다. “설정 → 언어 및 모양”에서 “마우스를 올린 동안 정렬 일시 중지”를 끄면 목록이 표시값에 따라 실시간으로 정렬되고, 상황에 맞는 메뉴나 확인 대화 상자가 열려 있을 때는 여전히 행 위치를 유지합니다.

프로세스 조회가 오래 걸리면 표는 마지막으로 유효했던 표시값을 유지하고 포인터를 올리면 갱신 상태를 볼 수 있으며, 10초를 넘긴 표시값은 흐리게 보여 줍니다. 새 표시값이 도착하면 자동으로 갱신되고, 기다리는 동안 유지한 값은 곡선과 기록 통계에 다시 넣지 않습니다. 시스템과 장치 표시값은 계속 따로 갱신됩니다.

경량 프로세스 열거를 지원하는 시스템은 프로세스 명단을 따로 갱신합니다. 전체 카운트 조회가 느릴 때도 새 프로세스는 나타나고 종료된 프로세스는 빠지며, 새 프로세스는 카운트를 얻기 전까지 “—”를 표시하고 얻은 뒤 채워지며 선택은 유지됩니다. 프로세스 신원이 아직 확인되지 않으면 작업 끝내기, 우선 순위, 효율성 모드 조작을 잠시 할 수 없습니다. 다른 시스템은 전체 스냅숏으로 명단을 갱신합니다.

“디스크 읽기”와 “디스크 쓰기”는 각각 디스크 읽기·쓰기 속도를 집계하고, I/O 열은 네트워크와 장치 접근도 포함합니다. Windows 11 24H2 이상은 일반 프로세스 조회를 먼저 쓰고, 다른 시스템은 권한 있는 서비스나 관리자 권한으로 수집할 수 있습니다. 유휴 상태에서는 “0”을, 표시값이 없을 때는 “—”를 표시하고 포인터를 올리면 이유를 볼 수 있습니다. 표 머리글과 앱 그룹은 이미 있는 표시값을 합산하고 전부 결측이면 “—”를 표시합니다.

프로세스 표의 GPU 열은 그 프로세스가 가장 사용량이 많은 GPU 엔진에서 차지한 시간 비율이고, 포인터를 올리면 어느 엔진인지 볼 수 있습니다(예: “GPU 0 - 3D”). 앱 그룹은 합산한 뒤 가장 사용량이 많은 엔진을 표시합니다. 전용 및 공유 GPU 메모리는 Windows가 보고하는 프로세스 상주 사용량을 쓰고 결측 표시값은 “—”로 표시합니다. 통합 그래픽이 쓰는 시스템 메모리는 공유 GPU 메모리에 들어가고 펌웨어가 그래픽에 예약한 부분만 전용 GPU 메모리에 들어갑니다. 공유 리소스는 여러 프로세스에 귀속될 수 있고, 그래픽 카드 전체의 실제 사용량은 성능 페이지에 있습니다. GPU 열은 성능 페이지에 나열된 그래픽 카드만 집계하고, 그래픽 카드를 감지하지 못하면(Microsoft 기본 렌더링 드라이버만 있는 가상 머신 등) GPU 열을 숨기고 선택은 남겨 둡니다. GoodGood을 관리자 권한으로 실행하거나 권한 있는 서비스를 켜고 ETW를 쓸 수 있으면 프로세스 표에 네트워크 열이 추가되어 프로세스마다 초당 보내고 받은 데이터량을 보여 주며 포인터를 올리면 보내기와 받기를 따로 볼 수 있습니다. 수집을 쓸 수 없으면 이 열을 숨깁니다. 표에 다 들어가지 않으면 가로로 스크롤할 수 있고 이름 열은 왼쪽에 고정됩니다.

앱 보기는 실행 파일 경로로 프로세스를 합치므로 설치 위치가 다른 같은 이름의 프로그램은 따로 표시합니다. 다른 앱이 시작한 WebView2 자식 프로세스는 호스트와 런타임 인스턴스별로 그룹화하고, 펼치면 렌더러, GPU, 네트워크 같은 역할을 볼 수 있으며 호스트 이름으로도 검색할 수 있습니다. 서비스 호스트는 호스팅하는 서비스를 표시하고, 호스트를 알아내지 못한 다른 프로세스는 프로세스 트리에서 부모·자식 관계를 확인합니다.

앱 패키지(MSIX) 프로그램은 Windows 작업 관리자와 마찬가지로 앱 이름을 표시하며(예: “터미널”) 이름에 Windows 표시 언어를 씁니다. 앱 패키지가 시작한 보조 프로세스(콘솔 호스트, 백그라운드 작업 호스트 등)는 계속 각자의 설명을 표시합니다. 이름순으로 정렬할 때 한국어 인터페이스는 한글 이름을 로마자보다 앞에 두고 영어 인터페이스는 로마자를 앞에 둡니다. 이름에 있는 숫자는 값으로 비교하고 대소문자와 악센트는 구분하지 않습니다. 서비스, 시작 프로그램, 연결 페이지의 텍스트 열도 같은 규칙으로 정렬합니다.

작업 표시줄 창을 가진 프로그램은 “앱”에 들어가고, 나머지 프로세스 중 시스템 디렉터리에 있고 Windows 구성 요소 버전 정보를 가진 프로그램과 시스템 커널 프로세스는 “Windows 프로세스”에, 다른 프로그램은 “백그라운드 프로세스”에 들어갑니다. 그룹은 둘러보기 쉽게 할 뿐이므로 프로세스를 끝내기 전에 용도를 확인해야 합니다. 제목의 수는 현재 필터의 최상위 항목을 세고 자식 프로세스를 펼쳐도 늘지 않으며, 일치하는 항목이 없는 그룹은 표시하지 않습니다. CPU, 메모리 같은 숫자로 정렬할 때는 사용량이 가장 많은 프로세스를 찾기 쉽게 전체에서 정렬합니다.

목록의 앱이나 프로세스를 클릭하면 선택되고 다시 클릭하면 선택이 해제됩니다. 두 번 클릭은 하위 항목이 있는 행(앱 그룹, 프로세스 트리의 부모 프로세스)을 펼치거나 접는 데만 씁니다. 자세히 창은 기본으로 목록 오른쪽에 상주합니다. 행을 선택하면 그 세부 정보를 표시하고 아무것도 선택하지 않으면 이 PC 사양(프로세서, 메모리, 저장소, 네트워크, 그래픽, 배터리이며 항목을 클릭하면 “성능” 페이지의 해당 장치로 이동합니다)을 표시합니다. 페이지 막대의 창 단추에는 세 가지 상태가 있고 클릭할 때마다 차례로 바뀌며 마우스 오른쪽 단추로 클릭하면 바로 고를 수 있습니다.

| 상태 | 단추 | 창 |
|---|---|---|
| 항상 표시 | 창 아이콘, 강조색 | 목록 오른쪽에 상주하고 아무것도 선택하지 않으면 PC 사양을 표시 |
| 프로세스를 선택하면 표시 | 오른쪽 열에 화살표가 붙은 창 아이콘, 강조색 | 프로세스를 클릭하면 미끄러져 나오고, 그 행을 다시 클릭하거나 창 오른쪽 위의 닫기 단추로 선택을 해제하면 미끄러져 숨음 |
| 숨기기 | 창 아이콘 | 표시하지 않음. Enter를 누르거나 다른 곳에서 프로세스 세부 정보를 볼 때 “항상 표시”로 바뀜 |

선택한 상태는 다시 시작한 뒤에도 유지됩니다. 창 왼쪽 가장자리를 끌어 너비를 조정하고 두 번 클릭해 기본 너비로 되돌립니다.

“이 PC” 제목 오른쪽의 표시·숨김 단추는 하드웨어 목록만 숨기고 창의 팁은 남기며 표시 상태를 기억합니다. 프로세스를 선택한 뒤 세부 정보를 보는 데는 영향을 주지 않습니다. “팁” 제목을 클릭하면 팁 내용을 접거나 펼칠 수 있고 접으면 제목 행만 남으며 펼친 상태도 다시 시작한 뒤 유지됩니다. “PC 사양을 텍스트로 복사”를 클릭하면 현재 하드웨어 사양을 복사하며 목록이 숨겨져 있어도 복사할 수 있습니다. GitHub에 표시값 이상을 보고할 때 관련 사양을 “관련 하드웨어” 항목에 붙여넣을 수 있고, 기능 제안에서는 해당 항목이 “참고 및 보충”입니다.

앱 그룹을 선택하면 자세히 창이 그 그룹의 CPU와 메모리 곡선, 리소스 합계, 가장 이른 시작 시간, 파일 위치, CPU순으로 정렬한 구성원을 표시합니다. 구성원을 클릭하면 프로세스 하나의 세부 정보를 볼 수 있습니다. 끝내기, 우선 순위, 효율성 모드 조작은 선택한 그룹에만 적용됩니다.

네트워크 속도는 기본으로 초당 바이트(KB/s, MB/s이며 디스크와 같습니다)로 표시하고, “설정 → 데이터 및 기록”에서 초당 비트(Kbps, Mbps이며 네트워크 어댑터 링크 속도와 회선 요금제에 맞춥니다)로 바꿀 수 있습니다. 개요 영역, 프로세스 표, 자세히 창, 기록 페이지가 함께 바뀌고, 성능 페이지의 네트워크 보기는 항상 두 단위를 함께 표시합니다.

## GPU 집계 기준

프로세스 GPU 사용량은 가장 사용량이 많은 엔진 하나를 씁니다. 앱 그룹과 범주 제목은 어댑터, 물리 GPU, 엔진 노드의 전체 신원으로 프로세스 기여도를 먼저 합산한 뒤 가장 사용량이 많은 노드를 고릅니다. 다른 그래픽 카드나 엔진 노드는 따로 계산하고 같은 이름의 엔진은 각자의 노드로 구분합니다.

전체 사용량은 Windows 엔진 시간을 바탕으로 하고 유효한 프로세스 엔진 표시값보다 낮지 않습니다. NVIDIA 그래픽 카드는 NVML 코어 사용률로 연산 부하를 보충합니다. 성능 페이지는 이번 표시값의 출처를 보여 주고, 개요 영역의 GPU 숫자도 포인터를 올리면 출처를 볼 수 있습니다. NVML 보충은 네이티브 엔진 곡선을 다시 쓰지 않습니다. 다른 도구와 비교할 때는 어댑터, 엔진, 샘플링 창을 함께 확인하고 영상, 3D, 연산 부하의 해당 지표를 각각 대조해야 합니다.

## 메모리 집계 기준

개요 영역, 프로세스 표 머리글, 프로세스 행의 “메모리”는 서로 다른 기준을 씁니다. 개요 영역의 메모리 값, 프로세스 표 머리글의 “메모리”, 범주 제목의 메모리 합계에 포인터를 올리면 해당 기준의 설명을 볼 수 있습니다.

| 위치 | 집계 의미 |
|---|---|
| 개요 영역의 사용 중인 메모리 | 시스템 전체 물리 메모리에서 사용 가능한 메모리를 뺀 값이며 사용 중 페이지와 수정된 페이지를 포함 |
| 프로세스 표 머리글의 메모리 백분율 | 위의 시스템 전체 사용량이 전체 물리 메모리에서 차지하는 비율 |
| 프로세스 행, 앱 그룹, 범주 제목의 메모리 값 | 전용 작업 집합, 즉 프로세스가 독점하고 물리 메모리에 상주한 부분. 그룹과 범주는 이 기준으로 합산 |

범주 제목은 각 프로세스의 전용 작업 집합을 합산하고, 시스템 전체 사용량에는 공유 상주 페이지, 커널과 드라이버, 페이지 테이블, 사용 중인 시스템 캐시, 수정된 페이지 등도 관여합니다. “Windows 프로세스”는 그 범주의 프로세스 전용 작업 집합을 집계합니다. 전체 작업 집합은 공유 페이지를 포함하므로 그대로 더하면 프로세스 사이에 공유된 부분을 두 번 세게 됩니다.

대기 메모리는 “사용 가능”에 들어가며, 시스템의 각 메모리 종류별 사용량은 “성능 → 메모리”의 구성 데이터로 확인합니다.

각 메모리 종류의 수집 출처는 [하드웨어 데이터](hardware-data.md)를 참고합니다.

## 디스크 세부 정보

디스크 제목 옆의 “개요 / 세부 정보”가 두 페이지를 오가고 선택한 페이지는 다시 시작한 뒤에도 유지됩니다. 세부 정보 페이지는 열 때마다 디스크 정보를 한 번 읽고, 전환 단추 옆의 “다시 읽기”를 클릭하면 다시 읽으며 상태 카드 오른쪽 위에 읽은 시각을 표시합니다. 온도는 실시간 표시값을 보여 주고 나머지 값은 읽은 시점의 상태를 유지합니다.

- **상태**: 상태, 남은 수명, 온도, 사용 가능한 예비 영역과 그 아래에 총 읽기, 총 쓰기, 전원 켜진 시간, 전원 주기, 비정상 종료, 미디어 오류를 나열합니다. 매핑을 마친 SATA SSD는 모델에 맞춰 수명, 누적 호스트 읽기·쓰기, 전원 통계, 비정상 전원 차단, 수정할 수 없는 오류를 표시하고, 예비 영역 비율을 제공하는 모델은 그 비율과 임계값도 표시합니다. SATA/ATA HDD는 읽을 수 있는 전원 켜진 시간, 시작·정지, 헤드 로드, 재할당·보류 중·오프라인 수정 불가 섹터, 인터페이스 CRC 카운트를 표시하고 매핑을 마친 읽기·쓰기 총량도 나열합니다. NVMe 온도 막대는 디스크가 보고한 위험 온도를 가득 찬 눈금으로 삼고 눈금선으로 경고 온도를 표시하며, 예비 영역 막대의 눈금선은 임계값을 표시합니다.
- **장치 정보**: 모델, 펌웨어 버전, 일련 번호, 용량, 볼륨, 인터페이스, PCIe, SATA 또는 PATA UDMA 전송 모드(현재 링크와 장치가 지원하는 최대 링크가 다르면 함께 표시), NVMe 또는 ATA 표준 버전, 섹터 크기와 지원 기능(장치가 보고한 SMART, TRIM, 쓰기 캐시, NCQ 포함). 일련 번호는 기본으로 숨겨지고 “표시”를 클릭해 봅니다.
- **SMART 특성**: NVMe 상태 로그는 상태, 사용량, 온도로 묶고 읽기·쓰기량은 512,000바이트 단위로 환산합니다. 온도 원시 값의 단위는 켈빈이고 보고하지 않는 센서는 나열하지 않습니다. ATA/SATA와 SAT를 지원하는 브리지 장치는 특성 번호, 이름, 현재 값, 최악 값, 임계값, 16진 원시 값을 표시하고 식별한 SSD 필드는 모델에 맞춰 이름을 붙입니다. SCSI/SAS는 장치가 제공하는 상태, 온도, 읽기·쓰기 오류 통계를 표시합니다. 이상한 값은 빨간색으로 표시합니다.

SMART 특성 표는 창 너비에 맞춰 조정됩니다. 각 열은 그 안에서 가장 넓은 글자에 맞춰 너비를 정하고 이름과 값은 붙여 두며, 남는 너비는 숫자 열에 고르게 나눕니다. NVMe의 상태, 사용량, 온도 세 묶음은 각 칸 높이가 비슷하면 나란히 놓고 그렇지 않으면 위아래로 놓으며, 각 묶음의 행을 다시 열로 나눕니다. ATA/SATA 특성은 자리가 되면 최대 3장의 표로 나란히 놓고 각 표는 5행 이상입니다. 더 이상 나누지 않을 때는 표 하나의 너비를 글자에 필요한 너비의 두 배로 제한하고 나머지 너비는 표 사이에 남깁니다. 창이 좁으면 이름이 줄을 바꾸고 그래도 들어가지 않으면 값이 이름 아래로 내려갑니다. 포인터가 있는 행은 배경색으로 표시합니다.

상태는 다음 규칙으로 판정합니다.

| 상태 | 조건 |
|---|---|
| 나쁨 | 심각한 경고의 예비 영역이 임계값 미만, 신뢰성 저하, 미디어가 읽기 전용으로 전환, 휘발성 메모리 백업 실패, 영구 메모리 영역이 읽기 전용, 또는 사용 가능한 예비 영역이 임계값 미만 |
| 주의 | 심각한 경고의 온도가 임계값을 초과하거나 아직 정의되지 않은 경고 비트, 미디어 및 데이터 무결성 오류, 남은 수명이 10% 이하, 또는 HDD에 재할당·보류 중·오프라인 수정 불가 섹터 존재 |
| 양호 | 위의 경우가 하나도 없음 |

NVMe의 남은 수명은 `100 − 사용 비율`이고 사용 비율은 제조사가 추정한 내구도이므로 100%를 넘을 수 있습니다. 심각한 경고와 남은 수명은 따로 판정합니다. ATA/SATA, USB-SAT, SCSI/SAS의 확장 데이터는 실행 중인 권한 있는 서비스로 읽으며 “설정 → 권한”에서 서비스를 설치, 시작, 업데이트할 수 있습니다. 없는 임계값과 표시값은 “—”로 표시하고 장치 고장 예측을 얻지 못하면 상태를 “알 수 없음”으로 표시합니다. 읽을 때 장치의 SMART 사용 상태를 유지합니다. 제조사 전용 USB/RAID 채널의 적용 범위는 로드맵에 있습니다.

일련 번호는 NVMe/ATA 제조사 SN을 먼저 쓰고 없으면 SCSI 장치 일련 번호와 Windows 일반 저장소 설명자로 물러납니다. 회전 속도는 ATA 장치가 보고한 값으로 표시합니다.

## 새 작업 실행과 Windows 탐색기 다시 시작

“새 작업 실행…”은 페이지 막대 가장 오른쪽의 “추가 작업” 메뉴에 있고 어느 페이지에서나 쓸 수 있으며 Ctrl+N으로도 엽니다. 프로그램 이름, 파일이나 폴더 경로를 입력하고 시작 인수를 덧붙일 수 있으며 “찾아보기…”로 파일을 고를 수 있습니다. “관리자 권한으로 실행”을 선택하면 Windows가 권한 부여를 처리합니다. 권한 부여를 취소하거나 시작에 실패하면 입력을 남겨 두어 고친 뒤 다시 시도할 수 있습니다. 선택하지 않으면 GoodGood 자체가 관리자 권한으로 실행 중이어도 표준 권한으로 시작합니다.

현재 바탕 화면의 Windows 탐색기에서 마우스 오른쪽 단추로 클릭해 “다시 시작”을 고르고 확인하면 바탕 화면과 작업 표시줄을 되살릴 수 있습니다. 표준 권한과 높은 권한의 탐색기를 모두 지원하고 다시 시작한 뒤에도 원래 계정과 권한을 유지하며, 높은 권한 인스턴스를 다시 시작하려면 GoodGood이 관리자 권한으로 실행 중이어야 합니다. 이 작업은 탐색기 창과 진행 중인 파일 작업에 영향을 줄 수 있고 현재 바탕 화면을 호스팅하는 인스턴스에만 적용됩니다. 그 인스턴스에서는 “다시 시작”을 쓸 수 있고 “작업 끝내기”와 “프로세스 트리 끝내기”는 모두 비활성화됩니다. 탐색기가 이미 종료되었다면 “새 작업 실행…”에서 `explorer.exe`를 입력해 다시 열 수 있습니다.

다시 시작하기 전에 권한을 확인하고 대체 프로세스를 준비합니다. 기존 탐색기가 종료 정리나 오류 보고 단계에서 멈춰 있으면 시간 초과 뒤 확인한 기존 인스턴스를 끝내고 종료를 확인한 다음 바탕 화면을 되살립니다. Windows가 이미 바탕 화면을 되살렸다면 기존 인스턴스를 씁니다. 바탕 화면과 작업 표시줄이 모두 응답한 뒤에야 다시 시작이 끝났다고 알립니다.

## 우선 순위, 효율성 모드와 일시 중단

프로세스(또는 앱 보기의 프로세스 그룹)에서 마우스 오른쪽 단추로 클릭합니다.

- **우선 순위 설정**: 실시간, 높음, 보통 초과, 보통, 보통 미만, 낮음. 실시간으로 설정하기 전에 먼저 확인하고, 표준 권한으로 실행 중이면 Windows가 실시간을 높음으로 낮추며 GoodGood이 이를 알립니다.
- **I/O 우선 순위**: 매우 낮음, 낮음, 보통. 낮추면 그 프로세스의 디스크 읽기·쓰기가 다른 프로세스 뒤로 밀리므로 백그라운드 압축, 인덱싱, 동기화, 다운로드가 디스크를 가득 채울 때 포그라운드 프로그램을 부드럽게 유지하기에 적합합니다. 높음과 중요 두 단계는 Windows가 예약하므로 설정할 수 없습니다. 현재 값은 “I/O 우선 순위”, “메모리 우선 순위” 두 열에서도 확인하고 단계별로 정렬할 수 있습니다.
- **메모리 우선 순위**: 매우 낮음, 낮음, 중간, 보통 미만, 보통. 메모리가 부족할 때 Windows가 우선 순위가 낮은 프로세스의 메모리 페이지부터 회수하므로 자주 쓰지 않는 백그라운드 프로그램에 적합합니다.
- **효율성 모드**: Windows 작업 관리자와 같으며 Windows가 그 프로세스를 우선적으로 E 코어와 낮은 주파수에서 실행하도록 배치하고 우선 순위를 낮음으로 내립니다. 끄면 원래 우선 순위로 돌아갑니다. 효율성 모드인 프로세스는 이름 뒤에 잎 표시가 붙습니다.
- **프로세스 일시 중단 / 프로세스 다시 시작**: 프로세스의 모든 스레드를 다시 시작할 때까지 일시 중단하며, 오래 실행되는 렌더링, 인코딩, 컴파일 작업에 잠시 자리를 내주기에 적합합니다. 일시 중단하기 전에 먼저 확인합니다. 일시 중단한 프로그램의 창이 응답을 멈추고 네트워크 연결이 시간 초과될 수 있으며, 안티 치트나 자기 보호 기능이 있는 프로그램에서 오류가 날 수 있습니다. 시스템 중요 프로세스, 데스크톱 창 관리자(`dwm.exe`), GoodGood 자체와 그 권한 있는 서비스는 일시 중단할 수 없습니다. 일시 중단은 아직 실행 중인 프로세스에만, “프로세스 다시 시작”은 일시 중단된 프로세스에만 적용되며, 앱이 일시 중단 뒤 새 프로세스를 시작했으면 메뉴가 두 항목을 함께 제공합니다. Windows가 백그라운드에서 유예한 앱 패키지(예: 최소화한 “계산기”)도 “일시 중단됨”으로 표시되지만 Windows가 스스로 다시 시작하며 메뉴는 두 항목을 제공하지 않습니다. 실행할 때는 프로세스의 현재 스레드 상태에 따라 처리합니다. 이미 일시 중단된 프로세스는 다시 일시 중단하지 않고, 다시 시작은 일시 중단 한 번을 되돌리며 프로그램이나 디버거가 스스로 일시 중단한 스레드는 일시 중단 상태로 남습니다. 다른 도구가 여러 번 겹쳐 일시 중단한 프로세스는 다시 시작한 뒤에도 일시 중단 상태일 수 있으므로 한 번 더 다시 시작할 수 있습니다.
- **규칙 추가**: 그 프로그램을 위한 규칙을 만들어 이후 시작할 때마다 자동으로 적용합니다. [설정](settings.md#규칙)을 참고합니다.

시스템 프로세스와 다른 사용자의 프로세스는 [권한 있는 서비스](settings.md#권한)를 켜거나 GoodGood을 관리자 권한으로 실행해야 바꿀 수 있습니다.

## 시작 항목

시작 프로그램 페이지는 레지스트리 Run 항목, 시작 폴더의 항목, 현재 계정에 설치된 앱 패키지 시작 작업을 나열합니다. 같은 앱의 여러 시작 작업은 따로 표시하고, 이름은 프로그램 설명이나 앱 패키지의 지역화 이름을 먼저 쓰며 원래 항목 이름으로도 검색할 수 있고 이름의 마우스 올림 도움말에도 표시합니다.

스위치를 클릭하거나 상황에 맞는 메뉴로 다음 로그인 때 시작할 항목을 사용하거나 사용 안 함으로 바꿀 수 있고 Windows 작업 관리자와 상태를 공유합니다. 앱 패키지 시작 작업은 표준 권한에서도 바꿀 수 있고, “모든 사용자”의 전통적인 시작 항목에는 여전히 관리자 권한이 필요합니다. 앱이 직접 변경을 허용하지 않거나 상태를 잠시 읽을 수 없으면 스위치를 비활성화하고 이유를 설명합니다. 페이지가 보이는 동안에는 10초마다 갱신되고 페이지로 돌아오면 다시 읽습니다.

앱 패키지 시작 작업을 켜면 다음 로그인 때 바로 시작합니다. Windows 작업 관리자가 아직 이전 상태를 표시하면 다시 열어 확인합니다.

## 메모와 고정

서비스, 시작 프로그램, 연결 페이지는 항목에 메모를 추가하거나 맨 위에 고정할 수 있습니다. 항목에서 마우스 오른쪽 단추로 클릭해 “맨 위에 고정”, “고정 해제” 또는 “메모 추가”, “메모 편집”, “메모 삭제”를 고릅니다. 메모는 이름 뒤에 표시되고 아이콘이 붙은 옅은 레이블로 이름과 구분합니다. 이름은 항상 온전히 표시되고 공간이 부족하면 메모가 먼저 좁아지며 포인터를 올리면 전체를 볼 수 있습니다. 검색 상자는 메모도 함께 찾습니다. 고정한 항목은 목록 맨 앞에 놓이고 이름 열 끝에 압정이 표시되며 아래에 구분선으로 나머지 항목과 나뉩니다. 고정한 항목끼리는 현재 정렬대로 배열합니다.

메모와 고정은 인터페이스 환경 설정과 함께 이 PC에 저장되고 다시 시작한 뒤에도 유지됩니다. 서비스는 서비스 이름으로, 시작 항목은 위치와 항목 이름으로 기억합니다. 연결은 프로그램과 포트로 기억합니다. 수신 대기 포트, UDP 포트, 수신 대기 포트를 통해 받은 연결은 로컬 포트로, 프로그램이 직접 시작한 연결은 원격 주소와 포트로 구분합니다. 같은 프로그램의 같은 포트에 있는 여러 연결은 메모와 고정을 공유하므로 프로그램을 다시 시작해 PID가 바뀌어도 유효합니다.

## 기록

GoodGood이 실행되는 동안 5초마다 프레임 하나를 기록합니다. 시스템 전체 CPU(이 5초 동안 각 샘플의 평균과 최대값), 메모리, 디스크와 네트워크 처리량, GPU, 배터리가 있는 장치는 배터리 충전 수준과 충전·방전 전력(충전 수준은 각 배터리의 평균, 전력은 각 배터리의 합)이며, 그 시점에 CPU, 메모리, I/O, GPU, 네트워크 사용량이 가장 많은 프로세스 몇 개도 함께 기록합니다. 창을 최소화했거나 알림 영역에 숨겼거나 새로 고침을 일시 중지한 동안에도 그대로 기록합니다. 최소화 또는 백그라운드 상주 시의 새로 고침 간격이 5초보다 길면 그 간격으로 기록하고 곡선이 드물어지지만 여전히 이어집니다. GoodGood이 실행되지 않은 구간은 곡선이 비고, 간격을 길게 두고 기록한 구간에 바로 붙어 있으면 1분 정도의 중단은 비우지 않습니다.

기록의 디스크 처리량은 읽기·쓰기 카운트를 모두 쓸 수 있는 디스크를 합산하고 전부 결측이면 0으로 기록합니다. 실시간 개요 영역은 어느 한 디스크의 카운트라도 결측이면 “—”를 표시하므로 기록의 합산 기준과 다릅니다.

- **시간 범위**: 페이지 막대에서 1시간, 6시간, 24시간, 7일을 고르면 차트가 지금까지의 그 구간을 표시하고 시간이 흐르는 만큼 정기적으로 앞으로 나아갑니다(1시간 범위는 10초마다, 7일 범위는 5분마다). CPU 곡선 위의 옅은 선은 각 구간에서 샘플링한 최대값입니다.
- **CPU 최대 프레임**: 평균과 최대값을 따로 표시합니다. “CPU 최대 프레임 표시”는 선택한 차트 구간에 포함된 CPU 최대 샘플의 실제 기록 프레임을 엽니다. 최대값이 같으면 가장 이른 프레임을 고릅니다. 제목에 목록에 해당하는 실제 시각을 표시하고, 프로세스 표시값은 그 프레임의 평균이므로 순간 최대의 원인을 단정할 수 없습니다. 일반 차트 지점은 그 구간의 첫 실제 기록 프레임을 표시해, 서로 멀리 떨어진 두 프레임의 평균 시각으로 빈 구간을 조회하는 일을 피합니다. 이 선택은 기록 파일을 다시 쓰지 않습니다.
- **특정 시점 보기**: 포인터를 곡선으로 옮기면 왼쪽에 그 순간의 값이 표시됩니다. 클릭하면 그 시점이 선택되고 아래에 그때 가장 사용량이 많았던 프로세스가 나열됩니다. 선택한 뒤 곡선에서 ← → 로 앞뒤로 옮기고(Shift를 함께 누르면 한 번에 더 많이 움직입니다) CPU 최대 프레임을 선택했을 때는 최대값이 속한 구간에서부터 움직입니다. Esc나 페이지 막대의 “최신 데이터로 돌아가기”로 선택을 해제합니다. 시점을 선택한 뒤에도 차트는 시간에 따라 앞으로 나아가고 그 시점이 차트를 벗어나면 선택이 자동으로 해제됩니다.
- **범위 전환**: 전환하면 항상 새 범위의 지금까지 구간을 표시합니다. 선택한 시점이 아직 새 범위 안에 있으면 선택을 유지하고 아래 프로세스 목록도 그대로이며, 그렇지 않으면 선택을 해제하고 표시값과 프로세스 목록이 최신 데이터로 돌아갑니다. 더 이른 구간을 보려면 더 긴 범위를 골라야 합니다.
- **배터리 데이터 누락**: 장치가 배터리 충전 수준을 아직 보고하지 않은 구간의 배터리 곡선은 비고 표시값은 “데이터 없음”으로 표시합니다. 실제 충전 수준이 0%일 때는 0%로 표시합니다.
- **프로세스로 이동**: 목록의 프로세스를 두 번 클릭하면 PID, 이름, 기록된 생성 시간이 현재 실행 인스턴스와 일치할 때만 프로세스 페이지로 이동하고, 이동할 때 한 번 더 확인합니다. 이전 기록에 생성 시간이 없으면 기록 표시값을 유지하고 이동을 제공하지 않습니다. 생성 시간은 그 프레임의 5초 기록 창 안에 있을 수 있고 창보다 늦을 수는 없습니다.

프로세스별 네트워크 트래픽은 로컬 수집이나 권한 있는 서비스 수집을 쓸 수 있을 때 기록합니다. 기록은 `%LOCALAPPDATA%\dev.goodgood.taskmanager\history`에 저장되고 하루에 파일 하나이며 7일 동안 보관하고, 하루를 연속으로 실행하면 약 8 MB입니다. “설정 → 데이터 및 기록”에서 기록을 끄거나, 차지하는 공간을 확인하거나, 기록을 모두 지울 수 있습니다. [설정](settings.md#데이터-및-기록)을 참고합니다.

현재 v2와 v3 기록을 읽습니다. 새로 만드는 v3 파일은 프로세스 생성 시간을 저장하고, 이미 있는 당일 v2 파일은 원래 형식으로 계속 덧붙이며 다음 날이 되어야 v3 파일을 만들어 기존 기록을 덮어쓰지 않습니다. v2 기록의 프로세스 생성 시간은 알 수 없습니다. 이전 버전 GoodGood은 v3 파일을 읽지 못하므로 버전을 낮추기 전에 기록 폴더를 백업해야 하고, 이전 버전 기록기는 지원하지 않는 형식의 당일 파일을 다시 만들 수 있습니다. 더 이른 형식은 해당 이전 버전으로 백업을 읽어야 합니다.

### 프로그램 관찰과 실행 인스턴스

새 단일 인스턴스 관찰 파일은 JSONL v2를 쓰고, 조회할 수 있을 때 같은 검증된 프로세스 핸들로 얻은 로컬 이미지 경로와 표시 경로를 프로그램 신원으로 저장하며 인터페이스가 넘긴 이름은 레이블로만 씁니다. 기존 v1 기록은 계속 읽고 프로그램 경로는 알 수 없는 상태로 두며 같은 이름의 프로세스로 채우지도, 기존 파일을 다시 쓰지도 않습니다. 이 메타데이터는 로컬 관찰 파일에 저장되고, 한 번의 실행에 대한 관찰은 계속 PID, 생성 시간, 확보한 핸들로 판단합니다.

프로세스 목록에서 실행 인스턴스 하나를 선택하고 자세히 창에서 “이 인스턴스 관찰”이나 “앞으로의 실행 관찰”을 고릅니다. 기록은 “기록” 페이지 위쪽에 표시되고, 그 프로세스가 시스템 기록의 사용량 순위에 들지 못해도 전용 작업 집합과 전용 커밋을 기록합니다. 작업 집합은 현재 상주한 전용 메모리를, 커밋은 프로그램이 받은 전용 커밋 메모리를 뜻하며 작업 집합이 늘었다는 것만으로 메모리 누수를 증명하지는 않습니다.

“이 인스턴스 관찰”은 PID와 생성 시간으로 확인한 인스턴스 하나에만 적용되고 다시 시작해도 따라가지 않습니다. 기록 하나는 최대 1시간, 720개 지점, 1 MiB이며 어느 한도에 먼저 이르면 멈추고, 기록 디렉터리의 `process-watch.jsonl`에 저장합니다.

“앞으로의 실행 관찰”은 선택한 인스턴스의 검증된 핸들에서 로컬 이미지 경로를 읽어 현재와 이후에 시작하는 같은 경로의 프로그램을 기록합니다. 인터페이스 이름은 레이블로만 쓰고 프로그램 신원을 판단하는 데 쓰지 않습니다. 다른 디렉터리의 같은 이름 EXE는 합치지 않고, 경로 비교에서 대소문자가 다른 디렉터리를 구분하며, 경로 별칭을 합치는 것을 보장하지 않고 파일 서명이나 해시로 바이너리 버전을 정의하지도 않습니다. 확인한 인스턴스마다 읽기 전용 조회 핸들을 종료할 때까지 하나씩 유지하고, 인스턴스별 곡선은 PID와 생성 시간으로 나눕니다. 새 인스턴스의 신원을 아직 읽을 수 없으면 확인하지 못한 같은 이름 인스턴스 수를 표시하고 1분마다 다시 시도하며 기존 인스턴스 데이터에 잇지 않습니다. 프로그램이 모두 종료되면 이후 실행, 직접 중지, 동시 관찰 512개 인스턴스 한도에 이를 때까지 기다립니다.

이후 실행 기록은 별도 파일 `program-watch.v1.bin`을 쓰고 최대 7일, 131072개 지점, 9 MiB를 보관합니다. 먼저 이르는 한도가 가장 오래된 기록을 정리하고, 기간이 지난 기록 슬롯은 비웁니다. 중지한 뒤의 데이터도 같은 방침으로 정리하고, GoodGood이 종료된 동안 만료된 기록은 다시 열 때 정리합니다. 기록에는 시퀀스와 무결성 검사가 붙어 손상된 기록을 표시값으로 쓰지 않습니다. 인스턴스 목록은 페이지마다 최대 256개이고 곡선은 페이지마다 저장한 지점 최대 1000개와 빈 구간 표시를 담으며, 이전 인스턴스와 이전 지점을 따로 넘겨 보거나 최신 기록으로 돌아갈 수 있습니다.

두 관찰은 보통 5초마다 지점 하나를 보관합니다. 백그라운드 샘플링이 느리거나 표시값이 유효하지 않거나 샘플링이 끊기면 빈 구간을 표시하고 0으로 채우지 않습니다. 새로 시작한 인스턴스는 시작 전의 샘플 빈 구간을 물려받지 않습니다. 종료 여부는 같은 프로세스 핸들로 확인합니다. 시스템 시계가 되돌아가면 관찰을 중단하고 역순 시각을 곡선에 잇지 않습니다. 관찰 파일은 사용량 순위 파일과 별개이므로 순위 기록을 꺼도 직접 선택한 관찰은 멈추지 않습니다.

“기록 중지”는 이미 있는 데이터를 보관하고 “기록 삭제”는 관찰을 멈추고 그 파일을 지웁니다. 다른 기록을 시작하기 전에 기존 기록을 지워야 합니다. GoodGood을 종료하거나 다시 시작해도 이전 관찰이 자동으로 이어지지 않고, 남아 있는 미완료 기록은 중단으로 표시됩니다. 알 수 없는 형식이거나 손상된 기록도 지울 수 있습니다. 설정의 기록 사용량에는 관찰 파일이 포함되고 “기록 지우기”는 관찰도 함께 멈추고 지웁니다.

## 파일을 사용하는 항목

“추가 작업” 메뉴에서 “파일을 사용하는 프로세스 찾기…”를 고르거나 파일이나 폴더를 창으로 끌어다 놓으면 사용 중인 프로세스를 조회합니다. 결과는 두 원본을 합칩니다. 다시 시작 관리자는 파일 참조와 로드된 모듈을 찾고, 핸들 스캔은 열린 파일, 디렉터리, 그 하위 항목을 보충하며 선택한 폴더를 현재 디렉터리로 쓰는 명령줄 프로세스도 포함합니다. 파일 ID로 하드 링크를 통해 같은 파일을 연 경우를 식별합니다.

대화 상자가 열린 뒤에도 파일이나 폴더를 대화 상자로 끌어다 놓아 조회 대상을 바꿀 수 있습니다. 관리자 창에도 표준 권한의 파일 관리자에서 파일을 끌어다 놓을 수 있습니다.

사용 중인 프로세스가 현재 바탕 화면의 탐색기이면 작업 단추가 “다시 시작”으로 표시되고, 확인하면 바탕 화면과 작업 표시줄을 되살린 뒤 파일 사용 여부를 다시 확인합니다. 다른 프로세스는 여전히 “작업 끝내기”로 사용을 풀 수 있습니다.

쓸 수 있고 권한이 부여된 권한 있는 서비스가 있으면 핸들 조회를 서비스에 맡기고, 그렇지 않으면 현재 계정의 권한으로 조회하며 표준 권한으로도 자신의 프로세스는 상당수 찾습니다. 각 결과는 일치한 경로와 핸들 수를 표시하고 중복된 원본은 PID와 생성 시간으로 합칩니다. “작업 끝내기”는 확인을 거치고 같은 프로세스 인스턴스를 다시 확인해 PID 재사용으로 다른 프로세스를 끝내는 일을 피합니다.

결과는 접근할 수 없는 프로세스, 건너뛴 핸들, 시간 초과된 조회도 나열합니다. “찾지 못함”은 이번 조회 범위에 일치하는 항목이 없다는 뜻입니다. 조회가 멈추면 이미 찾은 결과를 유지하고, 시간이나 수량 한도에 이르면 부분 결과를 돌려줍니다. 공유 삭제를 허용한 핸들도 나열될 수 있습니다.

핸들 스캔은 로컬 디스크의 절대 경로를 씁니다. 기호 링크, 디렉터리 연결점, 네트워크 드라이브, SUBST 경로는 다시 시작 관리자의 조회 결과를 유지하므로 실제 대상을 지정해 핸들을 보충 조회합니다. 보호된 프로세스와 이미 닫힌 핸들의 매핑은 놓칠 수 있습니다. [알려진 문제](../known-issues.md)를 참고합니다.

## 정보

정보 페이지는 탐색 창에서 “설정” 다음에 있고 버전, 현재 권한, 라이선스를 표시하며 새로운 기능, 종료, 시작 가이드 다시 열기 진입점을 제공합니다. 정보 페이지나 가이드 첫 단계를 열면 10 × 10 점 격자가 먼저 알파벳 A를 만들고 이어서 최근 10회 CPU 사용량의 점 격자 그림으로 바뀝니다. 열마다 샘플 하나에 해당하고 그때의 사용량만큼 아래에서 위로 점을 켜며 맨 위 점이 가장 밝고 가장 오른쪽 열이 최신 샘플입니다. 사용량이 80%에 이른 열은 호박색입니다. 샘플마다 각 열이 한 칸씩 왼쪽으로 밀리고 점의 위치는 그대로입니다. “인터페이스 애니메이션”을 끄면 점 격자 그림을 바로 표시합니다. 버전 번호는 배포판과 같고, 배포하지 않은 커밋으로 빌드한 테스트 버전은 뒤에 커밋 수와 커밋의 짧은 해시를 붙이며(예: `0.3.4+583.g4c638d7`) 사용한 빌드를 확인하기 쉽게 합니다. 버전 정보 아래 두 카드는 각각 [GoodGood 웹사이트](https://goodgoodtask.com/)와 [GitHub 저장소](https://github.com/acc0mplish/GoodGood)로 연결됩니다. 카드를 클릭하면 해당 홈페이지가 열리고 카드 아래의 단추가 자주 쓰는 페이지를 바로 엽니다. 웹사이트는 “다운로드”, “사용자 가이드”, “변경 로그”이고 GitHub는 “문제 보고”(문제 유형을 고르는 페이지), “토론”, “릴리스”입니다. 다운로드와 변경 로그 페이지는 인터페이스 언어에 맞춰 열리고 사용자 가이드는 한국어로 제공됩니다. “타사 구성 요소”는 오픈 소스 구성 요소와 라이선스를 나열합니다.

“로그 폴더 열기”를 클릭하면 `%LOCALAPPDATA%\dev.goodgood.taskmanager\logs\diagnostics`를 볼 수 있습니다. `goodgood.log`는 시스템 버전, 렌더러, 센서와 권한 있는 기능 상태, 실행 중인 프로그램의 SHA-256을 기록하므로 같은 버전 번호의 다른 빌드를 구분할 수 있습니다. 실패 기록에는 구체적인 단계, 시스템 오류 코드, 관련 경로가 들어 있습니다. 공개적으로 로그를 올리기 전에 이 경로에 들어 있는 사용자 디렉터리 이름을 확인합니다.

“진단 정보 복사”를 클릭하면 이슈에 붙여넣기 좋은 요약을 복사합니다. GoodGood 전체 버전, Windows 버전, 빌드 및 설치 유형, 현재 권한, 읽은 권한 있는 서비스와 작업 관리자 대체 상태, 커널 센서 설정과 스냅숏 상태, 스냅숏 시각(UTC), CPU와 메모리, 그래픽 카드와 드라이버, 디스크 모델과 버스, 현재 디스플레이 해상도, 창 클라이언트 영역 크기, 시스템과 인터페이스 배율, 글꼴 크기, 인터페이스 언어, 새로 고침 간격이 들어갑니다. 요약은 이미 있는 스냅숏과 설정을 재사용하고 없는 정보는 알 수 없음으로 표시하며, 샘플링을 일시 중지한 동안에는 원래 스냅숏 시각을 유지합니다. 요약은 위 항목으로만 만들고 프로세스 목록, 명령줄, 계정, 장치 일련 번호, 파일 경로, 네트워크 주소는 넣지 않습니다. 결함 보고나 표시값 이상 보고의 “진단 정보” 항목에 붙여넣고 문제가 생기기 전후의 진단 로그를 함께 첨부할 수 있습니다.

시간 표시에는 로컬 날짜, 밀리초, UTC 오프셋이 들어가고 시간대 조회에 실패하면 `+00:00`을 씁니다. `goodgood.log`는 1 MiB를 넘으면 교체하며 최근 세 개의 보관본을 남깁니다. 작업 관리자 대체 시작 프로그램은 `taskmgr.log`를 따로 씁니다.

## 터치 조작

Windows 터치 스크린은 단추 누르기, 목록 항목 선택, 두 번 탭으로 프로세스 트리 펼치기와 접기를 지원합니다. 목록이나 페이지 내용 위에서 손가락을 밀면 세로나 가로로 스크롤되고, 빠르게 밀면 관성 스크롤이 이어지며 다시 터치하면 멈춥니다.

프로세스, 표 머리글, 장치, 차트를 길게 누르면 해당 상황에 맞는 메뉴가 열리고, 목록 메뉴는 손가락을 눌렀을 때의 항목을 대상으로 합니다. 메뉴 항목을 탭하면 실행되고 메뉴 바깥을 탭하면 닫힙니다. 스크롤 막대 손잡이는 바로 끌 수 있습니다. 입력란은 탭으로 위치를 잡고 길게 눌러 글자를 선택하며, 포그라운드 창에서 Windows 터치 키보드 표시를 요청합니다. 인터페이스 크기는 [설정 → 언어 및 모양](settings.md)에서 조정합니다.

## 키보드 조작

| 조작 | 키 |
|---|---|
| 페이지 전환 | Ctrl+1 … Ctrl+9 |
| 프로세스 검색 | Ctrl+F 또는 /, 프로세스 페이지에서는 글자나 숫자를 바로 입력 |
| 새 작업 실행 | Ctrl+N(글자를 입력하는 중에는 동작하지 않음) |
| 새로 고침 잠시 일시 중지 | 프로세스 페이지, 성능 페이지에서 Ctrl을 누르고 있다가 놓으면 다시 시작. 직접 일시 중지한 상태는 유지 |
| 선택 | ↑ ↓ |
| 접기 / 펼치기 | ← →, 그룹 제목에서는 Enter나 스페이스도 사용 |
| 세부 정보 열기 | Enter |
| 프로세스 끝내기 | 프로세스 페이지에서 Alt+E, 목록에 포커스가 있으면 Delete도 사용(Shift+Delete는 확인을 건너뜀) |
| 창 표시 / 숨기기(전역) | Ctrl+Alt+Esc, 설정에서 변경 가능 |

그룹 제목의 접힌 상태는 다시 시작한 뒤에도 유지되고, 프로세스 목록에서 ←를 누르면 최상위 항목에서 속한 그룹의 제목으로 옮겨 갑니다. 검색하는 동안 각 그룹은 일치하는 항목을 모두 표시하고 접을 수 없으며, 검색을 지우면 원래 접힌 상태로 돌아갑니다. 목록이 필터링된 상태에서는 테두리, 표 머리글, 검색 상자를 강조색으로 표시하고 이름 열 머리글의 수 앞에 깔때기 아이콘을 표시합니다(포인터를 올리면 설명 표시). 필터링을 시작할 때 테두리가 한 번 빛나며 “인터페이스 애니메이션” 설정을 따릅니다. 프로세스로 이동할 때(예: 서비스 페이지나 연결 페이지에서)는 해당 그룹이 함께 펼쳐집니다.

각 범주와 사용자 그룹은 색으로 구분합니다. “앱”은 파랑, “백그라운드 프로세스”는 로즈 레드, “Windows 프로세스”와 “시스템” 그룹은 슬레이트 그레이, 다른 사용자 그룹은 차례로 청록, 연두, 청보라입니다. 그룹 제목에는 같은 색의 옅은 배경색이 깔리고 범주 제목 앞에는 같은 색 블록이 붙으며 수 배지와 제목 오른쪽의 가는 선도 그 색을 씁니다. 사용자 제목의 아바타도 그 색을 씁니다. 목록을 스크롤할 때 현재 그룹의 제목이 표 머리글 아래에 고정되어 그 그룹의 수와 합계를 표시하고, 다음 그룹의 제목이 다가오면 밀려납니다. 사용자별로 그룹화하면 사용자 제목과 범주 제목이 위아래로 겹쳐 놓입니다. 고정된 제목을 클릭해도 그 그룹을 접을 수 있습니다. 목록 스크롤 막대 바깥에는 각 그룹의 위치와 길이를 해당 색의 가는 선으로 표시하고 목록 위쪽에 있는 그룹의 색을 더 진하게 표시합니다. 스크롤할 때는 스크롤 막대 손잡이 옆에 현재 그룹과 위치를 표시하고(예: “Windows 프로세스 23 / 56”, 사용자별로 그룹화하면 “사용자 이름 · 범주”) 스크롤을 멈추고 1초 뒤에 사라집니다.

프로세스 페이지의 목록, 단추, 빈 영역에 포커스가 있을 때 글자나 숫자를 바로 입력하면 검색 상자에 글자가 덧붙습니다. ↓를 누르면 목록으로 돌아가고 Esc를 누르면 검색을 지우고 원래 위치로 돌아갑니다. 한국어 입력기를 쓰는 경우 첫 키부터 조합이 시작되고 글자를 확정한 뒤에야 목록을 필터링하며, 조합 중의 Enter, 방향 키, Esc는 입력기가 처리합니다.

Alt+E는 상황에 맞는 메뉴와 같은 확인과 권한 처리를 거치고 앱 그룹을 선택했으면 그 그룹에 적용되며, 입력란, 팝업, 메뉴가 열려 있을 때는 동작하지 않습니다. 전체 키 설명은 “설정 → 키보드 바로 가기 → 바로 가기 보기”에 있습니다.

## 권한

[설정 → 권한](settings.md#권한)이나 첫 실행 가이드에서 “관리자 권한으로 실행”을 켤 수 있습니다. 권한을 한 번 부여하면 모든 시작 진입점이 같은 정책을 따르고, 로그인 시 시작은 숨김 상태를 유지하며 상주 바로 가기는 현재 관리자 인스턴스를 표시합니다. 이 모드는 기본으로 꺼져 있고 권한 있는 서비스와 따로 관리합니다.

다른 관리자 계정으로 시작하면 설정, 기록, 로그가 그 관리자 계정에 저장되고 프로세스 보기와 열 너비 같은 인터페이스 환경 설정은 따로 저장됩니다.

관리자 권한으로 시작할 때 Windows 탐색기가 이미 종료되어 있으면 GoodGood이 바탕 화면을 먼저 되살릴지 묻습니다. 확인하면 원래 바탕 화면 계정의 표준 권한으로 탐색기를 열고 이어서 인터페이스를 시작하며, “아니요”를 고르면 이번 시작을 취소합니다.

표준 권한으로도 일반 프로세스의 경로와 리소스 사용량을 읽을 수 있고 보호된 프로세스는 일부 정보가 없을 수 있습니다. 서비스가 도울 수 있는 작업은 [설정 → 권한](settings.md#권한)을 참고합니다. 프로세스 세부 정보와 모든 사용자 시작 항목의 변경은 인터페이스 프로세스 자체의 권한을 씁니다. 상태 표시줄은 “관리자”, “권한 있는 서비스”, “표준 사용자” 중 하나를 표시합니다.
