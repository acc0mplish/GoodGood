# 설정

설정 페이지 왼쪽에는 각 그룹의 전체 이름이 나열되고 너비는 인터페이스 언어와 글꼴 크기에 맞춰 조정됩니다. 목록은 스크롤에 따라 현재 위치를 표시하고 그룹을 클릭하면 바로 이동합니다. 창이 좁으면 설정 내용이 사용 가능한 너비를 차지합니다.

## 언어 및 모양

“인터페이스 배율”은 글자, 아이콘, 컨트롤의 전체 크기를 80%–150% 범위에서 조정하며 기본값은 100%입니다. “글꼴 크기”는 기본 글꼴 크기를 11–20 px로 정하며 기본값은 13 px이고 제목과 보조 글자가 비례해 바뀝니다. 두 항목은 따로 설정하고 함께 쓸 수 있으며 즉시 적용되고 자동으로 저장되며 각각 초기화할 수 있습니다. 값을 입력한 뒤 Enter를 누르거나 ↑ / ↓ 키로 단계별로 조정할 수 있고, 포인터를 올리면 입력 상자 오른쪽에 위아래 화살표가 표시되어 한 번 클릭할 때 한 단계씩, 누르고 있으면 연속으로 조정하고 놓으면 적용됩니다.

프로세스, 서비스, 시작 프로그램, 연결 목록은 정렬한 열과 방향을 각각 기억합니다. 보기, 자주 쓰는 필터, 탐색 창, 새로 고침 간격 같은 환경 설정도 설정과 함께 저장됩니다.

인터페이스는 한국어, 영어, 스페인어, 독일어, 일본어, 프랑스어, 러시아어 일곱 언어를 지원하고 기본값은 “Windows와 동일”입니다. Windows 표시 언어를 먼저 쓰고, 다음으로 사용자 기본 언어 목록에서 지원하는 언어를 고르며, 마지막으로 영어를 씁니다. 같은 언어의 지역 변형은 번역을 공유합니다(예: 멕시코 스페인어, 캐나다 프랑스어). 전환하면 즉시 적용되고 알림 영역의 카드, 패널, 메뉴, 창 제목, 오류 메시지도 함께 바뀌며, 선택 항목에는 항상 각 언어의 원래 이름을 표시합니다.

권한 있는 서비스와 권한 상승 유지 관리 도우미는 Windows 표시 언어를 씁니다. 설치 관리자와 제거 관리자도 위 일곱 언어를 제공합니다. Windows 파일 선택 상자, 관리자 권한 부여 상자, 다른 앱이 제공하는 프로세스 이름과 서비스 설명은 각자의 원래 언어를 유지합니다.

숫자와 전체 날짜는 Windows 지역 형식을 쓰고 시간대는 시스템 설정을 쓰며 인터페이스 언어와 무관합니다. 실행 중에 숫자 지역 형식을 바꾸면 GoodGood을 다시 시작한 뒤 적용됩니다. 글꼴 크기와 배율 입력은 지역 소수 기호, 마침표, 전각 숫자를 받아들이고, 입력할 때는 입력기 조합을 유지하며 확정한 뒤 값을 확인합니다. 기록 곡선의 간단한 날짜 레이블은 인터페이스 언어에 맞춰 표시되고 시간 축은 24시간제를 씁니다. 일광 절약 시간이 바뀔 때 눈금은 각 시점의 현지 시간으로 배열하고, 선택하거나 포인터를 올리면 UTC 오프셋을 표시해 시계가 되돌아갈 때 겹치는 시점을 구분할 수 있습니다.

“테마”는 기본으로 Windows “개인 설정 → 색”의 앱 모드를 따릅니다. “밝게”나 “어둡게”를 직접 고르면 창 내용, 제목 표시줄, 배경의 테마가 고정되고 알림 영역의 마우스 올림 카드와 빠른 패널도 함께 바뀝니다. 알림 영역 메뉴, 시스템 대화 상자, 설치 관리자는 Windows 테마를 씁니다.

“탐색 위치”는 “위쪽”(기본값) 또는 “측면”을 고를 수 있습니다. 위쪽 탐색은 제목 표시줄 아래에 탭으로 나열되고 페이지를 전환하면 새 페이지가 오른쪽이나 왼쪽에서(탭 순서에 따름) 밀려 들어옵니다. 측면 탐색은 창 왼쪽에 있고 새 페이지가 아래나 위에서 밀려 들어오며, 기본으로 아이콘만 표시하고 왼쪽 위의 ☰ 단추로 펼쳐 페이지 이름을 표시합니다. 펼친 뒤 오른쪽 가장자리를 끌어 너비를 조정하고 두 번 클릭해 기본값으로 되돌립니다. 첫 실행 가이드에서도 고를 수 있고 설정은 이 PC에 저장되어 다시 시작한 뒤에도 유지됩니다.

Windows 11 22H2 이상은 기본으로 Mica 배경을 유지하고, Windows 11 21H2와 Windows 10은 자동으로 단색 배경을 씁니다. 곡선이 실제 화면에서 캡처와 다른 밝기로 보이면 알림 영역에서 GoodGood을 종료한 뒤 `goodgood.exe --opaque-window`로 시작합니다. 이 모드는 단색 창 배경을 쓰고 곡선 색상과 애니메이션 설정은 유지합니다.

“언어 및 모양”의 “시스템 프로세스 숨기기 규칙”은 프로세스 페이지와 연결 페이지가 공유하는 항상 표시, 추가로 숨기기 목록을 편집합니다. 두 페이지의 페이지 막대는 각각 아이콘 스위치를 제공하고 기본값은 꺼짐입니다. 규칙의 일치와 연결 귀속 설명은 [인터페이스와 조작](README.md#페이지)을 참고합니다.

같은 영역의 “사용자별로 프로세스 그룹화”는 자동(기본값), 항상 그룹화, 그룹화 안 함을 고를 수 있습니다. 자동 모드는 여러 사용자가 동시에 로그인한 동안에만 그룹화하고 연결이 끊겼지만 로그오프하지 않은 세션도 포함하며, 한 사용자만 로그인했으면 목록은 그룹화하지 않은 상태를 유지합니다. 그룹의 귀속과 그룹 안의 동작은 [인터페이스와 조작](README.md#페이지)을 참고합니다.

“마우스를 올린 동안 정렬 일시 중지”는 기본으로 켜져 있습니다. 포인터가 프로세스 목록 위에 있는 동안 행 위치가 유지되고 표시값은 계속 갱신되며, 목록을 벗어나면 다시 정렬합니다. 끄면 목록이 표시값에 따라 실시간으로 정렬되고, 상황에 맞는 메뉴나 대화 상자가 열려 있는 동안에는 여전히 행 위치를 유지합니다. 표시 방식은 [인터페이스와 조작](README.md#페이지)을 참고합니다.

같은 영역의 “프로세스 개요 영역”은 자동, 항상 표시, 숨김을 고를 수 있습니다. 자동 모드는 개요 영역과 가상의 프로세스 10행만큼의 고정 높이 예산을 확보하고 창 공간이 부족할 때만 접으며, 실제 행 수와 접힘, 필터 상태는 판정에 영향을 주지 않습니다. 전환은 인터페이스 애니메이션 설정을 따릅니다.

## 시작 프로그램 및 알림 영역

주 창은 마지막으로 사용한 상태를 기억합니다. 최대화한 뒤 종료하거나 알림 영역으로 닫으면 다시 열 때 여전히 최대화되어 있고, 일반 창으로 복원한 뒤에는 마지막 위치와 크기를 이어 씁니다. 최소화한 뒤 종료하면 다음 시작에서 최소화하기 전 상태로 돌아옵니다. 알림 영역 모드로 시작하면 창이 숨겨진 채로 있고 처음 열 때 복원합니다. 원래 디스플레이의 연결이 끊기면 Windows가 창을 사용 가능한 화면으로 옮깁니다.

| 설정 | 설명 |
|---|---|
| Windows에 로그인할 때 시작 | 로그인 후 `--hidden`으로 시작해 알림 영역에서 실행합니다. 알림 영역 아이콘을 클릭하거나 전역 바로 가기를 눌러 창을 열 수 있습니다. 작업 관리자 대체 진입점에서 이 항목을 켜면 GoodGood이 설치된 프로그램을 찾으며, 찾지 못한다는 안내가 나오면 설치 위치에서 시작한 뒤 다시 켭니다. |
| 기본 페이지 | GoodGood을 시작한 뒤 창을 처음 열 때 표시되는 페이지로 프로세스(기본값), 성능, 서비스, 시작 프로그램, 연결, 기록 중에서 고를 수 있으며 마지막으로 종료할 때 머문 페이지와 무관합니다. 알림 영역에서 조용히 시작했거나 작업 관리자 대체로 시작한 경우에도 창을 처음 열면 선택한 페이지가 열립니다. 앱 내 업데이트를 마치고 자동으로 다시 시작하면 업데이트 전 페이지로 돌아갑니다. |
| 알림 영역과 구성 요소 | 알림 영역 아이콘, 마우스 올림 카드, 알림 영역 아이콘을 마우스 오른쪽 단추로 클릭할 때의 동작, 닫을 때 알림 영역에 유지, 알림 영역에서 다시 열기, 알림 영역에서의 새로 고침 빈도는 [구성 요소 페이지](resident-mode.md#구성-요소-페이지)에 있으며 “구성 요소 열기”를 클릭해 이동합니다. |

## 키보드 바로 가기

“키보드 바로 가기”의 “바로 가기 보기”는 현재 설정한 전역 바로 가기, 페이지 전환, 일시 중지, 프로세스 작업, 기록 곡선 조작을 담은 전체 키 설명을 엽니다. “목록에 포커스가 있을 때” 같은 묶음을 펼치면 팝업이 아래로 늘어나고 위쪽 가장자리는 그대로 있으며, 창에 들어갈 수 있는 높이를 넘으면 팝업 안에서 스크롤합니다. 팝업은 Esc로 닫고 닫은 뒤 포커스는 연 단추로 돌아갑니다.

GoodGood을 표시하거나 숨기는 전역 바로 가기는 기본값 Ctrl+Alt+Esc이고 대부분의 프로그램에서 동작합니다.

- 오른쪽 스위치로 바로 가기를 끌 수 있고, 끄면 현재 조합을 유지하며 다시 켜면 되살아납니다.
- “변경”을 클릭하고 보조키를 누른 채 주 키를 눌렀다 놓으면 저장되고 켜집니다. 기록 영역에 현재 조합을 표시합니다. Esc를 누르거나 “취소”를 클릭하면 기록을 마치고, Backspace만 누르면 바로 가기를 끕니다. “기본값 복원”은 Ctrl+Alt+Esc로 되돌립니다. 창을 전환하거나 숨기거나 15초 동안 입력이 없으면 기록이 끝나고 기존 설정을 유지합니다.
- 조합을 다른 프로그램이 차지하고 있으면 카드 아래에 이유와 “다시 시도” 단추가 표시됩니다. 차지한 프로그램이 종료된 뒤 GoodGood 창을 다시 표시할 때도 자동으로 다시 시도합니다.
- 조합에는 Ctrl, Alt, Win 중 하나와 일반 키가 필요하며 F13–F24는 단독으로 쓸 수 있고 Shift+F1–F9와 Shift+F11은 확인을 거쳐야 저장됩니다. 이는 Windows 전역 바로 가기의 규칙입니다. 보조키는 좌우를 구분하지 않고(왼쪽 Ctrl과 오른쪽 Ctrl이 같음) 보조키로만 된 조합(예: 왼쪽 Ctrl+오른쪽 Ctrl+왼쪽 Alt)은 쓸 수 없으며, 일반 키는 하나만 쓸 수 있어 두 일반 키(예: 숫자 키패드의 + 와 -)는 조합할 수 없습니다. 보조키를 먼저 누른 뒤 일반 키를 눌러야 합니다.
- 보조키는 Ctrl, Alt, Shift, Win으로 일치를 판단하고 좌우를 같은 키로 봅니다. Caps Lock, Num Lock, Scroll Lock은 잠금 키입니다.
- 시스템 예약 조합과 Ctrl+C, Ctrl+V 같은 자주 쓰는 편집 키는 기록할 때 충돌을 알립니다. Ctrl+Shift+Esc의 설정 진입점은 “권한 → 작업 관리자 대체”에 있습니다. Ctrl이 붙은 Pause는 Windows가 Break로 인식하므로 다른 주 키를 고릅니다.
- 주 키와 입력할 수 있는 키 이름은 현재 Windows 키보드 배열로 매핑되고 키릴 문자와 AZERTY, QWERTZ, 일본어 배열의 기호 키를 지원하며, 인터페이스 언어를 바꿔도 저장한 조합을 유지합니다. AltGr 문자 입력과 Ctrl+Alt 조합은 Windows 매핑을 공유할 수 있으므로 Ctrl+Shift 같은 조합을 골라 충돌을 줄입니다. 일부 자주 쓰는 조합은 저장 전에 확인을 요청합니다.

배경 실측과 절충은 [전역 바로 가기](../design/hotkey.md)를 참고합니다.

## 권한

“관리자 권한으로 실행”은 배포 빌드에 적용됩니다.

“관리자 권한으로 실행”은 기본으로 꺼져 있습니다. “관리자 권한으로 실행 허용”을 켜고 Windows 권한 부여를 한 번 마치면 로그인 시 시작, 일반 바로 가기, 고정한 아이콘, Ctrl+Shift+Esc, 작업 표시줄의 “작업 관리자” 진입점이 모두 관리자 실행 정책을 따릅니다. 뒤의 두 진입점은 시스템 작업 관리자 대체를 먼저 켜야 합니다. 상주 바로 가기는 현재 관리자 인스턴스를 표시하고 실행 중이 아닐 때 전역으로 시작하는 기능은 제공하지 않습니다.

카드는 권한 부여 상태와 현재 프로세스 권한을 따로 표시합니다. 권한을 전환하면 GoodGood이 다시 시작되고 설정과 기록은 유지되며, 첫 실행 가이드에서는 마치거나 건너뛴 뒤에 전환합니다. 권한 부여를 취소해도 로그인 시 시작 환경 설정은 유지됩니다. UAC를 끈 관리자 계정에서는 프로세스가 그 계정의 기본 권한을 씁니다.

이 모드는 현재 Windows 계정이 관리자 그룹에 속해야 합니다. 표준 계정은 권한 있는 서비스로 다음 작업을 수행할 수 있습니다. 관리자 실행 권한 부여가 무효가 되면 GoodGood이 일반 권한으로 열리고 여기에서 복구 진입점을 제공합니다.

설치한 뒤 Program Files나 GoodGood 실행 디렉터리의 소유자와 쓰기 권한을 바꾸면 관리자 실행이나 권한 있는 서비스가 동작하지 않을 수 있습니다. 이때도 관리자 실행 권한 부여를 취소하고, Windows 작업 관리자를 복원하고, 서비스를 제거할 수 있습니다. 취소한 뒤 일반 권한 창이 시작되지 않으면 현재 창을 남겨 두고 종료한 뒤 다시 열도록 안내합니다. 관련 기능을 다시 켜려면 관리자가 해당 디렉터리의 보안 권한을 복구해야 하며, GoodGood은 시스템 디렉터리 권한을 스스로 바꾸지 않습니다.

권한 있는 서비스는 직접 설치해야 합니다. “설치 및 사용”을 클릭하고 권한 범위를 읽은 뒤 Windows 관리자 확인을 마치면 백그라운드 서비스가 다음 작업을 수행할 수 있습니다.

- 프로세스 또는 프로세스 트리 끝내기(시스템 중요 프로세스는 계속 차단).
- 프로세스 우선 순위, I/O 우선 순위, 메모리 우선 순위 설정, 효율성 모드 켜기와 끄기, 프로세스 일시 중단과 다시 시작.
- 자동 규칙의 우선 순위와 효율성 모드 조작.
- 프로세스별 네트워크 트래픽 수집(로컬 수집을 쓸 수 없을 때).
- 프로세스별 디스크 읽기·쓰기 수집(시스템이 일반 프로세스 조회로 카운트를 제공하지 않을 때).
- 디스크 세부 정보의 ATA／SATA, USB-SAT, SCSI／SAS 신원과 SMART 상태 정보 읽기 전용 조회.
- 핸들로 파일과 디렉터리 사용 여부 조회(프로세스의 현재 디렉터리 포함).
- Windows 서비스 시작, 중지, 다시 시작과 시작 유형 변경.
- IPv4 TCP 연결 끊기.

권한 범위는 컴퓨터 전체입니다. 현재 계정에서 실행되는 일반 데스크톱 프로그램이 모두 서비스를 호출해 위 작업을 수행할 수 있고, 다른 사용자의 프로세스 관리, Windows 서비스 변경, 프로세스 핸들과 리소스 카운트 조회도 포함됩니다. 시스템 중요 프로세스는 따로 보호되고 서비스는 제한 토큰과 AppContainer 호출을 거부합니다. 신뢰하는 계정에만 설치합니다.

서비스는 Windows와 함께 시작하고 한 번 설치하면 계정 하나에만 권한이 부여됩니다. 다른 계정은 관리자 권한으로 먼저 제거한 뒤 다시 설치해야 합니다.

서비스가 중지되어 있으면 “서비스 시작”을 클릭합니다. 프로토콜 버전이 호환되지 않으면 “서비스 업데이트”를 클릭해 보호된 디렉터리의 서비스 프로그램을 바꿉니다. 연결이 돌아오기 전에는 직접 조작과 규칙이 GoodGood 자체 권한으로 실행되고 서비스에 의존하는 표시값은 잠시 비게 됩니다. 명령을 실행하는 도중 연결이 끊기거나 시간 초과되면 해당 페이지를 먼저 새로 고쳐 결과를 확인한 뒤 다시 시도할지 정합니다.

“제거”를 클릭하면 서비스가 제거되고 GoodGood은 현재 프로세스 권한으로 계속 실행됩니다. Windows “설정 → 앱”에서 GoodGood을 제거할 때 서비스를 함께 제거하거나 남길 수 있습니다. 포터블 프로그램과 서비스 사본은 각각 독립적이므로 포터블 프로그램을 지우기 전에 여기에서 설치한 서비스를 제거할 수 있습니다.

**포터블 버전의 위험**: 권한 있는 서비스를 설치하거나 업데이트하고, 작업 관리자 대체를 켜고, PawnIO를 설치하거나 시작할 때 GoodGood은 관리자 권한으로 자신을 실행합니다. 권한 있는 서비스를 설치하면 자신을 SYSTEM으로 실행되는 서비스 프로그램으로 복사하기도 합니다. 설치 버전은 Program Files에 있어 관리자만 바꿀 수 있지만, 포터블 버전은 어디에나 둘 수 있으므로 표준 사용자가 쓸 수 있는 폴더(예: “다운로드” 폴더나 바탕 화면)에 두면 이미 있던 악성 프로그램이 그 전에 `goodgood.exe`를 바꾸어 사용자의 관리자 권한 부여로 SYSTEM 권한을 얻을 수 있습니다. 권한 있는 서비스가 필요하면 설치 버전을 쓰고, 포터블 버전을 쓸 때는 관리자만 쓸 수 있는 폴더에 둡니다.

세부 정보, 시작 항목 변경, 파일 사용 조회의 다시 시작 관리자 부분은 계속 GoodGood 자체 권한을 씁니다. 핸들 조회는 서비스를 쓸 수 있고 서비스를 쓸 수 없으면 현재 계정 권한으로 낮춰 조회합니다. 서비스가 연결되어 있으면 상태 표시줄 오른쪽 아래의 권한 표시가 “권한 있는 서비스”이고(인터페이스 프로세스 자체는 계속 표준 권한으로 실행됩니다) 서비스가 중지되거나 끊기면 약 30초 안에 “표준 사용자”로 돌아갑니다. 보호된 시스템 프로세스는 권한 있는 서비스의 조작을 거부할 수 있습니다.

네트워크 트래픽은 백그라운드에서 비동기로 읽으므로 보통 로컬 샘플링보다 새로 고침 주기 하나만큼 늦습니다. 서비스가 끊기거나 수집을 쓸 수 없으면 네트워크 열을 숨기고, 돌아오면 먼저 카운트 기준선을 만들어 쌓인 바이트를 순간 최대로 표시하지 않습니다. 클라이언트가 15초 동안 읽지 않으면 서비스가 ETW 세션을 닫고 다시 읽을 때 새로 시작합니다.

## 커널 센서

첫 실행 가이드는 권한 있는 서비스를 설정한 뒤 “커널 센서” 단계를 제공합니다. “서비스 설정”을 클릭해 이전 단계로 돌아가거나 “다음”을 클릭해 건너뛸 수 있습니다. 가이드와 설정 페이지는 진행 상황과 오류 정보를 공유하고, 가이드는 [정보](README.md#정보) 페이지에서 다시 열 수 있습니다.

“권한” 그룹은 “커널 센서” 스위치를 제공하고 기본값은 꺼짐입니다. GoodGood 권한 있는 서비스를 먼저 설치하거나 업데이트하고 시작한 뒤 스위치를 켭니다. GoodGood은 PawnIO를 자동으로 확인해 없거나 2.2.0보다 낮으면 공식 버전을 내려받아 설치하고, 이미 설치되어 요구 사항을 만족하면 드라이버를 시작하며, 이미 실행 중인 더 새로운 버전은 그대로 재사용합니다. 설치나 시작에는 관리자 권한이 필요하고 인터페이스 자체는 원래 권한을 유지합니다.

공식 2.0 구버전은 설치 방식이 다릅니다. GoodGood은 알려진 공식 서명 드라이버 파일을 식별하고 기본 설치 위치와 제거 정보를 확인한 뒤 새 설치 패키지와 옛 패키지를 먼저 검증하고, 구버전 공식 제거 관리자로 옛 버전을 지운 다음 새 버전을 설치합니다. 업그레이드 전에 PawnIO를 쓰는 다른 하드웨어 모니터링 프로그램을 종료합니다. 옛 서비스가 제거되지 않았거나 설치 관리자가 다시 시작을 요청하면 Windows를 다시 시작한 뒤 다시 켭니다. 설치 정보가 일치하지 않으면 자동 이전을 멈추고 Windows의 앱 관리에서 옛 버전을 제거한 다음 PawnIO 웹사이트에서 새 버전을 설치할 수 있습니다.

준비하는 동안 페이지를 전환해 진행 상황을 볼 수 있습니다. 설치나 관리자 권한은 직접 켤 때만 요청합니다. GoodGood은 공식 설치 패키지의 SHA-256과 Windows 서명을 확인하고, 취소하거나 검증에 실패하거나 드라이버가 시스템 정책에 막히면 이유를 표시하고 꺼진 상태를 유지합니다. 설치 관리자가 다시 시작을 요청하면 Windows를 다시 시작한 뒤 다시 켭니다. “PawnIO 웹사이트”에서 직접 설치할 수도 있습니다.

Windows에서 PawnIO 장치가 사용 안 함으로 되어 있으면 장치 관리자에서 먼저 사용하도록 설정한 뒤 다시 시도합니다. 장치 구성이 다시 시작 대기로 표시되어 있으면 먼저 다시 시작합니다. GoodGood은 서비스와 장치 상태를 함께 확인하고 모든 검사를 통과한 뒤에야 켜진 상태를 저장합니다.

PawnIO가 이미 정상적으로 실행 중이고 버전이 요구 사항을 만족하면 GoodGood은 장치를 확인한 뒤 그대로 재사용합니다. 표준 권한에서는 업데이트된 권한 있는 서비스가 장치 버전을 제공하므로 드라이버 저장 디렉터리의 쓰기 권한이 켜기에 영향을 주지 않습니다. 드라이버를 설치, 업그레이드, 시작하려면 여전히 파일과 상위 디렉터리 권한이 안전해야 하며, 관련 안내가 나오면 관리자가 해당 디렉터리를 확인해야 합니다. GoodGood은 시스템 디렉터리 권한을 그대로 둡니다.

성능 페이지의 CPU 보기는 “내부 센서” 카드에서 전력, 전압, 클록, 온도로 묶어 표시값을 보여 주고 “코어별 표시값” 카드에서 물리 코어마다 온도, 유효 클록, 전력, VID, 활성 비율을 제공합니다. Ryzen 7000/9000의 SVI3 공급 전압과 VID는 따로 표시하고, Intel은 PL1／PL2, 열 여유, 링 클록, 제한 상태를 제공하며 현재 상태와 하드웨어 이력을 따로 보여 줍니다. Windows 유휴 상태와 AMD SMU 상주 비율도 각각 표시합니다. 지원하는 메인보드는 팬 채널 회전 속도와 일치한 전원 레일, 메인보드·전원 온도도 표시합니다. 지원하는 하드웨어 범위는 [하드웨어 데이터](hardware-data.md#소비자용-하드웨어-호환-범위)를 참고합니다.

스위치를 끄면 커널 표시값 요청을 멈추고 Windows 기본 수집은 계속 동작하며, 서비스는 15초 동안 읽지 않으면 모듈을 해제합니다. 스위치를 끄거나 GoodGood을 제거해도 공유 PawnIO 드라이버는 제거되지 않고 Windows의 앱 관리에서 따로 제거할 수 있습니다.

Comet Lake S/H 내장 GPU의 온도, 클록, VID, GT／미디어 활동률, 제한 상태도 이 스위치가 제어하고 표시값은 해당 GPU 페이지에 나오며 VID는 요청 전압을 뜻합니다. 코어 클록과 공유 로직 클록은 유효한 0 MHz를 포함해 숫자로 바로 표시하고, 최소／최대 작동 클록은 기능 범위로 따로 나열합니다. 공유 메모리 클록은 컨트롤러 구성을 공칭 기준으로 환산하고 DDR 전송률은 그 약 두 배입니다. GPU 페이지는 커널 센서 상태를 표시하고 켜지지 않았거나 읽기에 실패하면 설명을 제공합니다. 내장 GPU RAPL 전력은 서비스가 직접 읽은 유효 PP1 에너지 차이를 먼저 쓰고 없으면 Windows 카운터로 물러나며 CPU 페이지에 중복해 표시하지 않습니다. 새 앱 버전을 설치하면 설치된 권한 있는 서비스가 갱신되고, 서비스를 설치하지 않은 시스템은 먼저 설치를 마쳐야 합니다.

## 작업 관리자 대체

“권한” 그룹의 “작업 관리자 대체” 카드는 시스템 작업 관리자 대체 상태를 표시하고 첫 실행 가이드에서도 바로 켤 수 있습니다. 기능은 기본으로 꺼져 있고, 배포판은 권한 있는 서비스를 설치해 현재 계정에 권한을 부여한 뒤에만 “대체 사용”을 제공합니다. 이 기능은 Ctrl+Shift+Esc를 포함해 컴퓨터 전체에서 `taskmgr.exe`의 시작 진입점에 영향을 주며, 권한을 부여한 계정에서는 GoodGood이 열리고 다른 계정은 계속 Windows 작업 관리자를 열려고 시도합니다. 다른 대체 설정이나 경로 필터 구성이 이미 있으면 켜기를 거부하고 자동으로 덮어쓰지 않습니다. 카드는 “다른 항목이 구성함”을 표시하고 `taskmgr.exe`의 IFEO 키에서 무엇을 발견했는지 적습니다. 현재 GoodGood 설정과 다른 Debugger 값, UseFilter 값, 또는 `PerfOptions` 같은 하위 키입니다. 카드에 나열된 내용으로 구성 출처를 확인하고 해당 프로그램으로 복구한 뒤 “상태 새로 고침”을 클릭합니다.

켤 때는 관리자 권한 부여를 확인해야 합니다. GoodGood은 시작 프로그램, 디버거 분리, 인터페이스 준비 상태를 확인하고 통과하면 복구 기록을 저장한 다음 `taskmgr.exe` 구성을 바꿉니다. GoodGood이 응답하지 않으면 독립 시작 프로그램이 Windows 작업 관리자를 열려고 시도합니다.

“Windows 작업 관리자 한 번 열기”를 클릭하면 Windows 기본 작업 관리자를 열고 현재 대체 설정은 그대로 유지합니다. 이 단추는 대체가 꺼져 있거나 권한 있는 서비스가 설치되지 않았을 때도 쓸 수 있고, 시작에 실패하면 카드 안에 이유를 표시합니다.

레지스트리 권한 검사는 통과했는데도 조작이 거부된다면 360 같은 보안 소프트웨어의 레지스트리나 시스템 보호 기록을 확인합니다. 이번 GoodGood 작업 관리자 대체에 해당하는 차단 기록을 찾으면 이번 변경을 허용하고 다시 시도할 수 있습니다. 해당 기록이 없으면 실패한 API와 오류 코드가 담긴 GoodGood 진단 로그를 제공해 계속 확인할 수 있습니다. GoodGood은 보안 소프트웨어 신뢰 규칙을 자동으로 추가하거나 보호를 끄거나 레지스트리 권한을 강제로 바꾸지 않습니다. 되풀이되는 오탐은 [360 소프트웨어 개방 플랫폼](https://open.soft.360.cn/guide/guide_1.php?i=3)에 이의를 제기하고 차단된 파일과 같은 버전을 제출합니다.

켜 둔 대체가 외부에서 취소되면 카드가 “대체가 제거됨”을 표시하고 진단 요약도 그 상태를 함께 보여 줍니다. GoodGood은 원래 켠 기록을 유지하고 시작과 상태 새로 고침 시 현재 시스템 진입점을 그대로 둡니다. 보안 소프트웨어 기록을 확인한 뒤 직접 다시 켤 수 있습니다.

카스퍼스키의 `HEUR:Trojan.Multi.Ifeodeb.a`는 이 기능이 쓰는 `taskmgr.exe:Debugger` 구성을 트로이 목마로 판정해 지울 수 있습니다. 카스퍼스키는 [Ifeodeb](https://threats.kaspersky.com/en/threat/Trojan.Multi.Ifeodeb/)를 Windows 시스템 프로그램의 비표준 디버거 구성 탐지로 정의합니다. 이의를 제기할 때 [공식 오탐 절차](https://support.kaspersky.com/kaspersky-for-windows/21.27/troubleshooting/other/1870)에 따라 탐지 대상, 탐지 이름, 제품과 바이러스 데이터베이스 버전, GoodGood 버전, 켠 단계를 제공합니다. 기록의 대상이 레지스트리 키이면 사용자가 직접 켠 작업 관리자 대체에 쓰인다는 점도 함께 설명합니다. 확인하는 동안에는 Windows 작업 관리자 진입점을 남겨 두고 GoodGood의 상주 바로 가기로 창을 엽니다.

권한 있는 서비스를 설치하거나 대체 자체 검사를 실행할 때 `PDM:Trojan.Win32.Generic`(`.nblk` 변형 포함) 행위 탐지가 나와 유지 관리 도우미가 종료되고 관련 파일과 바로 가기가 제거될 수도 있습니다. 유지 관리 도우미가 오류 보고를 남기지 않으면 GoodGood이 실제 종료 코드를 표시하고 진단 로그에도 그 값을 남기므로, 발생 시각을 보안 소프트웨어 사건과 맞춰 확인합니다. PDM 오탐 재검토는 위의 공식 절차에 GSI 시스템 보고서를 함께 첨부합니다. 작업 관리자 대체가 아직 기록되지 않았으면 현재는 Windows 기본 진입점을 계속 씁니다.

“Windows 작업 관리자 복원”은 권한 있는 서비스로 되돌리는 것을 먼저 시도하고 서비스를 쓸 수 없으면 관리자 권한을 요청합니다. 인터페이스를 실행할 수 없으면 카드 아래에 안내된 경로의 `goodgood-taskmgr-recover.exe`를 씁니다. 이 프로그램은 GoodGood 인터페이스나 백그라운드 서비스에 의존하지 않습니다. 독립 복구 프로그램도 손상되었으면 같은 디렉터리의 `taskmgr-recovery.txt`를 참고해 소유를 확인한 뒤 Debugger 값만 되돌리고 키 전체를 지우지 않습니다.

권한 있는 서비스를 제거하면 대체를 먼저 끄며 “제거”를 클릭할 때의 확인 상자가 이를 설명합니다. 권한 있는 서비스를 업데이트하면 대체는 켜진 채로 유지되고 대체에 쓰는 인터페이스와 시작 프로그램이 새 버전으로 함께 갱신됩니다. 설치 관리자로 GoodGood을 업그레이드할 때도 같습니다. 포터블 버전에서 프로그램 파일을 직접 바꾸었거나 설치 관리자가 업데이트를 마치지 못한 경우(예: 당시 시작 프로그램이 실행 중이었음)에는 Ctrl+Shift+Esc로 여는 것이 여전히 이전 버전이고 카드에 그 버전 번호가 적히며, 권한 있는 서비스에서 “서비스 업데이트”를 클릭해야 현재 버전이 열립니다. 업그레이드할 때 대체로 열린 이전 버전 GoodGood이 아직 실행 중이면(예: 알림 영역 상주) 이후 GoodGood을 열어도 그 버전이 표시되고 알림 영역에서 종료한 뒤에야 새 버전이 됩니다. 그러므로 업그레이드 전에 종료하는 것이 좋습니다. 대체를 복원한 뒤에는 다른 도구가 기록한 작업 관리자 대체가 서비스 업데이트나 제거에 영향을 주지 않습니다. GoodGood을 제거하기 전에도 복원 검사를 거쳐야 하고, 덮어쓰기 업그레이드는 작업 관리자 대체 구성을 유지합니다. 복원에 실패하면 파일을 남기고 관련 제거를 막으며 다른 도구의 구성은 그대로 둡니다. 자세한 과정은 [시스템 작업 관리자 대체](../architecture/task-manager.md)를 참고합니다.

## 애니메이션

| 설정 | 설명 |
|---|---|
| 창 전환 효과 | GoodGood 창을 표시, 숨기기, 최소화, 복원할 때의 페이드 효과를 제어합니다. 최대화와 최대화 복원은 항상 Windows 창 애니메이션을 씁니다. 끄면 Windows나 다른 창 관리 프로그램이 창 전환을 처리하며, 기본값은 Windows의 “애니메이션 효과” 설정을 따릅니다. |
| 인터페이스 애니메이션 | 페이지와 대화 상자 전환, 선택 표시의 이동, 정보 페이지와 가이드의 점 격자 애니메이션, 아이콘 동작을 제어합니다. 포인터를 단추, 탐색 항목, 설정 그룹에 올리면 그 아이콘이 짧은 동작을 한 번 재생하고(예: 톱니바퀴 회전, 다운로드 화살표 하강), 단추가 다른 아이콘으로 바뀌면(예: 일시 중지와 다시 시작) 새 아이콘이 튀어 들어옵니다. 기본값은 Windows의 “애니메이션 효과” 설정을 따릅니다. |
| 차트 애니메이션 | 부드럽게, 균형, 절전, 끔 네 단계입니다. 기본값은 부드럽게이고 Windows 애니메이션 효과를 껐으면 기본값이 끔입니다. 차트 상한이 바뀔 때의 전환과 상한 레이블의 표시도 이 설정을 따르며 끄면 바로 바뀝니다. 단계별 차이와 비용은 [차트 애니메이션](../design/charts.md)을 참고합니다. |

| 하드웨어 가속 | 기본으로 켜져 있고 GPU가 인터페이스를 그립니다. 끄면 CPU가 그리고(Windows 기본 소프트웨어 렌더러 WARP) GoodGood이 더 이상 GPU를 쓰지 않습니다. GPU가 최대로 사용되는 동안 GoodGood 인터페이스가 끊기거나 게임, 렌더링, 학습 같은 작업 중에 GoodGood이 GPU를 쓰지 않게 하려는 경우에 적합합니다. CPU 사용량이 늘어나므로 “차트 애니메이션”을 함께 낮출 수 있습니다. 전환하면 다시 시작하지 않고 바로 적용됩니다. |

세 가지 애니메이션 설정은 서로 독립적이고 “하드웨어 가속”은 애니메이션 설정을 바꾸지 않으며, 변경은 즉시 적용되고 저장됩니다. 다른 소프트웨어로 창 애니메이션을 관리할 때는 “창 전환 효과”를 끄고 인터페이스와 차트 애니메이션을 남길 수 있습니다. 업그레이드할 때 새 창 스위치는 이전의 인터페이스 애니메이션 상태를 물려받고 이후에는 따로 저장합니다.

창을 최소화하거나 알림 영역에 숨기면 인터페이스는 그리기를 멈추고 두 그리기 방식 모두 비용을 만들지 않습니다. “하드웨어 가속”이 바꾸는 것은 창이 보일 때의 비용입니다. 끄면 창 화면은 여전히 Windows가 화면으로 합성하고 곡선의 스크롤도 Windows 합성에 맡기며, CPU는 주로 샘플마다 곡선을 다시 그립니다. 알림 영역의 마우스 올림 카드와 빠른 패널도 CPU가 그립니다. 쓸 수 있는 GPU를 감지하지 못한 컴퓨터는 항상 CPU로 그리며 이 스위치는 그리기 방식을 바꾸지 않습니다.

## 데이터 및 기록

| 설정 | 설명 |
|---|---|
| 새로 고침 빈도 | 0.5초, 1초(기본값), 2초, 5초마다 샘플링합니다. 간격이 짧을수록 표시값이 자주 갱신되고 샘플링 비용도 커집니다. 상태 표시줄의 새로 고침 컨트롤로 간격을 바꾸거나 인터페이스 새로 고침을 일시 중지할 수 있습니다. 일시 중지하는 동안 기록과 규칙은 5초마다 샘플링합니다. |
| 최소화 상태의 새로 고침 빈도 | 창을 최소화한 뒤의 샘플링 간격으로 0.5초, 1초, 2초, 5초(기본값), 10초, 30초입니다. 창을 최소화하면 인터페이스가 그리기를 멈추고 샘플링만 유지합니다. 간격이 길수록 백그라운드 비용이 줄지만 새로 시작된 프로그램에 규칙이 적용되기까지 최대 한 간격이 걸리고, 5초를 넘으면 기록도 드물어집니다. |
| 숨겨진 동안 메모리 확보 | 창을 최소화하거나 알림 영역에 숨긴 상태가 1분, 10분(기본값), 30분에 이르면 차트 이미지를 해제하고 쓰지 않는 메모리를 Windows에 돌려줍니다. “안 함”을 고르면 계속 유지합니다. 수집, 기록, 규칙은 그대로 동작합니다. 창을 다시 표시하면 차트를 먼저 다시 그리므로 잠시 멈출 수 있습니다. |
| 네트워크 속도 단위 | 초당 바이트(MB/s, 기본값, 디스크와 같음) 또는 초당 비트(Mbps, 네트워크 어댑터 링크 속도와 회선 요금제에 맞춤)이며 앱 전체가 함께 바뀝니다. 성능 페이지의 네트워크 보기는 항상 두 단위를 함께 표시합니다. |
| 기록 저장 | 기본으로 켜져 있고 5초마다 리소스 사용량과 그때 가장 사용량이 많은 프로세스를 기록합니다. 백그라운드 샘플링 간격이 5초보다 길면 그 간격으로 기록합니다. 데이터는 이 PC에 7일 동안 보관되고, 기록을 끄면 이미 있는 데이터는 원래 보관 기간에 맞춰 정리됩니다. [기록 페이지](README.md#기록)를 참고합니다. |
| 저장된 기록 | 기록이 차지하는 공간과 가장 이른 기록 하나를 표시합니다. “지우기”는 확인 후 모든 기록을 삭제합니다. |

최소화 상태와 백그라운드 상주 시(위치는 [구성 요소 페이지](resident-mode.md#구성-요소-페이지))의 새로 고침 간격을 5초보다 짧게 바꾸면 먼저 확인을 띄웁니다. GoodGood이 그 간격으로 모든 프로세스와 하드웨어 데이터를 백그라운드에서 샘플링하므로 CPU 사용량과 전력 소비가 늘고 배터리를 쓸 때 더 뚜렷하다는 설명입니다. 취소하면 원래 간격을 유지합니다. 첫 실행 가이드의 “백그라운드에서 유지” 단계도 이 두 항목을 제공하며 규칙은 같습니다.

창이 최소화 상태나 알림 영역에서 포그라운드로 돌아올 때 그동안의 새로 고침 간격이 포그라운드의 “새로 고침 빈도”보다 길었으면 오른쪽 아래에서 간격 변화를 한 번 알립니다(예: “창이 최소화된 동안 GoodGood은 리소스를 아끼기 위해 1초 대신 5초마다 새로 고쳤습니다.”). 알림의 “조정”은 해당 설정 항목을 열며(최소화 시의 간격은 이 페이지, 백그라운드 상주 시의 간격은 구성 요소 페이지) “다시 알리지 않음”은 이 종류의 알림만 끄고 최소화와 백그라운드 상주의 알림은 따로 설정합니다. 창이 잠시만 비어 있어 아직 포그라운드 새로 고침 주기 하나가 지나지 않았으면 알리지 않고, 돌아올 때 첫 실행 가이드나 업데이트 대화 상자, 확인 상자가 표시되어 있거나 업데이트 후 처음 창을 표시하는 경우(이때는 새 버전의 새로운 기능이 표시됩니다)에도 이번에는 알리지 않습니다.

## 규칙

프로그램이 시작할 때 우선 순위나 효율성 모드를 자동으로 설정합니다. 그룹 위쪽에 프로그램 이름(예: `chrome.exe`)을 입력하고 “추가”를 클릭하면 새 규칙이 만들어집니다. 각 규칙은 다음을 포함합니다.

- **프로그램 이름**: 대소문자를 구분하지 않고 같은 이름의 여러 프로세스에 적용됩니다. 프로그램이 실행 중이면 규칙 앞에 그 아이콘을 표시합니다.
- **우선 순위**: 우선 순위 유지, 또는 실시간, 높음, 보통 초과, 보통, 보통 미만, 낮음 중 하나.
- **효율성 모드**: 효율성 모드 유지, 효율성 모드 사용, 효율성 모드 사용 안 함.
- **사용 스위치**: 규칙을 적용할지 정합니다. 사용하지 않으면 규칙 설정을 보관합니다.

규칙은 저장한 뒤 일치하는 기존 프로세스에 먼저 적용되고 이후 프로그램이 시작할 때 다시 적용됩니다. 백그라운드 스레드가 규칙을 처리하므로 GoodGood이 알림 영역에 숨겨져 있어도 실행됩니다. 느린 요청이 진행되는 동안에는 최신 프로세스 목록을 유지합니다.

각 규칙 아래에는 적용된 프로세스 수, 권한이 부족한 프로세스 수, 실행에 실패한 프로세스 수를 표시하고 규칙을 저장하거나 권한 출처가 바뀌면 다시 셉니다. 권한 있는 서비스를 설치, 중지, 다시 시작하면 기존 프로세스를 다시 확인합니다. 요청을 보낸 뒤 응답을 잃었을 때는 조작을 자동으로 반복하지 않으므로, 서비스 상태를 확인한 뒤 규칙을 다시 저장해 재시도합니다.

프로세스 목록에서 마우스 오른쪽 단추로 클릭해 “규칙 추가”를 고르면 그 프로세스의 우선 순위와 효율성 모드로 규칙을 만들 수 있습니다. 규칙은 실행 파일 이름으로 일치합니다. 여러 앱이 같은 호스트 프로그램을 쓰거나 설치 경로가 다른 같은 이름의 프로그램이 있으면 이 규칙이 미치는 범위를 알립니다.

## 업데이트

현재 버전 뒤의 종류는 실제 프로그램에서 옵니다. 개발 빌드는 따로 표시되고, 로컬 테스트 빌드와 시험판은 베타, 정식 배포는 안정판으로 표시됩니다. 업데이트 채널은 이후 확인할 버전의 출처를 정하고, 채널을 바꿔도 현재 프로그램의 버전 종류는 유지됩니다.

GoodGood은 GitHub Releases에서 새 버전을 받습니다. 자동 경로는 `https://github.com/acc0mplish/GoodGood/releases`에서 릴리스 정보와 설치 패키지를 읽고, GitHub에 연결할 수 없으면 내장 프록시(`PROXY_PRESETS`)를 차례로 시도하며 사용자가 지정한 프록시를 쓸 수도 있습니다. 새 버전을 찾으면 백그라운드에서 내려받고, 다운로드가 끝나 서명 검증을 통과한 뒤에 다음과 같이 처리합니다.

- 상태 표시줄 왼쪽의 버전 번호가 강조색 “{version} 설치”로 바뀌어 모든 페이지에서 보이고 포인터를 올리면 설명이 나옵니다. 다운로드하는 동안에는 그 자리에 진행률을 표시하고, 포터블 버전은 자동으로 내려받지 않으며 새 버전을 찾으면 “새 버전 {version}”을 표시합니다. 마우스 오른쪽 단추로 클릭해 “이 버전에 대해 다시 알리지 않음”을 고르면 이후에는 탐색 창의 “설정”과 설정 페이지의 “업데이트” 그룹에만 알림 점이 표시됩니다.
- 창이 표시된 상태이면 오른쪽 아래에서 “GoodGood {version}을(를) 설치할 준비가 되었습니다”를 한 번 알립니다. 창이 알림 영역에 숨겨져 있으면 다음에 창을 표시할 때, 첫 실행 가이드가 열려 있으면 가이드를 마친 뒤에 알립니다. 버전마다 한 번만 알리고 시작할 때 대화 상자를 띄우지 않습니다.
- 알림 영역 아이콘에 강조색 점이 표시되고 마우스 올림 카드에 새 버전 번호를 표시하며 빠른 패널 위쪽에 업데이트 진입점이 나오고 알림 영역 메뉴에 “버전 {version} 준비됨” 항목이 추가됩니다. 마우스 올림 카드를 껐으면 시스템 도구 설명이 “GoodGood {version}을(를) 사용할 수 있습니다”를 표시합니다.

새 버전을 찾으면 “업데이트” 그룹의 상태 카드가 “이 버전의 변경 사항 보기” 단추를 표시합니다. 이 단추, 상태 표시줄의 업데이트 표시, 빠른 패널의 “업데이트”, 알림 영역 메뉴 항목을 클릭하면 업데이트 대화 상자가 열려 현재 버전과 새 버전의 차이를 읽고 설치 패키지 크기와 서명 검증 결과를 확인하고 설치할 수 있습니다. 첫 실행 가이드가 열려 있으면 대화 상자는 가이드를 마친 뒤에 열립니다. 대화 상자의 버전별 항목은 새 기능, 수정, 성능, 업그레이드 안내 같은 범주로 묶여 색으로 구분되고 개수를 표시하며 새 기능은 카드로 나열됩니다. 여러 버전을 건너뛰었으면 목록 위에 범주별 항목 수를 합산해 표시하고 최신 버전은 기본으로 펼쳐지며 건너뛴 버전은 클릭해 펼칩니다. 합산 오른쪽의 “모두 펼치기”와 “모두 접기”로 모든 버전을 한 번에 펼치거나 접을 수 있습니다. 업데이트 후 표시하는 새로운 기능에서는 모든 버전이 기본으로 펼쳐지고 모두 클릭해 접을 수 있습니다. 대화 상자를 열면 각 부분이 차례로 나타나고 버전을 펼치거나 접을 때 높이가 부드럽게 전환되며, 포인터를 새 기능 카드나 항목에 올리면 서서히 강조됩니다. “인터페이스 애니메이션”을 끄면 바로 표시합니다. 팝업 높이는 창에 맞춰 늘어나 창이 높을수록 많은 내용을 보여 주고, 넘치면 내용 영역에서 스크롤합니다. 다운로드 진행률이 바뀌어도 펼친 상태와 읽던 위치를 유지합니다. 새로운 기능은 인터페이스 언어의 번역으로 표시하고, 그 언어의 번역이 없으면 영어로, 영어도 없으면 한국어로 표시합니다. “다시 시작하고 업데이트”를 클릭하면 설치가 시작되고 관리자 권한이 필요합니다. 설치하는 동안 GoodGood이 종료되고 설치 관리자는 진행률 표시줄만 보여 주며, 끝나면 표준 권한으로 GoodGood을 다시 시작해 원래 페이지로 돌아갑니다. 알림 영역에 숨긴 상태에서 시작한 업데이트는 다시 시작한 뒤에도 알림 영역에 남습니다. 관리자 권한 부여를 취소하면 설치하지 않고 나중에 다시 설치할 수 있습니다.

업데이트 후 창을 처음 열면 GoodGood이 업데이트 전후의 버전 번호와 그 사이의 변화를 표시합니다. 알림 영역에서 시작했거나 첫 실행 가이드나 작업 관리자 대체 진입점으로 시작했으면 설명을 알맞은 표시 시점으로 미룹니다. “업데이트 후 새로운 기능 표시”를 끄면 오른쪽 아래에 짧은 알림만 표시합니다. 다시 읽으려면 “이 버전의 변경 사항 보기”, 정보 페이지의 “새로운 기능”, 상태 표시줄 왼쪽의 버전 번호를 클릭합니다.

프로그램 파일을 다른 소프트웨어가 쓰고 있으면 설치 관리자가 점유한 프로세스, 오류 코드, 진단 로그 경로를 표시합니다. 관련 프로그램을 종료한 뒤 “다시 시도”를 클릭해 설치를 계속하고, “취소”를 클릭하면 설치를 끝내고 기존 프로그램을 유지합니다. 게임이나 보안 소프트웨어가 계속 점유하면 관련 프로그램을 정상적으로 종료하거나 작업을 저장하고 컴퓨터를 다시 시작한 뒤 설치합니다. 진단 로그는 설치 계정의 임시 디렉터리에 있고 팝업에 표시된 경로로 모을 수 있습니다. 다른 관리자 계정으로 권한을 부여하면 원래 바탕 화면 계정에서도 이번 설치 로그를 읽을 수 있습니다.

설치 패키지는 `%LOCALAPPDATA%\dev.goodgood.taskmanager\updates`에 캐시됩니다. 다시 시작할 때 캐시를 검증하고 통과하면 바로 설치할 수 있습니다. 설치 전에 서명을 다시 확인하고 파일이 바뀌었거나 지워졌으면 다시 내려받으며 설치를 마치면 캐시를 정리합니다.

| 설정 | 설명 |
|---|---|
| 자동으로 업데이트 확인 | 기본으로 켜져 있습니다. 시작한 지 약 1분 뒤에 한 번 확인하고 이후 하루에 한 번 확인하며, 확인에 실패하면 6시간 뒤에 다시 시도합니다. 끄면 “업데이트 확인”을 클릭할 때만 확인합니다. |
| 업데이트 후 새로운 기능 표시 | 기본으로 켜져 있습니다. 업데이트를 마친 뒤 창을 처음 열 때 새 버전의 새로운 기능을 보여 주고 버전마다 한 번만 표시합니다. 끄면 오른쪽 아래 알림으로 바뀝니다. 같은 줄의 “이 버전의 변경 사항 보기”는 언제든지 현재 버전의 새로운 기능을 엽니다. |
| 업데이트 채널 | 안정판(기본값)은 정식 버전만 받습니다. 베타는 `1.2.0-beta.1` 같은 시험판도 함께 받습니다. 안정판으로 되돌아가면 다음 업데이트는 설치된 버전보다 높아야 합니다. |
| 다운로드 소스 | 자동(기본값, GitHub를 먼저 시도하고 이어서 내장 프록시), GitHub만, GitHub 프록시만. |
| GitHub 프록시 | 내장 프록시는 gh-proxy.com, gh-proxy.org, ghfast.top이고 사용자 지정 프록시를 입력할 수도 있습니다. GitHub 주소 앞에 붙는 접두사이며 https를 써야 합니다. |
| 별표 알림 | 기본으로 켜져 있습니다. 하루에 한 번 창 오른쪽 아래에 카드를 표시해 GitHub에서 GoodGood에 별표를 남기도록 권합니다. |

“별표 알림” 카드는 창이 표시된 지 약 5초 뒤에 나타나고 약 30초 뒤에 자동으로 접히며 포인터가 카드에 머무는 동안은 유지됩니다. 대화 상자가 표시 중이면 닫힌 뒤로 미루고, 첫 실행 가이드를 열었거나 [포터블 버전 안내](README.md#첫-실행)가 표시된 실행에서는 표시하지 않습니다. 작업 관리자 대체(예: Ctrl+Shift+Esc)로 시작한 실행에서도 표시하지 않고 그날의 알림은 이후의 일반 시작으로 미룹니다. 카드의 조작은 다음과 같습니다.

- “GitHub에서 별표 남기기”는 브라우저에서 GoodGood 저장소 페이지를 열고 “별표 알림”을 끕니다.
- “다시 알리지 않음”은 “별표 알림”을 끄고 오른쪽 아래에서 설정에서 다시 켤 수 있다고 알리며, 알림의 “설정 열기”는 이 항목으로 이동합니다.
- 오른쪽 위의 닫기 단추는 그날의 카드만 접습니다.

날짜는 이 PC의 시간으로 판단하고 카드를 표시할 때 네트워크에 접근하지 않습니다.

제3자 프록시는 이 PC의 IP 주소와 요청한 파일을 알 수 있습니다. GoodGood은 설치 패키지 서명과 그에 묶인 버전 번호를 검증하고 현재 버전보다 높고 검증을 통과한 패키지만 설치합니다. 업데이트 설명도 서명과 버전 검증을 통과해야 표시합니다.

설치 버전은 앱 내 업데이트를 지원하고 관리자 실행이나 작업 관리자 대체로 연 사본도 포함합니다. 포터블 버전은 새 버전을 찾으면 새로운 기능을 표시하고 “다운로드”를 클릭해 프로그램을 직접 바꿉니다. 개발 빌드는 업데이트 확인을 건너뜁니다.

권한 있는 서비스를 설치한 상태이면 설치 관리자가 같은 관리자 권한 부여에서 서비스도 함께 갱신하고, 작업 관리자 대체를 켜 두었으면 대체가 유지되며 그것이 쓰는 인터페이스와 시작 프로그램도 새 버전으로 갱신됩니다. 설치 관리자가 서비스를 갱신하지 못하면 업데이트 후 첫 시작에서 서비스를 갱신할지 묻습니다. [권한](#권한)을 참고합니다.

### 이전 버전 업그레이드와 데이터

v0.3.3／v0.3.4에서 업그레이드하면 따로 저장한 인터페이스 환경 설정을 물려받습니다. v0.3.2 이하에서 v0.4.0으로 바로 업그레이드하면 옛 WebView2 캐시에만 있던 인터페이스 환경 설정(레이아웃, 행 메모, 고정 표시 등)이 기본값으로 돌아가므로 다시 설정해야 합니다. 앱 설정, 기록 파일, 로그는 유지됩니다.

업그레이드 후 GoodGood은 시작할 때 로컬 데이터 디렉터리에 있는 `EBWebView`, `WebView2` 옛 브라우저 데이터를 백그라운드에서 정리합니다. 아직 쓰이고 있는 파일은 이후 시작에서 계속 정리합니다. 구현은 [네이티브 호스트](../architecture/host.md)를 참고합니다.
