# 관리자 권한 시작

"관리자 권한으로 실행"은 기본적으로 꺼져 있습니다. 관리자 신분을 가진 현재 Windows 계정은 UAC 확인 한 번으로 시작 권한을 만들 수 있습니다. 권한 있는 서비스, PawnIO와 시스템 작업 관리자 대체는 각각 따로 승인합니다.

지속되는 관리자 권한 시작 작업은 릴리스 빌드에서만 사용합니다.

## 시작 채널

`goodgood-service::admin`은 보호된 `Program Files\GoodGood Runtime\<애플리케이션 식별자>\<계정 SID>`를 관리합니다. 디렉터리에는 안정적인 `goodgood-launcher.exe`, 버전별로 이름을 만드는 인터페이스 프로그램, 일반 시작 기록과 관리자 승인 기록이 있습니다. 일반 계정은 이 파일을 교체할 수 없습니다. 관리자 권한 시작은 권한 있는 서비스의 실행 여부에 의존하지 않고 서비스를 제거해도 취소되지 않습니다.

예약 작업은 현재 계정에 묶이고 `InteractiveToken`과 `HighestAvailable`로 실행됩니다. 런처는 `RunEx`로 대화형 세션을 지정합니다. 계정은 작업을 읽고 실행할 권한이 있고 관리자와 SYSTEM은 수정할 수 있습니다. 작업 동작은 보호된 GoodGood 프로그램을 가리키며 보조 프로그램 매개변수는 창 표시 여부, 업데이트 표시와 작업 관리자 준비 핸드셰이크만 부호화합니다.

승인 보조 프로그램은 Shell 폴더를 확인하기 전에 COM 보안을 초기화하고 Packet Privacy와 Impersonate를 사용하며, [작업 스케줄러 초기화 예제](https://learn.microsoft.com/en-us/windows/win32/taskschd/time-trigger-example--c---)를 따릅니다. 등록에 실패하면 읽기 전용 진단을 덧붙입니다. XML 검증과 기존 작업 조회의 HRESULT, 작업 상태, 지원되는 아키텍처 버전, COM 초기화 결과, 권한 상승 상태, 세션, 호출자 신원 일치 여부, 그리고 작업에 직접 관여한 프로그램 경로를 기록하며 경로에서 계정 SID로 이름 붙은 디렉터리는 `<SID>`로 표시합니다. 원래 등록 오류 코드는 유지하고 작업 XML, 매개변수나 계정 이름은 기록하지 않습니다.

기존 작업 검증에 실패하면 사용 설정 상태, 계정 SID, 로그온 종류, 실행 수준, 동작 수, 프로그램 경로와 매개변수별로 단계를 기록합니다. 속성을 읽거나 계정을 확인하다 실패하면 원본 오류 코드를 유지하고, 검증 불일치는 계속 `ERROR_INVALID_DATA (13)`을 반환합니다. 로그에는 실패 단계와 오류 코드만 기록하고 계정 이름, SID, 작업 XML이나 동작 매개변수는 기록하지 않습니다.

로그인 시작은 기존 Run 항목과 Windows "시작 앱" 스위치를 그대로 쓰되 대상을 안정적인 런처로 바꾸고 `--hidden`을 붙입니다. 일반 바로 가기와 고정 아이콘도 같은 방식을 쓰고 창의 AppUserModelID는 애플리케이션 식별자를 유지합니다. 시스템 작업 관리자 대체는 표준 권한 진입점을 먼저 만들고, 그 진입점이 단일 인스턴스와 주 창을 만들기 전에 관리자 승인에 따라 분기합니다. 상주 바로 가기로 표시하면 이미 실행 중인 관리자 인스턴스를 보여 줍니다.

예약 작업은 사용자 SID를 계정 이름으로 정규화한 뒤에도 검증은 사용자 SID로 합니다. 순수 계정 이름이 같은 이름의 컴퓨터나 도메인 개체와 일치하면 조회가 반환한 도메인 한정 계정 이름으로 다시 확인하고 결과가 사용자 계정인지 검증합니다. 승인 작업과 기록을 제출한 뒤 바로 가기 마이그레이션에 실패해도 이미 효력이 발생한 승인은 유지하며, 사용할 수 없는 바탕 화면이나 시작 메뉴 디렉터리는 해당 단계별로 진단 로그에 기록합니다.

참고: [작업 보안 컨텍스트](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks), [RunEx의 세션과 매개변수](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/nf-taskschd-iregisteredtask-runex).

시작 작업은 우선 순위 4를 사용해 시작 보조 프로그램이 보통 CPU, I/O와 메모리 우선 순위를 쓰게 하며, 대화형 애플리케이션 시작 용도에 맞춥니다. 값 매핑은 [Task Scheduler의 Priority 정의](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-priority-settingstype-element)를 참조하십시오.

## 권한 전환과 실패 처리

시작 요청은 무작위 이름의 이벤트와 길이가 제한된 데이터를 사용합니다. 보조 프로그램은 요청자의 PID, 생성 시간, 계정, 세션과 무결성 수준을 확인하고 제한된 토큰을 거부합니다. 원래 프로세스가 확인하고 종료하면 보조 프로그램이 대상 권한의 인터페이스를 시작합니다.

이미 일반 창이 있으면 관리자 사본이 단일 인스턴스 메시지로 인계를 제안합니다. 받는 쪽은 프로세스의 관리자 토큰, 계정, 세션, 생성 시간과 보호된 프로그램 경로를 확인하고 종료합니다. 새 프로세스가 단일 인스턴스 잠금을 얻은 뒤 설정을 읽고 샘플링과 기록을 시작하며 창을 만듭니다. 이미 관리자 창이 있으면 표시와 준비 요청만 전달합니다.

첫 프레임을 그린 뒤 시작 성공을 확인합니다. 준비에 실패하면 원래 인터페이스를 유지하고, 대상 시작에 실패하면 이번에 시작한 프로세스를 정리하고 표준 권한 인터페이스를 되살립니다. 자동 시작이 작업 무효를 발견하면 설정에 수리를 안내하고 수리 작업이 승인을 다시 요청합니다. 작업 관리자 대체로 시작한 경우에는 Windows 작업 관리자로 대체할 수 있습니다.

## 설정, 시작 가이드와 유지 관리

설정은 승인 상태와 현재 프로세스 권한을 따로 표시합니다. 승인 존재 여부는 예약 작업으로 판단하며 실행 디렉터리나 승인 기록이 비정상이어도 승인을 끌 수 있습니다. 계정에 실행 디렉터리가 없으면 작업 스케줄러에 연결하지 않고, 승인 기록이 없으면 작업 스케줄러를 사용할 수 없는 상태를 오류로 표시하지 않습니다. 권한을 전환해야 하면 설정에서 준비를 마친 뒤 다시 시작하며, 시작 가이드의 승인은 먼저 저장하고 완료하거나 건너뛰어 가이드 상태를 저장한 뒤 전환합니다. 승인 해제는 사용 설정과 설치 후 유지 관리와 함께 실행 디렉터리의 `install.lock`을 공유합니다. 다른 작업이 그 잠금을 보유하고 있으면 승인 해제는 실패로 보고하고 나중에 다시 시도할 수 있습니다. 승인 해제는 실제 디렉터리를 단계별로 고정하고 디렉터리 링크를 거부하며 디렉터리의 소유자와 ACL에 의존하지 않습니다. 잠금 파일은 그 파일 자체만 열고, 관리자가 열 수 없거나 잠금 파일이 재분석 지점이나 하드 링크로 교체되었으면 디렉터리가 외부에서 수정된 것이므로 승인 해제는 이 잠금을 거치지 않고 계속하며 링크 대상도 열지 않습니다. 승인 해제는 예약 작업을 먼저 삭제한 뒤 승인 기록과 오래된 인터페이스 사본을 정리하고, 일반 시작 기록이 가리키는 프로그램은 유지합니다. 그 기록을 신뢰할 수 없으면 사본을 모두 유지합니다. 로그인 시작 환경 설정, 설정과 기록은 유지합니다. 표준 권한 창 준비에 실패해도 철회는 효력이 있으며 현재 창은 유지하고 종료 후 다시 열도록 안내합니다. UAC 끔처럼 분할 토큰이 없는 관리자 계정은 전환할 표준 토큰이 없으므로 승인을 철회하면 계정 기본 권한을 유지하고 표준 권한 시작 보조 프로그램을 기다리지 않습니다. 인터페이스는 여전히 현재 프로세스의 실제 권한을 표시합니다.

설치 후 훅은 기존 보호된 기록과 작업 동작을 갱신하고 다른 계정에는 승인을 추가하지 않습니다. 제거는 인터페이스 사본을 먼저 끝내고 작업 스케줄러에서 현재 애플리케이션 식별자와 유효한 계정 SID에 해당하는 작업을 열거해 철회한 뒤 관리자 권한 시작 파일을 삭제하며, 실행 디렉터리가 없어도 작업을 철회할 수 있습니다. 정리는 독립 삭제 경로를 쓰고 실제 디렉터리를 단계별로 고정하며 디렉터리 링크와 동시 교체를 거부하고, 알려진 파일 이름만 삭제하며 그 안의 승인 내용을 사용하지 않고 소유자나 ACL도 수정하지 않습니다. 파일이 아직 점유되어 있으면 실패 상태를 유지하고 해제 후 다시 시도할 수 있습니다. 알 수 없는 파일은 유지하고 디렉터리를 재귀적으로 처리하지 않습니다. 애플리케이션 식별자가 공유하는 `GoodGood Runtime`이 비면 함께 삭제하며, 삭제 실패는 제거에 영향을 주지 않습니다. 일반 런처와 작업 동작의 프로그램 경로는 포터블 버전의 원래 위치에 의존하지 않습니다.

포터블 버전을 직접 업데이트할 때는 관리자 권한 실행을 먼저 끄고 종료한 뒤 파일을 교체하고 새 버전에서 다시 켭니다. 보호된 사본이 더 오래된 것을 발견하면 새 버전은 표준 권한으로 시작하고 사용자 승인 후 보호된 사본을 갱신합니다.

같은 버전 번호로 다시 빌드한 경우는 프로그램 내용으로 식별합니다. 비교 결과는 파일 경로, 크기와 수정 시간별로 캐시하고 원본 프로그램이 바뀌면 다시 비교합니다.
