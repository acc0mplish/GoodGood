# 전역 바로 가기

Windows 호스트는 주 창에서 `RegisterHotKey`를 호출해 창 표시·숨기기 조합을 등록하고 `WM_HOTKEY`로 알림을 받습니다. 호스트와 설정 페이지는 [키와 예약 조합 표](../../resources/hotkey-table.json)와 [검증 사례](../../src-gpui/tests/hotkey-cases.json)를 함께 씁니다. 조작 방법은 [설정](../guide/settings.md#키보드-바로-가기)을 참고합니다.

## RegisterHotKey의 동작

다음 결론은 Windows 11(26300)에서 실측한 것입니다. `SendInput`으로 표시를 넣은 키를 주입하고 F20–F23을 주 키로 쓰며, 같은 스레드의 저수준 키보드 후크로 시스템이 본 사건을 기록했습니다.

| 상황 | 결과 |
|---|---|
| CapsLock을 먼저 누른 채로, 또는 CapsLock이 켜진 상태로 조합 입력 | 정상적으로 실행 |
| 주 키를 먼저 누르고 보조키를 나중에 누름 | 실행되지 않음. 보조키 집합은 주 키를 누른 순간에 비교함 |
| `VK_RCONTROL`을 주 키로 사용 | 절대 실행되지 않음. `VK_CONTROL`을 주 키로 쓰면 어느 쪽 Ctrl을 단독으로 눌러도 실행됨 |
| 왼쪽 Ctrl, 오른쪽 Ctrl, 왼쪽 Alt를 차례로 누름(보조키만) | `Ctrl+Alt+VK_MENU`만 실행되며, Alt를 누르는 순간 모든 Ctrl+Alt+문자보다 먼저 처리됨 |
| Ctrl+CapsLock 등록 | Ctrl을 먼저 눌러야 함. 바로 가기가 가져간 CapsLock도 여전히 대소문자를 전환함 |
| 주 키를 이미 누른 상태에서 등록해 자동 반복이 한 번 발생 | 실행됨. `MOD_NOREPEAT`을 붙여도 같으며, 붙이지 않으면 반복마다 실행됨 |
| 저수준 키보드 후크가 주 키를 삼킴 | 등록한 바로 가기는 실행되지 않음. 후크가 바로 가기보다 먼저 처리됨 |

또한 `Shift+A`, `Ctrl+C`, `Ctrl+1`, `Alt+Space`, `Alt+PrintScreen`은 모두 등록에 성공합니다. Alt+F4, Alt+Tab, Ctrl+Esc, Ctrl+Shift+Esc, 보조키 없는 F12와 대부분의 Win+문자는 `ERROR_HOTKEY_ALREADY_REGISTERED`를 돌려줍니다.

## 기록과 등록

- 설정 페이지는 GPUI의 키 이름, 현재 배열 문자, 보조키를 [`Recording`](../../src-gpui/src/frontend/recorder.rs)에 넘겨 공유 키 표의 주 키로 매핑합니다. 좌우 보조키는 같은 표시를 쓰고, 보조키를 먼저 누른 뒤 주 키를 놓을 때 조합을 확정합니다.
- 기록하는 동안 기존 바로 가기를 일시 중지하고 자동 반복을 무시합니다. 보조키만 1.5초 동안 누르고 있으면 주 키가 다른 프로그램에 잡혀 있을 수 있다고 알립니다. 기록을 끝내거나 취소하면 등록을 되살리고, 창을 숨기거나 일시 중지한 상태가 60초에 이르러도 호스트가 되살립니다.
- 새 조합에는 보통 Ctrl, Alt 또는 Win 중 하나가 필요합니다. F13–F24는 단독으로 쓸 수 있고, 일부 Shift+기능 키 조합은 확인을 거쳐야 합니다. 설정 페이지는 시스템 예약 키, 잠금 키, 흔한 편집 조합을 막습니다. Ctrl+Pause는 Break의 가상 키 코드를 만들어 내므로 기록기가 이 조합을 거부합니다.
- [`hotkey.rs`](../../src-gpui/src/hotkey.rs)가 공유 키 표의 주 키를 Windows 가상 키 코드로 바꾸고 `MOD_NOREPEAT`으로 등록합니다. 변경할 때는 새 조합을 먼저 등록하고 설정 저장에 성공하면 기존 조합을 해제하며, 저장에 실패하면 새 등록을 되돌립니다. 시작할 때 저장된 조합을 설정에서 복원합니다.
