# 네이티브 호스트

`src-gpui/src/lib.rs`는 애플리케이션 시작을 담당하며, 먼저 설치, 작업 시작, 서비스와 작업 관리자 보조 모드를 처리한 뒤 설정, 진단 로그, 단일 인스턴스 통신, 샘플러와 GPUI 창을 로드합니다.

수집기가 기준선 준비를 마치면 샘플러가 최소 샘플링 간격(250 ms)이 끝날 때 첫 스냅숏을 만듭니다. 시작 중에 로드한 전면, 백그라운드 간격과 일시 중지 설정은 이 기한을 유지하며, 이후 스냅숏은 첫 샘플링 시각부터 선택한 간격으로 예약됩니다. 작업 관리자 대체는 첫 스냅숏이 인터페이스에 들어온 뒤에 준비 완료를 확인하고 창을 표시합니다.

플랫폼 호스트는 창, 알림 영역과 전역 바로 가기를 관리합니다. 바로 가기를 누르면 주 창이 사용 중인 창이면 숨기고, 아니면 맨 앞에 표시합니다. 사용 중이라는 것은 주 창이 전면 창이거나, 전면이 작업 표시줄(숨겨진 아이콘 영역 포함)이거나 비어 있으면서 그 전의 최근 다른 전면 창이 주 창인 경우입니다. 작업 표시줄을 클릭하면 작업 표시줄이 먼저 전면 창이 되므로, 호스트는 `EVENT_SYSTEM_FOREGROUND`로 작업 표시줄이 아닌 최근 전면 창을 기록합니다. 알림 영역 아이콘이나 작업 표시줄 모니터를 클릭할 때는 가시성으로 따로 판단합니다. 작업 표시줄 모니터는 활성화를 얻지 않는 자식 창이므로 클릭 후 전면 창이 사용자가 방금 쓰던 프로그램을 반영하지 않을 수 있습니다. 주 창이 표시 중이고, 최소화되지 않았고, 숨겨지지 않았고(`DWMWA_CLOAKED`, 다른 가상 데스크톱 포함) 다른 앱의 일반 창에 가려지지 않았을 때 숨깁니다. 가려짐은 그 위에 있으면서 중심을 덮고 최소 3분의 1 면적을 차지하는 창을 뜻하며(`activation::covered`), 항상 위 창, 도구 창과 마우스 관통 오버레이는 세지 않습니다. 창이 최소화되거나 숨겨지면 곡선 그리기를 멈추고 샘플링은 해당 백그라운드 간격으로 계속합니다. 창을 복원하면 새 스냅숏을 요청하고 그 간격을 샘플링 시각에 맞춰 표시합니다.

호스트의 `goodgood-restored` 이벤트는 알림 영역 숨기기, 최소화와 이 프로세스의 첫 표시를 구분합니다. 인터페이스는 `trayPage` 환경 설정에 따라 이후 알림 영역 복원을 처리합니다. 기본값은 현재 페이지를 유지하고 `default`를 선택하면 `startPage`가 지정한 기본 페이지를 엽니다. 닫지 않은 대화 상자는 원래 컨텍스트를 유지합니다. 첫 표시는 시작 페이지 선택을 따르므로 업데이트 후 재시작해도 업데이트 전 페이지로 돌아갑니다.

파일 끌어다 놓기는 프런트엔드의 OLE 수신과 Windows 네이티브 파일 메시지가 함께 처리합니다. 관리자 창은 네이티브 파일 메시지 채널로 표준 권한 프로그램의 파일 전달을 받고, 디코딩할 때 파일 수, 경로 하나의 길이와 전체 길이를 제한한 뒤 기존 파일 잠금 조회에 넘깁니다. 창을 소멸할 때 메시지 서브클래스를 제거하고 호스트 참조를 해제합니다. 인터페이스는 [DragAcceptFiles](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-dragacceptfiles)와 [ChangeWindowMessageFilterEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changewindowmessagefilterex)를 참조하십시오.

`window_motion.rs`는 창을 표시할 때, 알림 영역으로 숨길 때, 최소화와 복원할 때 제자리에서 페이드 인·아웃시킵니다(표시 180 ms, 사라짐 140 ms). 독립된 `motion.window` 환경 설정으로 제어합니다. 켜져 있는 동안에는 페이드가 진행 중이거나 창이 최소화·숨김 상태일 때만 DWM 창 전환을 억제해 모든 복원 경로가 페이드 인으로 나타나게 합니다. 창이 표시 중일 때는 DWM 전환을 유지해 최대화, 최대화에서 복원, 스냅이 시스템 애니메이션을 따릅니다. 끄면 진행 중인 페이드를 끝내고 자체 임시 투명 스타일을 제거하며 시계를 멈추고, DWM 전환과 네이티브 최소화/복원 메시지 처리를 해제합니다. 다른 스레드의 요청은 창 스레드로 넘겨 실행하며, 제목 표시줄의 최소화 버튼은 `SC_MINIMIZE`를 보내고 켜져 있을 때는 작업 표시줄 복원과 다른 프로그램이 직접 창을 표시하는 경우에도 페이드 인합니다.

`crates/goodgood-app/src/preferences.rs`는 인터페이스 환경 설정과 창 위치를 원자적으로 구성 디렉터리의 `preferences.json`에 저장하며, 같은 구성 디렉터리의 시작 진입점이 환경 설정을 공유합니다. 파일은 v0.3.3/v0.3.4의 배치를 따릅니다. 환경 설정은 `values`에, 창 위치는 `window`에 저장하고 갱신할 때 다른 구성은 유지합니다. v0.3.2 이하에서 바로 업그레이드하면 이전 WebView2 캐시의 인터페이스 환경 설정이 기본값으로 복원되며, 자세한 내용은 [업그레이드 안내](../guide/settings.md)를 참조하십시오. `src-gpui/src/window_state.rs`는 `WINDOWPLACEMENT`의 일반 창 사각형과 최대화 표시를 저장하고, 이동이나 크기 조절이 끝나면 저장하며 종료와 나가기 전에 다시 기록합니다. 숨김 시작은 첫 표시까지 최대화 복원을 미루고 최소화 상태는 복원하지 않으며, 테스트 인스턴스는 창 위치를 복원하지 않습니다.

여러 모니터에 걸친 위치를 복원하면 `SetWindowPlacement` 안에서 모니터 변경 콜백이 동기적으로 실행될 수 있습니다. GPUI 컨텍스트가 갱신 중이면 창은 이 알림을 합쳐 미룬 뒤 대여를 해제하고 최신 모니터와 새로 고침 간격을 읽어, 네이티브 콜백의 재진입으로 인한 시작 충돌을 피합니다. 컨텍스트가 유휴이면 알림을 즉시 처리합니다.

`admin.rs`는 창을 만들기 전에 관리자 권한 시작과 권한 전환을 처리합니다. 설정 페이지는 전환을 즉시 적용하고 시작 가이드는 끝날 때 적용하며, 자세한 내용은 [관리자 권한 시작](administrator-startup.md)을 참조하십시오. 로그인 시작 항목은 보호된 관리자 런처나 애플리케이션 자체를 사용합니다. 설치와 제거 전에 `goodgood.exe --goodgood-close-copies`가 관리자 권한 시작과 작업 관리자 대체 디렉터리의 인터페이스 사본을 끝내 단일 인스턴스 잠금과 교체 대상 파일을 해제합니다.

`native_runtime.rs`는 프로세스 내 상태를 관리하고 알림을 합쳐 메인 스레드에 배정합니다. `commands.rs`는 인터페이스 요청을 애플리케이션 서비스에 분배하며, 시간이 걸리는 작업은 작업 스레드에서 완료합니다.

알림 영역 아이콘의 생성, 도움말과 아이콘 갱신은 독립 스레드가 Windows Shell을 호출해 처리하고, 샘플링 스레드와 인터페이스는 최신 상태만 제출합니다. Explorer가 느려지는 동안에는 이전 도움말을 쌓지 않고 회복된 뒤 최신 상태를 적용하며, `TaskbarCreated` 알림과 이후 갱신이 알림 영역 아이콘을 다시 만듭니다. 종료할 때 삭제 요청에 최대 100 ms를 기다려 주며, 알림 영역 오작동이 창 종료를 막지 않습니다.

실시간 알림 영역 아이콘(`shell/tray_icon.rs`)은 알림 영역 스레드에서 `SM_CXSMICON` 크기로 그립니다. 추세와 비율 점 격자는 16, 20, 24, 32 px에 각각 정수 픽셀 배치가 있고, 다른 크기는 정수 배로 확대하면서 여백이 가장 작은 배치를 골라 가운데에 놓으며 점은 항상 정수 픽셀에 놓입니다. 알림 영역 스레드는 최근 6개 값을 보관해 추세를 열로 표시하고, 숫자는 GDI 그레이스케일 앤티에일리어싱 텍스트의 커버리지를 사용합니다. 새 값으로 그린 픽셀이 현재 아이콘과 같으면 기존 아이콘을 유지하고 Shell을 호출하지 않습니다. 글자 색은 `SystemUsesLightTheme`에서 읽고 `WM_SETTINGCHANGE`에서 갱신합니다. 아이콘을 추가한 뒤 `NOTIFYICON_VERSION_4`로 전환합니다. 콜백의 하위 비트는 이벤트, `wParam`은 기준점 좌표이며 오른쪽 클릭은 `WM_CONTEXTMENU`, 마우스 올림은 `NIN_POPUPOPEN` / `NIN_POPUPCLOSE`로 도착합니다. 마우스 올림 카드를 켜면 `NIF_SHOWTIP`을 설정하지 않아 시스템 도움말이 카드에 자리를 내주고, 도움말 텍스트는 화면 읽기 프로그램용으로 유지됩니다.

마우스 올림 카드, 빠른 패널과 작업 표시줄 모니터의 패널(`frontend/tray.rs`)은 GPUI 팝업 창(`WindowKind::PopUp`) 하나를 공유하며, 미리 만들어 두고 두 번의 사용 사이에는 숨깁니다. 새 창은 렌더러, 스왑 체인과 글리프 아틀라스를 만들어야 하고 개발 빌드는 셰이더까지 그 자리에서 컴파일하므로 i5-13500HX에서 릴리스 빌드 약 30 ms, 개발 빌드 약 0.6 s가 걸리는 반면, 이미 있는 창을 표시해 페이드 인을 시작하기까지는 약 10–20 ms입니다. 알림 영역 아이콘이나 작업 표시줄 모니터가 포인터 이동(`WM_MOUSEMOVE`)을 받으면 즉시 만들고, 창을 알림 영역으로 숨겼거나 알림 영역 방식으로 시작한 경우에는 1.5 s 뒤에 만듭니다. 만든 뒤에는 화면 밖에서 완전히 투명하게 빠른 패널을 한 번 배치해 텍스트 조판과 글리프 래스터화를 미리 마치고 높이를 기록합니다. 숨긴 창은 전용 메모리를 약 13 MB 차지하며 "숨길 때 메모리 해제"와 함께 해제되고, 이후 포인터가 알림 영역 아이콘으로 오면 다시 만듭니다. 호스트는 `Shell_NotifyIconGetRect`와 해당 모니터의 작업 영역으로 기준점을 계산하고(`shell/tray_anchor.rs`), 팝업 창은 이전 높이로 완전히 투명하게 표시되어 배치를 마친 뒤, 높이가 다르면 내용 높이와 클라이언트 영역(보이지 않는 테두리 제외)으로 알림 영역 아이콘 옆, 작업 표시줄에서 12 px 떨어진 곳에 다시 위치를 잡고 나서 계층 창의 불투명도로 페이드 인합니다. 창은 비활성 창의 프레임 속도 상한에 걸리지 않으며 페이드 인·아웃은 모니터 주사율로 그립니다. 패널은 테스트 인스턴스 밖에서 전면을 얻고 활성화를 잃으면 닫힙니다. 아이콘이 숨겨진 아이콘 팝업 영역(`WindowFromPoint` 위치가 작업 표시줄 프로세스에 속하지만 작업 표시줄의 최상위 창은 아님, Windows 11에서는 `TopLevelWindowForOverflowXamlIsland`)에 있으면 기준점을 그 팝업 영역의 사각형으로 바꾸고 카드와 패널을 그 위에 놓습니다. 이 팝업 영역은 활성화를 잃으면 접히므로 패널이 전면을 얻지 않고, 팝업 창의 서브클래스 프로시저가 `WM_MOUSEACTIVATE`에 `MA_NOACTIVATE`로 응답하며(GPUI는 기본적으로 클릭 시 창을 활성화함) 다른 창이 전면을 얻으면 `EVENT_SYSTEM_FOREGROUND` WinEvent 훅으로 패널을 닫습니다. 마우스 올림 카드도 활성화를 얻지 않습니다. 열려 있는 동안 샘플러의 창 프로브는 "표시"로 간격을 계산해 값이 전면 새로 고침 빈도로 갱신됩니다.

데스크톱 모니터(`frontend/monitors.rs`)는 또 다른 GPUI 팝업 창으로, 켜면 만들고 끄면 제거합니다. 인터페이스는 값만 그리고, 시스템 쪽 창 동작은 호스트의 `shell/desk.rs` 서브클래스 프로시저가 처리합니다. `WM_MOUSEACTIVATE`에는 `MA_NOACTIVATE`로 응답합니다. 왼쪽 버튼을 누르면 호스트가 포인터를 캡처하고 화면상 포인터 이동량으로 창을 옮기며, 시스템 드래그 임계값을 넘어야 드래그로 봅니다. 놓으면 `goodgood-desktop-monitor` 이벤트로 클라이언트 영역 왼쪽 위의 물리 좌표를 인터페이스에 넘겨 저장하게 합니다. 두 번 클릭하면 주 창을 표시합니다. 오른쪽 클릭의 네이티브 메뉴는 서브클래스 프로시저에서 실행하며 알림 영역 메뉴처럼 GPUI 이벤트 처리 안에 메시지 루프를 중첩하지 않습니다. 항상 위는 `HWND_TOPMOST` / `HWND_NOTOPMOST`로 전환하고 불투명도와 마우스 관통은 계층 창의 `LWA_ALPHA`와 `WS_EX_TRANSPARENT`를 사용합니다. 창은 화면 밖에서 표시되어 배치를 마친 뒤 내용 높이와 클라이언트 영역(보이지 않는 테두리 제외)으로 저장된 위치에 놓입니다. 그 위치가 어떤 모니터에도 없으면 주 모니터 작업 영역의 오른쪽 위에 놓습니다. 배율이 다른 모니터로 옮기면 새 배율로 다시 위치를 잡습니다.

작업 표시줄 모니터(`shell/taskbar.rs`)는 `Shell_TrayWnd`의 계층 자식 창으로, 독립 스레드 `goodgood-taskbar`의 메시지 루프에서 실행됩니다. 스레드를 넘나드는 부모·자식 창은 입력 큐를 공유하므로, 별도 스레드를 두면 인터페이스 스레드가 바쁠 때 작업 표시줄을 붙잡지 않고 Explorer가 느려져도 이 스레드에만 영향을 줍니다. 창은 `WS_EX_NOPARENTNOTIFY`를 가져 생성과 소멸 시 Explorer에 알림을 보내지 않습니다. 인터페이스는 샘플링마다 각 값의 이름, 값과 최대 너비를 제출하고(`shell/taskbar_draw.rs`), 스레드는 작업 표시줄의 DPI로 조판하며 텍스트도 인터페이스와 같이 DirectWrite로 설정합니다. 인터페이스의 Segoe UI Variable Text, 고정 폭 숫자와 인터페이스 언어에 따른 글꼴 대체를 쓰고, 이름은 Regular, 값은 Medium입니다(굵기 축으로 정확히 500을 잡으며, Semibold는 작업 표시줄 글자 크기에서 뭉개집니다). 글자는 픽셀마다 세 번 샘플링해 커버리지를 구해 하나의 값으로 합성하고, 시스템 텍스트 렌더링 매개변수의 감마와 대비로 보정해 미리 곱한 BGRA로 칠하여 `UpdateLayeredWindow`로 표시합니다. 처음의 GDI 그레이스케일 앤티에일리어싱은 커버리지 등급이 적어 곡선이 계단처럼 보이고 커버리지 보정이 없어 어두운 작업 표시줄의 밝은 텍스트가 흐릿하고 톱니처럼 보였습니다. 레이블 스타일의 텍스트는 13 px(인터페이스 기본 글자 크기)로 두 줄이 48 px 작업 표시줄에 딱 들어갑니다. 곡선 스타일은 값마다 둥근 카드를 놓고 이름과 값을 위에, 곡선을 아래에 두며, 인터페이스가 값과 함께 최근 40회 샘플링을 제출하고(시간 축에서 가져와 값의 눈금으로 0–1로 정규화) 스레드가 장치 색으로 면과 꺾은선을 그립니다. 캡슐 스타일은 값마다 높이 24 px의 둥근 캡슐 하나에 장치 색 점과 이름, 값을 한 줄로 놓으며, 값의 확보 너비는 최근 60초에 실제로 나타난 가장 넓은 값을 씁니다(`taskbar_draw::Reserve`, 작업 표시줄 스레드가 보관). 큰 숫자 스타일은 장치 색의 10 px 이름과 왼쪽 정렬한 16 px 숫자를 쓰고 단위는 작게 흐리게 표시합니다. 네 가지 스타일은 같은 조판 함수가 스타일에 따라 텍스트와 카드를 배치하며(`taskbar_draw::lay_out`), 텍스트 형식은 글자 크기별로 캐시합니다. 모든 픽셀은 1/255의 불투명도를 남겨 영역 전체가 포인터를 받습니다. 이미지가 이전과 같으면 갱신하지 않습니다. 스레드는 500 ms마다 작업 표시줄과 알림 영역(`TrayNotifyWnd`)의 위치, DPI와 자식 창 계층을 확인하고 필요하면 다시 위치를 잡아 자식 창 맨 위로 되돌립니다. Explorer가 다시 시작되면 `TaskbarCreated`나 작업 표시줄 창 무효화로 다시 붙고, 작업 표시줄이 없으면 2초마다 찾습니다. Windows 11의 작업 표시줄 버튼은 XAML 내용으로 그려지므로 모니터는 알림 영역 왼쪽이나 작업 표시줄 시작 지점의 빈 곳을 덮으며, 위치는 `TaskbarAl`, `TaskbarDa`와 위젯 패키지 존재 여부를 참고합니다. Windows 10에서는 `ReBarWindow32`의 `MSTaskSwWClass`를 좁혀 모니터 자리를 만들고, Explorer가 다시 배치하면 다음 확인에서 다시 좁히며, 끌 때 원래 너비로 되돌립니다. 클릭, 오른쪽 클릭과 포인터 도착은 주 창으로 전달됩니다. 클릭은 알림 영역 아이콘과 같은 경로로 창을 표시하거나 숨기고, 포인터가 도착하면 팝업 창을 미리 만들며, 오른쪽 클릭은 모니터의 사각형을 기준점으로 모니터 패널을 열거나 닫습니다(`frontend/tray/monitor.rs`). 패널은 빠른 패널처럼 전면을 얻고 활성화를 잃으면 닫힙니다. 패널의 옵션은 인터페이스가 구성 요소 페이지의 값 옵션으로 생성하고, 체크와 스타일 전환은 설정만 갱신하며 패널은 열린 채 설정에 따라 새로 고칩니다. 스타일 카드의 미리보기는 호스트가 작업 표시줄 모니터와 같은 조판과 그리기(`shell::taskbar_preview`)로 불투명 이미지로 그려 작업 표시줄 배경색 위에 깔고, 처음 두 값, 작업 표시줄 밝기나 배율이 바뀔 때만 다시 그리며 샘플링마다 갱신하지 않습니다. 테스트 인스턴스(`--test`)는 Explorer를 건드리지 않고, 스스로 만들어 Z 순서 맨 아래에 활성화 없이 놓은 대체 작업 표시줄(`GoodGoodTestTaskbar`, 안에 같은 이름의 `TrayNotifyWnd` 포함)에 붙습니다.

데스크톱 모니터나 작업 표시줄 모니터가 표시되는 동안 샘플러의 창 프로브는 "표시"로 간격을 계산합니다.

알림 영역 GUID는 애플리케이션 식별자와 정규화한 프로그램 경로에서 안정적으로 파생하며, 생성, 수정, Explorer 재생성과 삭제가 모두 같은 `guidItem`과 `NIF_GUID`를 사용합니다. 버전, 도움말 텍스트, 언어와 업데이트 배지는 식별자 계산에 참여하지 않습니다. 같은 경로에 덮어 설치하면 기존 식별자를 쓰고, 개발/테스트 식별자와 다른 프로그램 위치는 서로 격리됩니다. Windows는 알림 영역 GUID를 프로그램 경로와 연결하며, 자세한 내용은 [NOTIFYICONDATA의 식별자와 경로 규칙](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw#troubleshooting)을 참조하십시오.

차트는 물리적 사용 가능 메모리, 프로세스가 커밋할 수 있는 메모리와 속한 작업의 커밋 한도로 래스터 예산을 조정합니다. 여유가 32 MiB 아래로 떨어지면 기존 텍스처를 해제하고 래스터 정밀도를 낮추며 동시 작업 버퍼를 4 MiB로 제한해 샘플링과 작업용 할당 공간을 남깁니다. 큰 차트는 픽셀 예산에 따라 계속 줄어듭니다. 실시간 값, 곡선 데이터, 평활화와 채우기는 유지하고 여유가 64 MiB로 돌아오면 원래 정밀도를 복원합니다.

`disk_details`는 물리 디스크 번호로 신원, PCIe 링크와 사용 가능한 상태 필드를 읽습니다. NVMe와 일반 저장소 속성은 로컬에서 읽고 ATA/SAT/SCSI의 확장 신원과 상태 조회는 이미 실행 중인 권한 있는 서비스가 보충합니다. 요청마다 한 번 읽고 주기 샘플링은 일반 디스크 지표만 갱신합니다. 반환 구조와 단위는 [디스크 세부 정보 인터페이스](core.md#디스크-세부-정보-인터페이스)를 참조하십시오.

구성 디렉터리에는 settings.json과 preferences.json을, 로컬 데이터 디렉터리에는 기록, 업데이트 파일과 진단 로그를 저장합니다. 릴리스 빌드의 식별자는 resources/app.json에서 오고, 개발 빌드는 .devbuild와 안정적인 작업 공간 지문을 덧붙여 작업 공간마다 설정과 단일 인스턴스 잠금을 따로 저장합니다. 테스트에서도 별도 식별자를 명시할 수 있습니다.

같은 오류가 계속 나타나면 진단 로그는 1, 2, 4, 8, 15분으로 반복 보고 간격을 늘리고 이후에는 최대 15분에 한 번 보고합니다. `suppressed_repeats`는 그동안 합친 반복 횟수입니다. 오류마다 빈도를 따로 제한하며, 새로운 오류는 즉시 보고하고 같은 오류가 1분 조용하면 간격을 초기화합니다. 서비스가 실행 중이 아닐 때의 조회와 센서 상태는 합쳐서 보고하고, 새로 등록된 서비스의 1077(아직 시작하지 않음)은 정상 정지 상태로 처리합니다.

0.1.0–0.3.4는 WebView2로 인터페이스를 표시했고 로컬 데이터 디렉터리에 브라우저 데이터 `EBWebView`를 남겼습니다. 0.3.x에서 다른 관리자 계정으로 실행하면 데스크톱 계정의 로컬 데이터 디렉터리 아래 `WebView2\elevated-*`에 기록했습니다. `leftovers.rs`는 시작할 때마다 현재 식별자의 이 두 디렉터리를 확인하고, 있으면 백그라운드 스레드가 삭제하며 창 표시를 미루지 않습니다. 링크를 만나면 링크 자체만 제거하고 대상을 삭제하지 않습니다. 아직 종료 중인 WebView2 프로세스가 파일을 점유하면 나머지는 다음 시작으로 미루고, 실패 단계와 오류 코드를 `goodgood.log`에 기록합니다. 다른 관리자 계정으로 실행할 때는 그 계정의 디렉터리만 확인하며, 데스크톱 계정의 `WebView2`는 그 계정이 직접 GoodGood을 시작할 때 삭제합니다.

`crates/goodgood-app/src/explorer.rs`는 데스크톱 창, 시스템 이미지 경로, 세션, PID와 생성 시간으로 탐색기를 확인합니다. 닫기 전에 먼저 주 스레드가 일시 중단된 새 Explorer를 만들고, 기존 데스크톱 프로세스를 부모로 삼아 원래 계정의 토큰을 상속하며 새 프로세스와 기존 프로세스의 계정, 세션, 권한 상승 상태와 무결성 수준이 같음을 검증합니다. 표준 권한과 높은 권한의 데스크톱 모두 원래 권한으로 다시 만듭니다. 높은 권한 데스크톱은 GoodGood이 관리자 권한으로 실행 중이어야 하며, 분할 토큰이 없는 관리자 계정도 지원합니다. 프로세스와 스레드 객체의 접근 제어와 무결성 수준도 데스크톱 토큰에서 가져와, 관리자가 만든 객체가 표준 계정의 탐색기 관리를 막지 않게 합니다. 준비에 실패하면 원래 데스크톱을 유지하고 시작하지 않은 대체 프로세스를 정리합니다.

대체 프로세스가 준비되면 GoodGood은 작업 표시줄에 종료를 요청하고 최대 5초를 기다립니다. 기존 데스크톱이 아직 실행 중이면 미리 연 핸들로 그 인스턴스를 끝내고 다시 최대 5초 동안 종료를 확인합니다. Windows가 이미 데스크톱을 복구했으면 그 인스턴스를 쓰고, 아니면 준비한 Explorer를 시작합니다. 새 데스크톱과 작업 표시줄이 1초 동안 계속 메시지에 응답하면 완료로 보고합니다. 프로세스 종료 진입점은 현재 데스크톱의 Explorer를 인식하고, 파일 잠금 대화 상자도 이 프로세스에 "다시 시작"을 제공합니다.

`crates/goodgood-app/src/tasks.rs`는 "새 작업 실행"과 설치 후 시작을 처리합니다. 관리자 권한 프로세스가 표준 권한으로 프로그램을 시작할 때 보조 프로세스 `goodgood.exe --goodgood-run-task`를 데스크톱 셸 프로세스의 자식으로 만들고 셸의 토큰을 상속합니다. 계정 원래의 표준 토큰이고 대화형 로그온 세션에 속하며 드라이브 매핑과 장치 네임스페이스가 데스크톱과 같습니다. 부모 프로세스로 만든 자식 프로세스는 생성자의 환경 변수를 물려받으므로, 보조 프로세스는 대상을 시작하기 전에 자기 계정으로 환경을 다시 만듭니다. 사용할 수 있는 셸 프로세스가 없거나 보조 프로세스를 만들 수 없으면 현재 토큰에서 걸러 낸 표준 토큰을 대신 사용합니다. 이 토큰은 여전히 권한 상승된 로그온 세션에 속하고 해당 DOS 장치 디렉터리를 읽을 수 없으며 매핑된 네트워크 드라이브도 다릅니다. "새 작업 실행"의 보조 프로세스가 이미 만들어졌으면, 그것이 스스로 대상 시작 실패(셸이 이미 권한 상승되었거나 환경을 다시 만들 수 없음)를 보고한 뒤에만 다른 방식을 씁니다. 그 밖의 종료 코드는 충돌을 포함해 모두 시작 결과로 보고하며 대상이 두 번 시작되지 않습니다. 설치 후 시작은 보조 프로세스가 실패하거나 충돌해도 걸러 낸 토큰으로 넘어갑니다. 중복 시작된 GoodGood은 이미 실행 중인 인스턴스로 넘길 뿐입니다.

"새 작업 실행"은 GoodGood과 같은 계정이며 권한 상승되지 않은 셸만 사용하고, 그 밖의 경우에는 걸러 낸 토큰을 사용하며 작업은 GoodGood이 있는 계정에 남습니다. 설치 프로그램 완료 페이지의 "시작"과 애플리케이션 내 업데이트 후 재시작(`goodgood.exe --goodgood-launch-installed`)은 데스크톱 계정의 셸에 맡깁니다. UAC가 다른 관리자의 자격 증명을 받아도 GoodGood은 데스크톱 계정으로 실행되며 토큰과 로그온 세션이 이후 바로 가기로 시작할 때와 같습니다. 셸 자체가 이미 권한 상승된 상태(UAC 끔 또는 기본 제공 Administrator 계정)면 직접 시작하며 결과는 그 환경의 다른 시작 방식과 같습니다.

업데이터는 다운로드, 취소와 설치 전 재검증을 담당합니다. 클라이언트는 `resources/app.json`의 공개 키로 설치 파일과 업데이트 설명의 서명을 검증하고 서명에 묶인 버전을 확인합니다. 설치 프로그램은 실행 중인 인터페이스 사본을 끝내고 기존 관리자 권한 시작 기록을 갱신하며 권한 있는 서비스를 새로 고칩니다. 관리자 권한 시작이나 작업 관리자 대체로 실행 중인 설치 버전도 애플리케이션 내 업데이트를 적용할 수 있고, 포터블 버전은 다운로드 진입점을 제공합니다. `--goodgood-updater-check`는 인터페이스를 표시하기 전에 설치 종류를 반환해 패키징 절차가 확인할 수 있게 합니다.

플랫폼 책임과 macOS 경계는 [GPUI 개발](../development/gpui.md)을 참조하십시오.

인터페이스의 시스템 프로세스 숨기기는 [System Informer의 필터 구현](https://github.com/winsiderss/systeminformer/blob/32ef60573927b26a153df29c258e63db15ab4f7c/SystemInformer/mwpgproc.c#L399)을 참고했습니다. 프로세스 메타데이터로 표시 결과를 걸러 내고 필터 상태를 저장합니다. System Informer는 Windows 서명을 사용하고 서명 조회를 켜지 않으면 Microsoft 회사 이름으로 필터링합니다. GoodGood은 추가 수집이나 서명 검증 없이 기존 `windowsProcess`(시스템 디렉터리, Windows 제품과 회사 정보 또는 커널 의사 프로세스 신원)를 재사용합니다. `frontend/visibility.rs`는 편집 가능한 예외와 추가 숨김 명단을 처리하고, 필터는 앱 그룹과 프로세스 트리를 만들기 전에 실행됩니다. 연결 목록의 캐시 입력에는 필터 규칙과 소유 프로세스의 Windows 식별자가 들어가며, 규칙이나 신원이 바뀌면 다시 만듭니다.
