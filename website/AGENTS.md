# 웹사이트 개발

페이지, 구성 요소와 릴리스 입구는 [README](README.md)를 참고합니다.

- 시각적 방향은 사용자가 확인한 안과 애플리케이션 자체의 시각 체계(`resources/theme.json`: 글꼴, 강조색, 재질, 윤곽선, 데이터 곡선 색)를 기준으로 합니다. 외부 디자인 규칙 라이브러리나 디자인 관련 스킬은 도입하지 않으며, 사용자가 지정한 참고 사이트와 시각적 취사선택은 해당 검토에서 기록합니다.
- 위쪽 막대에는 GitHub 아이콘, 별과 개수, 검색, 테마, 언어와 다운로드 입구를 유지합니다. 여러 언어의 문구가 길어지면 위쪽 막대 너비를 넓히거나 줄을 바꾸며, 이미 있는 정보를 숨겨 넘침을 처리하지 않습니다.
- 국소적인 시각·상호 작용 변경은 영향받는 페이지, 조작과 관련 뷰포트만 미리 봅니다. 텍스트, 링크나 문서만 고치는 변경은 루트의 검증 범위에 따릅니다. 공용 배치, 탐색, 테마나 반응형 규칙처럼 넓은 영향을 주는 동작을 고칠 때는 빌드해 미리 본 뒤 `bun run --cwd website check:browser <미리 보기 주소>`를 실행합니다. 이 검사는 1440, 768, 390 px에서 테마, 언어 기억, 홈 화면 시연, 문서 탐색과 검색을 확인하고 스크린숏을 `target/official-web/review/`에 남기므로 이번 회차의 스크린숏을 확인한 뒤 보고합니다.
- 홈 화면 시연(`src/components/replica/`)은 애플리케이션의 문구, 열, 상호 작용과 테마 토큰을 그대로 따릅니다. 애플리케이션의 인터페이스나 문구가 크게 바뀌면 시연도 함께 고칩니다. 시연 데이터는 가상 값과 문서용 주소 대역(RFC 5737/3849)을 씁니다.
- 시연은 구성 요소 안에 한국어로 쓰고 `replica/i18n/`의 JSX 런타임이 텍스트와 속성을 번역합니다. `en.ts`에는 영어 원문 사전을 두고 `catalog-map.json`이 해당 문구를 애플리케이션 `locales/`의 키로 대응시키며, 빌드할 때 `scripts/locales.mjs`가 언어별 사전을 만듭니다. 시연 전용 문구와 웹사이트 문구는 `src/locales/`에서 영어, 스페인어, 독일어, 일본어, 프랑스어와 러시아어를 채웁니다. 같은 말이 위치에 따라 다르게 읽히면 `data-i18n`으로 구분하고 수량은 자리 표시자와 복수형을 유지합니다. 문구를 고친 뒤에는 해당 언어의 `globalThis.__goodgoodMissing`을 확인하고, 공유 메커니즘을 고칠 때는 전체 둘러보기를 확인합니다. 언어 등록은 `src/lib/languages.ts`를 기준으로 하며 위쪽 단추와 메뉴는 항상 전체 원어 이름을 표시합니다.
- 홈 화면의 시연 데스크톱은 1920×1080으로 배치하고 페이지 너비에 맞춰 비례해 축소하며, 작업 표시줄은 Windows 11의 48 px 스타일로 그립니다. 창은 기본 1600×900이고 작업 표시줄 위의 1920×1032 안에서 가운데에 놓이며, 변과 모서리를 끌어 크기를 바꾸고(애플리케이션의 최소 창 `resources/app.json`의 `window.minWidth`, `window.minHeight`보다 작지 않게 하며 현재 값은 640×480) 최대화할 수도 있습니다(`src/components/home/DeskWindow.tsx`). 데스크톱 아래의 "전체 화면 미리 보기"는 브라우저를 전체 화면으로 바꿔 데스크톱 전체를 표시합니다. 애플리케이션의 최소 창을 바꾸면 `DeskWindow.tsx`의 `MIN`도 함께 고칩니다. 시연은 관리자 권한으로 실행되고 권한 있는 서비스와 커널 센서가 모두 켜진 상태로 가정해 애플리케이션이 표시할 수 있는 모든 데이터를 보여 줍니다. 시연에서 위치와 크기를 읽는 코드는 `widgets.tsx`의 `localRect`, `scaleOf`로 창 자체의 픽셀로 환산합니다. 데스크톱 아래의 둘러보기(`src/components/home/HeroTour.tsx`)는 절마다 메뉴, 대화 상자와 알림 영역을 차례로 시연하고 방문자가 절을 고를 수 있습니다. 단계는 `data-tour`, 단추 제목이나 문구로 요소를 찾고 찾지 못한 단계는 오류 없이 건너뛰므로, 시연 창의 구조나 문구를 고친 뒤에는 헤드리스 브라우저에서 영향받는 절의 대상을 확인합니다. 공유 선택자나 둘러보기 메커니즘을 고칠 때는 전체 절을 확인합니다.
- 사용자의 `start-website.bat`이 보통 이미 실행 중입니다. 에이전트 자체 점검에는 `start-website.bat build`와 `preview --port <포트>`를 우선 사용합니다. 빌드가 쓰는 `website/content/`는 개발 서버와 같으므로 사용자의 인스턴스에 영향을 주지 않습니다. 두 번째 개발 서버가 필요하면 `GOODGOOD_NEXT_DIR=.next-<이름>`을 설정하고 포트를 바꾸며, 시험이 끝나면 그 디렉터리를 지우고 Next.js가 `tsconfig.json`에 쓴 해당 `include` 항목도 되돌립니다.
- 문서의 모양과 상호 작용은 fumadocs.dev를 기준으로 합니다. 그 Spacious 배치와 Fumadocs 구성 요소를 그대로 쓰고 배치를 따로 설계하지 않으며, `src/styles/docs.css`는 강조색, 글꼴과 한국어 조판 세부만 바꿉니다. 사이드바 아이콘은 `scripts/content.mjs`의 `pageIcons`에서 파일별로 지정하고 `src/lib/source.ts`에서 하나씩 가져옵니다(lucide를 통째로 가져오면 개발 서버의 첫 컴파일이 느려집니다). 홈 화면 스타일은 `site` 계층에 있고 클래스 이름을 Tailwind 유틸리티 클래스와 같게 짓지 않습니다(예: `grid`, `table`). 그럴 경우 Fumadocs의 요소에도 적용됩니다.
- 동작: 페이지 전환은 `SiteFrame`과 문서 배치 바깥의 React `<ViewTransition>`이 맡고(스타일은 `global.css`), 문서 안에서의 쪽 넘김은 fumadocs.dev 방식을 유지하며 전환을 넣지 않습니다. 펼칠 수 있는 `<details>`에는 `data-disclose`를 붙이고 `Disclosure.tsx`가 높이 동작을 통일해 처리하며 Chromium만 지원하는 `interpolate-size`에 의존하지 않습니다. 시연 곡선은 `curve.worker.ts`가 OffscreenCanvas에 그리며 방식은 애플리케이션과 같습니다. 샘플링마다 곡선 전체를 그림 한 장으로 그리고 같은 시각의 표본이 항상 같은 서브픽셀 위상에 놓이게 한 뒤, 프레임마다 그 그림을 샘플링 시계가 주는 위치로 서브픽셀 단위로 평행 이동하고 양 끝은 장치 픽셀에 맞춰 자릅니다. 서버가 렌더링한 SVG는 첫 프레임과 Worker가 없을 때의 대체 수단으로만 씁니다. 합성기로 SVG를 평행 이동하는 방식으로 되돌리지 않고(샘플링마다 애니메이션을 다시 만들면 시작 지연 때문에 뒤로 튑니다) 프레임마다 곡선을 다시 그리지도 않습니다(계단이 프레임마다 달라집니다). 위치는 `Curve.tsx`의 샘플링 시계(`advanceClock`)가 정합니다. 새 샘플링은 이전 샘플링의 시작점에서 간격만큼 이어지고 데이터와 시계가 같은 메시지로 Worker에 전달되며, 이전 시계와 새 시계의 차이는 Worker가 속도에 나누어 반영하므로 곡선이 거꾸로 가지 않습니다. 시연 창에서 페이지, 장치 보기와 세부 정보의 밀어 넣기는 `widgets.tsx`의 `slideIn`을 쓰고 화면 픽셀에 맞춰 멈추며, 그렇지 않으면 이동 중에 글자가 흐려지고 끝날 때 튑니다. 이 컨테이너들은 계속 독립 레이어를 유지하며(`will-change`), 그렇지 않으면 동작이 끝나 레이어를 걷을 때 안의 스크롤 목록 글자가 픽셀에 다시 정렬되며 한 번 더 움직입니다. 스크롤 영역 안에서 움직이는 내용에는 `overflow: clip`을 한 겹 더 두어야 변위가 스크롤 범위에 들어가지 않습니다. 페이지 전환 시 같은 위치에 있는 컨트롤(예: 도구 모음의 분할 선택기)에는 페이지별 `key`를 주어야 선택 블록이 이전 페이지의 항목에서 미끄러져 오지 않습니다.
- 성능: 반복 재생되는 장식 동작은 transform과 opacity만 바꿔 합성 스레드에 맡깁니다. 해당 구획에 `data-motion`을 붙이고 선택자를 `global.css`의 `[data-still]` 일시 정지 목록에 넣어, 구획이 뷰포트를 벗어나면 `MotionGate`가 멈춥니다. 계속되는 전환이나 동작이 있는 레이어를 둥근 모서리의 `overflow: hidden` 잘라 내기 안에 넣지 않습니다. 브라우저가 프레임마다 레이어 트리를 다시 만듭니다. 첫 화면 아래의 홈 화면 구획은 `content-visibility: auto`로 배치와 그리기를 미룹니다. 홈 화면이나 내부 페이지에만 있는 스타일은 `home.css`, `replica.css`나 `pages.css`에 쓰고(경로별 스타일로 불러옵니다) 여러 페이지가 공유하는 것만 `global.css`에 둡니다. 시연 창에서 첫 화면에 쓰지 않는 페이지는 필요할 때 불러옵니다. 유려함이나 로딩에 영향을 줄 수 있는 변경은 헤드리스 브라우저에서 변경 전 빌드와 번갈아 메인 스레드의 초당 소요 시간, 가장 긴 프레임과 CPU 스로틀 4배에서의 총 차단 시간을 측정합니다.
