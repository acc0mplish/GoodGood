# GoodGood 웹사이트

웹사이트는 pnpm 작업 공간의 `@goodgood/website` 패키지이고 Next.js로 정적 내보내기하며, 문서 부분은 [Fumadocs](https://fumadocs.dev)(`create-fumadocs-app`의 정적 내보내기 템플릿을 기반으로 함)를 쓰며 배치는 fumadocs.dev와 같습니다(Spacious). 첫 페이지의 애플리케이션 창 시연과 실측 소요 시간 재생은 React 구성 요소입니다. 창은 애플리케이션 `resources/theme.json`의 색과 크기를 따르고, 프로세스와 시스템 판독값은 모두 가상 값이며, 시스템 판독값은 표본 번호에 따라 결정적 잡음으로 생성하고 되풀이되지 않습니다. 일곱 언어의 첫 페이지는 같은 시연을 실행하고 페이지 언어에 따라 소프트웨어 문구를 재사용하며, 시연 전용 문구는 웹사이트 사전에서 관리합니다. 문서는 저장소 `docs/` 아래의 Markdown을 렌더링하며 안정판(`/docs/`, 최신 릴리스 태그에서 가져옴)과 개발판(`/docs/dev/`, main에서 가져옴)으로 나뉩니다. 두 판은 서로 다른 루트 디렉터리이고, 사이드바 위쪽의 판 선택기는 다른 판의 같은 글을 엽니다. 검색 색인은 빌드할 때 내보내고 브라우저에서 낱말 단위로 나눈 뒤 판으로 거릅니다. 페이지 사이는 Next.js 라우팅으로 바뀌며(본문 내용은 뷰 전환으로 흐려지며 위로 사라지고 아래에서 흐려지며 나타나며 머리글은 움직이지 않음), 포인터를 올리거나 초점을 얻거나 링크를 만질 때 대상 페이지를 미리 가져오고, 누른 뒤에는 달라진 부분만 바꾸므로 브라우저가 페이지를 다시 읽지 않습니다. 언어별 페이지는 각자의 루트 레이아웃을 씁니다. 위쪽 언어 메뉴는 전체 원어 이름을 표시하고 방향키, Home, End, Enter, Space와 Escape를 지원하며 펼침, 접힘과 페이지 전환 동작을 갖춥니다. 동작 줄이기 설정은 동작을 끕니다. 언어를 바꿀 때 페이지, 쿼리 매개 변수, 앵커와 읽던 위치를 유지하고 언어 항목에 포인터를 올리면 대상 페이지를 미리 가져옵니다. 주소마다 한 언어만 표시하며 브라우저 언어로 자동 이동하지 않습니다. 방문자가 위쪽 메뉴, 언어 안내나 시연 설정에서 고른 언어는 `goodgood-language`에 저장되고, 이후 사이트 밖에서 루트 주소를 열면 그 언어의 첫 페이지로 이동합니다. 사이트 안의 링크, 새로 고침과 뒤로 가기는 이동하지 않으며, 언어를 고른 적이 없는 방문자(검색 엔진 포함)는 항상 한국어 첫 페이지를 봅니다. 다른 언어 판이 있는 페이지에서 페이지 언어가 방문자가 고른 언어와 다르거나, 고른 적이 없을 때 브라우저가 선호하는 언어(`navigator.languages`에서 처음으로 지원하는 언어)와 다르면 머리글 아래 가운데에서 안내 띠가 밀려 나오고, 그 언어로 해당 판을 알리며 언어 단추를 강조색으로 표시합니다. 안내는 사이트를 읽을 때마다 한 번만 하고, 닫으면 띠가 머리글로 들어가며 언어 단추가 잠깐 밝아져 언어를 바꾸는 자리를 알리고, `goodgood-language-dismissed`에 기록해 같은 언어를 다시 알리지 않습니다. 언어별 안내 문구는 `src/lib/languages.ts`에 있습니다. 웹사이트와 문서는 테마 기본 설정(시스템 따름, 밝게 또는 어둡게)을 함께 쓰며 `goodgood-theme`에 저장합니다.

| 디렉터리 | 역할 |
| --- | --- |
| `src/app/` | 공개 주소: `(ko)/`는 한국어 페이지와 문서(`docs/`), `en/`, `es/`, `de/`, `ja/`, `fr/`, `ru/`는 해당 언어 페이지이며, 그 밖에 검색 색인, Markdown 보기, 사이트맵과 언어 모델이 읽는 `llms.txt`, `llms-full.txt`가 있습니다 |
| `src/views/` | 첫 페이지, 내려받기, 변경 기록과 정책 페이지의 내용과 조합 |
| `src/components/` | 머리글, 바닥글, 테마와 검색. `replica/`는 애플리케이션 창 시연이고 `home/`은 첫 페이지의 다른 상호 작용 부분입니다 |
| `src/lib/`, `src/styles/` | 사이트와 첫 페이지 데이터, 문서 원본과 링크 해석, 디자인 변수와 스타일. `app.css`는 사이트 전체가 함께 쓰고, 첫 페이지와 내려받기, 변경 기록 페이지의 스타일은 `home-route.css`, `pages-route.css`로 해당 페이지에서만 불러오며, `docs.css`는 Fumadocs의 강조색과 글꼴을 애플리케이션의 것으로 바꿉니다 |
| `src/locales/` | 웹사이트와 시연 전용 번역. 소프트웨어에 이미 있는 번역은 대응 키로 재사용합니다 |
| `content/`, `public/assets/` | 스크립트가 만들며 버전 관리에 넣지 않습니다: 두 판의 문서, 사이트 데이터 `site.json`과 미리 보기 그림 |
| `src/data/` | 실측 조작 소요 시간과 측정 조건. [샘플링 설명](src/data/README.md)을 참고합니다 |
| `scripts/` | 릴리스 파일 검증, 문서 준비, 미러 생성, 빌드와 콘텐츠 보안 정책, 페이지별 Markdown 사본, 미리 보기, 브라우저 검사와 공개 검사 |
| `public/` | 웹사이트와 함께 배포하는 정적 설정: 캐시와 보안 응답 헤더, 이전 주소 리디렉션 |
| `cloudflare/` | 웹사이트, 내려받기 미러, 업데이트 목록과 www 이동의 정적 자산 설정 |

## 로컬 개발

Windows에서는 저장소 루트의 [start-website.bat](../start-website.bat)을 두 번 눌러 실행하거나 터미널에서 `.\start-website.bat`을 실행합니다. 스크립트는 잠금 파일이 지정하는 의존성을 설치하고 문서와 사이트 데이터를 준비한 뒤 Next.js를 시작하고 로컬 주소(기본값 `http://localhost:4321`)를 출력합니다. 페이지, React 구성 요소나 스타일을 저장하면 브라우저가 자동으로 갱신됩니다. 개발 출처는 본체 네트워크 어댑터 주소를 허용하며 근거리 통신망과 가상 어댑터를 포함하므로, 그 주소로 접속해도 개발 연결과 단추 상호 작용이 정상입니다. 저장소 [docs/](../docs/README.md) 아래의 Markdown을 고치면 커밋하지 않은 내용을 `/docs/dev/`에서 볼 수 있고 `/docs/`는 항상 릴리스 태그에 해당합니다. 생성 파일은 내용이 바뀔 때만 기록합니다. `website/scripts/`에서 사이트 데이터를 준비하는 스크립트를 고치면 준비 프로세스가 스스로 다시 시작해 데이터를 다시 만들고 개발 서버는 계속 실행됩니다.

| 명령 | 용도 |
| --- | --- |
| `start-website.bat --open` | 시작한 뒤 브라우저를 엽니다 |
| `start-website.bat --port 4400` | 듣는 포트를 지정합니다 |
| `start-website.bat --host` | 같은 근거리 통신망의 휴대 전화나 다른 장치에서 미리 봅니다 |
| `start-website.bat build` | 정적 웹사이트, 검색 색인과 릴리스 미러를 빌드합니다 |
| `start-website.bat preview` | 최근 정적 빌드를 로컬에서 미리 봅니다(`--port`로 포트 지정) |
| `start-website.bat check` | TypeScript 형식 검사와 정적 산출물 검증을 실행합니다 |

Ctrl+C로 서버를 멈춥니다. 다른 플랫폼에서는 저장소 루트에서 `pnpm install --frozen-lockfile`, `pnpm site:dev`를 실행합니다. 처음 시작할 때는 Git과 pnpm을 설치하고 안정판 태그를 로컬에 두어야 합니다(`git fetch --tags`로 받을 수 있음). 개발 서버는 로컬에서 이미 검증한 릴리스 데이터를 우선 사용하고, 처음 받을 때는 GitHub Releases에 연결해야 합니다. 개발 서버와 빌드는 모두 문서를 `website/content/`에 기록하고, 로컬 빌드의 개발판은 작업 공간을 읽어 개발 서버와 같으므로 둘을 함께 실행할 수 있습니다. 프로덕션 빌드는 `target/official-web/dist/`에 있습니다. 배포할 때는 `GOODGOOD_DOCS_DEV_REF`로 개발판 문서를 그 빌드의 `origin/main` 커밋에 고정합니다.

배포와 업데이트 목록의 게시 순서는 [웹사이트와 릴리스 미러](../docs/development/website.md)를 참고합니다. 빌드하고 미리 본 뒤 `pnpm --dir website check:browser <미리 보기 주소>`는 별도의 헤드리스 Chrome 또는 Edge에서 1440, 768과 390 px로 테마 기억, 언어 기억, 첫 페이지 창 시연, 문서 사이드바 탐색, 판 전환과 검색을 확인하고 스크린숏을 `target/official-web/review/`에 남깁니다. 브라우저를 찾지 못하면 `CHROME_PATH`로 지정합니다.
