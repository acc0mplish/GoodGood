# 다국어

인터페이스, 알림 영역, 네이티브 오류와 설치 관리자는 [`locales`](../../locales)를 함께 사용합니다. `ko-KR`이 원문 문구이며 `en-US`, `es-ES`, `de-DE`, `ja-JP`, `fr-FR`, `ru-RU`가 같은 이름 공간에 번역을 제공합니다. 모두 일곱 가지 언어이며 다른 모든 디렉터리는 `locales/ko-KR/`의 키를 하나씩 그대로 대응해 유지합니다. 인터페이스 키에는 파일 이름 접두사가 붙으며 예를 들어 `settings.update.check`입니다. `native.json`의 키는 `tray.quit`처럼 그대로 씁니다. 언어 선택 항목은 각 언어의 원래 이름을 쓰므로 어떤 인터페이스 언어에서도 알아볼 수 있습니다.

GPUI 호스트가 문구 디렉터리를 등록한 뒤 자리 표시자가 있는 문구는 `goodgood_core::tr!`로 서식을 적용하고 정적 레이블은 `frontend::theme::label`로 읽습니다. 동적 키는 그릴 때 현재 언어로 해석하며 날짜, 바이트 수와 단위는 네이티브 서식 함수가 처리합니다.

구성 요소 라이브러리 `gpui-component`는 자체 문구 디렉터리를 가지며 일부 언어만 담고 있습니다. `catalog::set_locale`은 인터페이스 언어를 설정할 때 같은 언어 태그를 구성 요소 라이브러리에 전달하고 그 라이브러리에 없는 언어는 영어로 대체합니다. 이 디렉터리는 구성 요소 라이브러리가 직접 그리는 문구, 즉 터치로 텍스트 상자를 길게 눌렀을 때의 편집 메뉴와 접근성 레이블에 쓰입니다. 텍스트 상자의 오른쪽 버튼 메뉴는 `widgets::input`이 `common.edit` 문구로 구성하며 모든 언어를 다룹니다. 문구가 내장된 구성 요소를 쓸 때도 `locales`에서 문구를 전달합니다.

언어를 바꾸면 열 머리글, 메뉴와 테마 레이블을 다시 구성합니다. 글꼴 대체 목록은 언어별로 캐시하며 한국어는 Malgun Gothic / 맑은 고딕을, 일본어는 Yu Gothic UI / Meiryo를 우선 사용하고 영어, 스페인어, 독일어, 프랑스어와 러시아어는 시스템 기본 글꼴을 씁니다. 시스템 언어는 Windows 표시 언어로 선택하고 지원하지 않으면 사용자의 기본 언어 목록을 살피며 마지막에는 영어를 씁니다. 같은 언어의 지역 변형은 디렉터리를 공유하며 예를 들어 `es-MX`는 `es-ES`를, `fr-CA`는 `fr-FR`을 씁니다. 한국어는 주 언어가 `ko`이면 모두 `ko-KR`로 모이므로 `ko`, `ko-KR`, `ko-KP`가 같은 디렉터리를 사용하고 Windows LANGID는 `0x0412`입니다. 보조 프로세스는 `GOODGOOD_LOCALE`로 언어를 물려받고 서비스는 자신이 실행되는 시스템 계정의 표시 언어를 사용합니다.

복수형은 원래 숫자 인수 `count`와 CLDR 기수 규칙으로 선택합니다. 한국어와 일본어는 `other` 하나만 쓰고 영어와 독일어는 `one/other`, 스페인어와 프랑스어는 `one/many/other`, 러시아어는 `one/few/many/other`를 씁니다. 한국어 문구 디렉터리에는 `one` 형식이 없으며 다른 언어는 각자 필요한 형식을 그대로 유지합니다. `many`는 프랑스어와 스페인어에서 백만의 정수 배수를 덮습니다. 러시아어는 1, 2–4, 5–20과 21, 22 같은 끝자리를 구분하고 소수 부분이 있으면 `other`를 씁니다. 정수를 묶음 기호와 함께 표시할 때는 `theme::counted`, 소수 수량은 `theme::quantity`를 씁니다. 원래 숫자를 `i18n::format_count`에 넘겨 복수형을 고르고 지역 서식 결과로 `{count}`를 바꾸어 묶음 기호를 소수점으로 오인하지 않게 합니다. 새로 고침 간격 같은 소수도 지역 서식 함수로 표시합니다. 네이티브 계층과 인터페이스가 선택 로직을 공유하며 문구가 없으면 영어로, 영어에도 없으면 원문 문구로 대체합니다. 테스트는 명시적인 언어 인수를 써서 프로세스 단위 언어를 바꾸거나 특정 번역 문구를 단정하지 않습니다.

숫자와 전체 날짜는 Windows 지역 설정을 따르며 인터페이스 언어와 무관합니다. 소수점, 묶음 기호와 묶음 자릿수는 시작할 때 읽고 날짜는 시스템의 짧은 날짜와 시간 형식을 씁니다. 타임스탬프는 그 시각의 로컬 표준 시간대 오프셋으로 변환합니다. 기록 곡선의 짧은 날짜 레이블은 인터페이스 언어를 쓰고 시간 축은 24시간제를 유지합니다. 숫자 입력은 입력기 조합을 유지하고 확정할 때 지역 소수점, 마침표와 전각 숫자를 인식하며 묶음 기호는 해석하지 않습니다. 버전, PID, 포트, 경로, 설정 파일과 프로토콜 데이터는 원래 형식을 유지합니다.

사용자에게 보이는 문구는 모든 언어 디렉터리에서 관리합니다. 로그, panic과 주석은 영어로 씁니다. `bun run i18n`(`node scripts/i18n.mjs`)은 문구 키, 자리 표시자, 각 언어에 필요한 복수형, 서식 있는 텍스트 중첩, 빈 번역, 숨은 제어 문자, 월 개수와 네이티브 계층·데스크톱·설치 관리자의 언어 등록 일치 여부를 검사합니다. 등록된 언어 태그는 `locales/` 디렉터리, `Locale` 열거형의 serde 이름, `installerLanguages`의 키와 NSIS 템플릿의 `MUI_LANGUAGE`가 모두 같아야 합니다. NSIS 언어는 ENGLISH, KOREAN, SPANISH, GERMAN, JAPANESE, FRENCH, RUSSIAN 일곱 가지입니다. 이 검사는 또 애플리케이션과 웹사이트의 고정 용어와 단위를 확인합니다. 프랑스어와 러시아어의 `one`은 여러 숫자를 덮으므로 번역에서 `{count}`를 반드시 유지합니다. 한국어가 아닌 번역에는 한국어 문구가 없어야 하며 언어 이름만 예외이고 일본어는 한자를 쓸 수 있습니다. 코드에 한국어나 한자로 된 사용자 문구를 직접 쓰는 것도 오류이므로 `locales/`를 거칩니다. 경로, 파일 이름, 명령줄 인수, `Debugger`, `UseFilter`와 JSON의 `null` 같은 기술 식별자는 원문을 유지합니다. 설치 문구는 `installer.json`에 있고 패키징할 때 `scripts/lib/installer-locales.mjs`가 NSIS `LangString`으로 바꾸며 훅은 `GOODGOOD_TEXT`로 키를 참조합니다. 설치 도움말 프로세스는 각 언어의 Windows LANGID를 받아들이고 정적 텍스트는 경로에 있는 `&`를 그대로 표시합니다.

변경 기록은 인터페이스 언어마다 한 부씩(`changelog/<언어 태그>.md`) 있으며 `changelog/ko-KR.md`가 원문이고 나머지는 이 파일을 항목별로 번역한 것입니다. 소절 제목은 `resources/changelog.json`에 있습니다. 정보 페이지는 애플리케이션에 컴파일된 해당 언어 판을 표시합니다. 업데이트 대화 상자는 그 버전에 실린 해당 언어 번역을 먼저 표시하고 없으면 한국어가 아닌 언어에서 영어를, 영어도 없으면 한국어 원문을 표시합니다. 웹사이트와 저장소 설명 파일의 언어는 따로 관리합니다.

언어를 추가할 때는 모든 디렉터리를 채우고 goodgood-core의 Locale과 네이티브 설정 항목에 등록하며 `resources/changelog.json`에 언어 이름과 각 소절 제목을 적고 `changelog/` 아래 번역을 채운 뒤 모의 스냅숏으로 모든 페이지 배치를 확인합니다.

창 확인은 `node scripts/ui-shots.mjs l10n-ko tools/window-probe/steps/localization.json --language ko-KR`로 실행하며 레이블과 언어를 바꾸어 같은 단계를 다시 씁니다. 이 단계는 모든 페이지, 첫 실행 안내, 최소 창과 20 px 글꼴, 150% 인터페이스 배율을 다룹니다. 설치 마법사 문구는 NSIS 컨트롤 높이와 각 언어 글꼴의 실제 줄 높이를 함께 고려합니다.

기록 눈금은 로컬 시간 경계로 계산하며 일광 절약 시간을 넘을 때 존재하지 않는 시각은 건너뛰고 되돌린 뒤의 중복 시각은 유지합니다. 선택한 시각에는 UTC 오프셋을 붙이고 레이블 너비는 실제 글꼴 측정값을 씁니다. 지역 형식 테스트는 Windows 지역 API와 직접 대조하고 표준 시간대 테스트는 Windows 표준 시간대 데이터베이스를 읽으며 둘 다 시스템 설정을 바꾸지 않습니다. 바로 가기 키 녹화는 주 창의 현재 네이티브 메시지에서 가상 키와 보조 키를 얻고 보조 키를 놓거나 글자가 바뀐 뒤에도 같은 가상 키로 녹화를 끝냅니다. 테스트 입력은 문자 매핑 대체를 유지합니다.

## 용어집

### 고정 약어, 식별자와 단위

애플리케이션, 웹사이트와 인터페이스 시연이 다음 규칙을 함께 따르고 README와 변경 기록도 같은 표기를 씁니다. 기계가 읽는 목록은 [`resources/terminology.json`](../../resources/terminology.json)에 있고 [`terminology.mjs`](../../scripts/lib/terminology.mjs)가 검사하며 `bun run i18n`과 웹사이트 문구 테스트에 연결되어 있습니다.

| 분류 | 고정 표기와 적용 범위 |
|---|---|
| 핵심 지표 | 모든 언어의 리소스 레이블, 열 이름, 그룹과 지표에서 `CPU`, `GPU`, `I/O`, `PID`를 함께 씁니다. 주변 문구는 언어에 따라 번역하며 예를 들어 `Чтение (I/O)`, `Lecture I/O`, `I/O lesen`입니다. |
| 프로토콜과 인터페이스 | `SMART`, `NVMe`, `ATA`, `SATA`, `SCSI`, `USB`, `PCIe`, `TCP`, `UDP`, `IPv4`, `IPv6` 같은 식별자와 대소문자를 유지합니다. |
| 하드웨어와 센서 | `CPUID`, `MSR`, `RAPL`, `NVML`, `IGCL`, `VID`, `PPT`, `TDC`, `EDC`, `FCLK`, `MCLK`, `UCLK` 같은 식별자를 유지하고 설명 문구는 각 언어의 역명을 씁니다. |
| 기술 이름과 코드 | `PawnIO`, `DirectX`, `EcoQoS` 같은 이름과 경로, 파일 이름, 명령줄 인수, 레지스트리 키의 정확한 표기를 유지합니다. |
| 용량과 속도 | 서식 함수의 `B`, `KB`, `MB`, `GB`, `TB`와 대응하는 `/s`를 따르고 네트워크 비트 속도는 `b/s`, `Kbps`, `Mbps`, `Gbps`, `Tbps`를 씁니다. 이진 접두사를 분명히 쓰는 문구는 `KiB`, `MiB`, `GiB`, `TiB`를 유지합니다. 환산 기수는 데이터와 서식 함수가 정합니다. |
| 주파수와 하드웨어 판독값 | `Hz`, `kHz`, `MHz`, `GHz`, `W`, `mW`, `V`, `mV`, `A`, `mA`, `°C`, `RPM`, `MT/s`를 유지합니다. 예를 들어 러시아어 전압 레이블은 `+3,3 V`로 쓰고 메모리 판독값은 `GB`를 씁니다. |

숫자 형식, 값과 단위 사이의 공백, 퍼센트 기호 간격은 기존 지역 및 언어 규칙을 따릅니다. "초", "픽셀", "프레임/초" 같은 자연어 표현은 계속 번역합니다. 단위 기호의 대소문자와 접두사는 원래 뜻을 유지하며 예를 들어 `MB/s`, `Mbps`, `MiB`는 서로 다른 단위입니다.

고정 약어 검사는 원문 문구의 해당 용어를 덮습니다. `exactLabels`는 리소스 이름 같은 독립 레이블을 따로 고정합니다. 완전히 자연스러운 번역을 쓰는 예외는 `localizedPhrases`에 문구 키로 기록하며 예를 들어 CPU 시간은 프랑스어 `Temps processeur`, 러시아어 `Время процессора`로 쓸 수 있고 I/O 설명 문장은 전체 입출력 역명을 쓸 수 있습니다. 예외도 통일 약어 규칙을 따르며 약어를 쓸 때는 `CPU`, `GPU`, `I/O`로 씁니다. 키 이름을 조정할 때 목록도 함께 고치고 검사는 더 이상 유효하지 않은 키를 보고합니다. 새 예외는 구체적인 맥락을 적고 회귀 사례를 보충합니다.
